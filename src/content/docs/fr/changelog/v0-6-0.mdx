[Modifications sur GitHub](https://github.com/darkone-linux/darkone-nixos-framework/compare/v0.5.0...v0.6.0) · [Toutes les versions](/fr/changelog/)

:::caution[Ruptures de compatibilité]
- **secrets** : abandon de default-password-hash et de just passwd-default
- **space** : space-bot fusionné dans space-init, le bot exige un réseau Matrix
- **openclaw** : secret du mot de passe de la passerelle pour le CLI de l'hôte, exécution selon le fournisseur
- **openclaw** : clonage des projets dans le projectsDir partagé, agents de code
:::

## Corrigé

- **iso** : tty1 attend le réseau, Entrée ouvre nmtui pour le Wi-Fi
- **init** : le lien Dnf/ est une racine GC, conservé par le GC hebdomadaire
- **iso** : NetworkManager seul sur les cartes réseau, pas de dhcpcd à côté
- **oauth2-proxy** : ne tourne que là où Caddy l'appelle, pas sur chaque hôte de zone
- **hardware** : Zed démarre sans l'avertissement de GPU émulé sur une VM
- **space** : space-init vérifie les destinataires du fichier, pas le déchiffrement de la clé d'infra
- **microvm** : pas de wait-online networkd sur un hyperviseur dhcpcd
- **microvm** : conserve le DNS de dhcpcd sur l'hyperviseur, pas de resolved tiré par networkd
- **microvm** : couche de store inscriptible dans les invités, Home Manager s'active
- **space** : space-bot analyse la ligne de journal du jeton MAS, permissions restaurées en cas d'échec
- **space** : space-bot écrit son marqueur avec sudo, var/generated n'appartient pas à nix
- **space** : space-init écrit le marqueur du bot au format nixfmt
- **sso** : oauth2-proxy rafraîchit les claims toutes les 15 min, les changements de groupe s'appliquent
- **microvm** : l'hyperviseur vérifie que ses invités conservent son stateDir
- **openclaw** : une session de MP par membre quand un espace en compte plusieurs
- **openclaw** : les clones de projets acceptent une nouvelle clé de serveur SSH
- **home** : visionneuse d'images pour chaque profil graphique, Geeqie dans les essentiels
- **home** : le dossier du réseau local attend les dossiers du shell, réessayé en cas d'erreur
- **gnome** : une seule liste d'applications masquées avec UMI, les applications absentes ne sont plus occultées
- **microvm** : hyperviseur entièrement sous networkd, résolveur de zone statique
- **microvm** : l'invité résout uniquement via la zone, sans repli ni LLMNR
- **microvm** : pas d'optimisation du store sur un hyperviseur, les overlays des invités passent en ESTALE
- **nix-cache** : les NAR repris contournent le cache, épingles stables pour les applications cassées
- **tests** : fixture sops pour l'hôte isolé space1 d'eval-all
- **virtualbox** : signature des modules noyau avec kmodigest, l'agrégateur exige .ko.cer
- **nextcloud** : création de l'admin via occ, option adminuser retirée en amont
- **openclaw** : amorçage de la configuration modifiable clé par clé, les structures définies dans l'interface sont conservées
- **openclaw** : icône et description
- **openclaw** : correctif du runtime Node avec patchelf --no-sort, segfault de ld.so
- **headscale** : attend un vrai 200 de l'émetteur OIDC avant de démarrer
- **headscale** : joint le Kanidm local via loopback, pas de repli OIDC au démarrage

## Sécurité

- **microvm** : répertoires d'état des invités fermés aux utilisateurs de l'hyperviseur (0770)
- **openclaw** : unité de passerelle durcie, l'agent écrit uniquement dans son état
- **microvm** : état des invités monté nosuid,nodev sur l'hyperviseur
- **adguardhome** : DNS amont et de repli uniquement via TLS/HTTPS
- **c8** : les résolveurs de zone chiffrent l'amont, les clients ne suppriment que le repli
