### &#x1F4E6; darkone.host.gateway

Passerelle / routeur principal d'une zone de réseau local.

:::tip[Une passerelle prête à l'emploi&nbsp;!]
La passerelle est configurée dans le fichier `usr/config.yaml`.
Les services supplémentaires activés (homepage, adguardhome, forgejo, nix-cache...)
sont automatiquement configurés avec une connectivité réseau cohérente sur
la passerelle et toutes les machines du réseau local.
:::

:::caution[Le trafic routé est filtré]
`filterForward = true`&nbsp;: seuls les échanges LAN &lt;-&gt; WAN et LAN &lt;-&gt; tailnet sont autorisés.
Tout le reste est abandonné — à ajouter dans `networking.firewall.extraForwardRules`.
:::

* **enable** `bool` Activer les fonctionnalités de passerelle pour l'hôte courant (dhcp, dns, proxy, etc.)

```nix
darkone.host.gateway.enable = false;
```

### &#x1F4E6; darkone.host.hcs

Serveur de coordination headscale principal.

:::tip[Un serveur headscale prêt à l'emploi&nbsp;!]
Le réseau est configuré dans le fichier `usr/config.yaml`.
Les services supplémentaires activés (authentification, etc.)
sont automatiquement configurés avec une connectivité réseau cohérente sur
votre réseau global.

Alias Zsh «&nbsp;h&nbsp;» pour «&nbsp;headscale&nbsp;».
:::

:::caution[SSH public]
Le port 22 est ouvert sur toutes les interfaces, Internet compris — unique
hôte de la flotte dans ce cas&nbsp;: il héberge le plan de contrôle du tailnet,
l'y accéder ne doit donc pas nécessiter le tailnet.
:::

* **enable** `bool` Activer le serveur de coordination headscale
* **enableClient** `bool` Activer le client tailscale sur le nœud HCS (recommandé pour héberger des services)

```nix
darkone.host.hcs = {
  enable = false;
  enableClient = true;
};
```

### &#x1F4E6; darkone.host.minimal

Chaque configuration d'hôte est basée sur cette configuration minimale.

:::caution[Déclaration de services]
Un certain nombre de services (immich, nextcloud, forgejo, etc.) peuvent être déclarés dans
`usr/config.yaml` de chaque hôte, quel que soit son type (serveur, ordinateur portable,
bureau, etc.). **Il est conseillé de les déclarer dans le fichier yaml pour que
le service soit visible sur l'ensemble du réseau!**
:::

* **enable** `bool` Configuration minimale de l'hôte
* **secure** `bool` Préférer des options plus sécurisées (désactiver les utilisateurs mutables...)

```nix
darkone.host.minimal = {
  enable = false;
  secure = false;
};
```

### &#x1F4E6; darkone.host.umi

Profil hôte&nbsp;: poste de travail piloté au regard (Tobii Eye Tracker 5 + Talon), utilisable sans clavier ni souris.

:::note[Étend le poste de bureau]
Hérite du profil poste de bureau complet (GNOME, multimédia, bureautique) et ajoute les
prérequis du contrôle au regard&nbsp;: une session Cinnamon X11 pour les utilisateurs concernés, la
connexion automatique, l'injection d'événements uinput et les règles udev Tobii.
:::

:::tip[Coexistence X11 / Wayland]
Talon exige X11 (Wayland non pris en charge en amont, pas prévu) et
GNOME 50 a abandonné sa session Xorg, donc les sessions de contrôle au regard tournent sous Cinnamon (X11,
UX proche de GNOME, tray natif) tandis que les autres utilisateurs gardent GNOME Wayland. Les
utilisateurs listés dans `gazeUsers` (plus `autoLoginUser`) voient leur session GDM enregistrée
initialisée à «&nbsp;cinnamon&nbsp;» via AccountsService&nbsp;; GDM continue de gérer
le fichier ensuite.
:::

:::caution[Paquet Talon]
`pkgs.talon` provient de l'input `talon-nix` câblé dans le flake DNF
(x86_64-linux uniquement, tarball amont non libre). Avec `package = null`,
udev/uinput/a11y restent configurés et Talon peut être lancé manuellement
(steam-run sur le tarball amont, ce qui conserve la mise à jour automatique).
:::

:::tip[Premier lancement]
Le firmware du Tobii 5 doit être initialisé une fois sur une machine Windows
(Tobii Experience). Au premier lancement de Talon, rebranchez le tracker puis
redémarrez Talon (udev), et lancez la calibration depuis le menu Talon.
:::

:::note[Bruit noyau attendu]
Le tracker déclare deux interfaces de classe vidéo (caméras oculaires IR brutes) que
uvcvideo ne peut pas gérer&nbsp;: `Unknown video format`, `No supported video formats
found`, `probe with driver uvcvideo failed with error -22`. Sans danger et
souhaité&nbsp;: aucun pilote noyau ne réclame les interfaces, donc libusb les obtient librement.
Le tracker est atteint via l'interface 0 (spécifique au fournisseur, endpoints
bulk), jamais via /dev/video*.
:::

* **enable** `bool` Configuration hôte optimisée pour le contrôle au regard (Tobii + Talon)
* **autoLoginUser** `nullOr str` Utilisateur de connexion automatique (obligatoire pour une session sans clavier).
* **gazeUsers** `listOf str` Utilisateurs dont la session GDM est initialisée en Cinnamon/X11 (autoLoginUser est toujours inclus).
* **package** `nullOr package` Paquet Talon (par défaut `pkgs.talon` de l'overlay talon-nix lorsque disponible).

```nix
darkone.host.umi = {
  enable = false;
  autoLoginUser = null;
  gazeUsers = [ ];
  package = pkgs.talon or null;
};
```

### &#x1F4E6; darkone.profile.advanced

Profil pour les utilisateurs avancés (informaticiens, développeurs, administrateurs).

:::note[Profil d'hôte vs profil Home]
Ce module active des fonctionnalités pour tous les utilisateurs du système.
Utilisez les profils HomeManager pour fournir des logiciels adaptés à chaque utilisateur (admin, avancé, étudiant, enfant, adolescent, etc.).
:::

* **enable** `bool` Utilisateur avancé (admin sys, développeur)

```nix
darkone.profile.advanced.enable = false;
```
