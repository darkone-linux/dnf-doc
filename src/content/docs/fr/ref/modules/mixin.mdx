### &#x1F4E6; darkone.host.gateway

La passerelle / routeur principal d'une zone de réseau local.

:::tip[Une passerelle prête à l'emploi !]
La passerelle se configure dans le fichier `usr/config.yaml`.
Les services activés additionnels (homepage, adguardhome, forgejo, nix-cache...)
sont automatiquement configurés avec une connectique réseau cohérente sur la
passerelle et sur toutes les machines du réseau local.
:::

:::caution[Le trafic routé est filtré]
`filterForward = true` : seuls les échanges LAN &lt;-&gt; WAN et LAN &lt;-&gt; tailnet
passent. Tout le reste est supprimé → ajoutez-le à
`networking.firewall.extraForwardRules`.
:::

:::tip[Liens de secours : Internet en mode dégradé]
`backupLinks` ajoute des liens de secours (port Ethernet libre, client Wi-Fi
comme un partage de connexion de téléphone) vers lesquels la zone se replie
lorsque le WAN perd sa liaison, son bail ou Internet :

```nix
darkone.host.gateway.backupLinks.phone = {
  type = "wifi";          # SSID + passphrase: sops `backup-link/phone/{ssid,psk}`
  interface = "wlp4s0";
  priority = 10;          # lower = preferred among backups
};
```

Les métriques de routage orientent la route par défaut ; `dnf-uplink-monitor`
effectue des ping via chaque lien et pénalise celui qui n'a pas Internet.
Détails : `lib/uplinks.nix`.
:::

* **enable** `bool` Active les fonctionnalités de passerelle pour l'hôte courant (dhcp, dns, proxy, etc.)
* **backupLinks** `attrs` Liens de secours, utilisés quand le WAN n'a pas de liaison, pas de bail ou pas
  d'Internet. Nom : `[a-z][a-z0-9-]*`.
  * **type** `enum [ "ethernet" "wifi" ]` `ethernet` : client DHCP sur un port libre. `wifi` : client WPA2/WPA3 ;
    le SSID et la phrase de passe sont lus depuis sops
    (`backup-link/&lt;name&gt;/ssid`, `backup-link/&lt;name&gt;/psk`).
  * **interface** `str` Interface qui porte le lien : ni le WAN, ni un port LAN, ni une radio hostapd.
  * **priority** `ints.between 1 99` Plus la valeur est basse, plus le lien est préféré parmi les liens de
    secours (métrique de route 200 + 10 × priority, le WAN restant à 100).
* **linkCheck.targets** `nonEmptyListOf str` Adresses IP pingées via chaque lien de secours ; une seule réponse suffit. Uniquement des IP littérales : la sonde ne doit pas dépendre du DNS.
* **linkCheck.interval** `ints.positive` Secondes entre deux tours de sonde.
* **linkCheck.failAfter** `ints.positive` Nombre de tours échoués avant qu'un lien de secours soit pénalisé.
* **linkCheck.recoverAfter** `ints.positive` Nombre de tours réussis avant qu'un lien de secours pénalisé soit rétabli (hystérésis).

```nix
darkone.host.gateway = {
  enable = false;
  backupLinks.type = null;
  backupLinks.interface = "wlp4s0";
  backupLinks.priority = 10;
  linkCheck.targets = internetProbeTargets;
  linkCheck.interval = 10;
  linkCheck.failAfter = 3;
  linkCheck.recoverAfter = 6;
};
```

### &#x1F4E6; darkone.host.hcs

Serveur de coordination headscale principal.

:::tip[Un serveur headscale prêt à l'emploi&nbsp;!]
Le réseau est configuré dans le fichier `usr/config.yaml`.
Les services supplémentaires activés (authentification, etc.)
sont automatiquement configurés avec une connectivité réseau cohérente sur
votre réseau global.

Alias Zsh «&nbsp;h&nbsp;» pour «&nbsp;headscale&nbsp;».
:::

:::caution[SSH public]
Le port 22 est ouvert sur toutes les interfaces, Internet compris — unique
hôte de la flotte dans ce cas&nbsp;: il héberge le plan de contrôle du tailnet,
l'y accéder ne doit donc pas nécessiter le tailnet.
:::

* **enable** `bool` Activer le serveur de coordination headscale
* **enableClient** `bool` Activer le client tailscale sur le nœud HCS (recommandé pour héberger des services)

```nix
darkone.host.hcs = {
  enable = false;
  enableClient = true;
};
```

### &#x1F4E6; darkone.host.minimal

Chaque configuration d'hôte est basée sur cette configuration minimale.

:::caution[Déclaration de services]
Un certain nombre de services (immich, nextcloud, forgejo, etc.) peuvent être déclarés dans
`usr/config.yaml` de chaque hôte, quel que soit son type (serveur, ordinateur portable,
bureau, etc.). **Il est conseillé de les déclarer dans le fichier yaml pour que
le service soit visible sur l'ensemble du réseau!**
:::

* **enable** `bool` Configuration minimale de l'hôte
* **secure** `bool` Préférer des options plus sécurisées (désactiver les utilisateurs mutables...)

```nix
darkone.host.minimal = {
  enable = false;
  secure = false;
};
```

### &#x1F4E6; darkone.host.umi

Profil d'hôte : poste UMI (Unified Multimodal Input), utilisable sans clavier ni souris.

:::note[UMI : Unified Multimodal Input]
Objectif d'accessibilité : des entrées coordonnées (toucher, voix, regard…) remplacent
le clavier et la souris, combinées selon les capacités de l'utilisateur. Pile actuelle :
Onboard sur écran tactile, commandes vocales Talon, Tobii Eye Tracker 5 piloté via Talon.
:::

:::note[Hérite du profil desktop]
Hérite du profil desktop complet (GNOME, multimédia, bureautique) et ajoute les
prérequis UMI : une session Cinnamon X11 pour les utilisateurs UMI, l'auto-login,
l'injection d'événements uinput et les règles udev Tobii.
:::

:::tip[Coexistence X11 / Wayland]
Talon nécessite X11 (Wayland non pris en charge en amont, pas prévu) et
GNOME 50 a supprimé sa session Xorg, donc les sessions UMI tournent sous Cinnamon (X11,
UX proche de GNOME, barre système native) tandis que les autres utilisateurs conservent
GNOME Wayland. Les utilisateurs listés dans `gazeUsers` (plus `autoLoginUser`) voient
leur session GDM sauvegardée initialisée sur "cinnamon" via AccountsService ; GDM
continue à gérer le fichier ensuite.
:::

:::caution[Paquet Talon]
`pkgs.talon` provient de l'entrée `talon-nix` branchée dans le flake DNF
(x86_64-linux uniquement, archive amont non libre). Avec `package = null`,
udev/uinput/a11y sont tout de même configurés et Talon peut être lancé manuellement
(steam-run sur l'archive amont, ce qui conserve la mise à jour automatique).
:::

:::tip[Premier lancement]
Le firmware du Tobii 5 doit être initialisé une fois sur une machine Windows
(Tobii Experience). Au premier démarrage de Talon, rebranchez le tracker puis
redémarrez Talon (udev), puis lancez la calibration depuis le menu Talon.
:::

:::note[Bruit attendu du noyau]
Le tracker déclare deux interfaces de classe vidéo (caméras oculaires IR brutes) que
uvcvideo ne peut pas gérer : `Unknown video format`, `No supported video formats
found`, `probe with driver uvcvideo failed with error -22`. Sans danger et
souhaité : aucun pilote noyau ne revendique les interfaces, donc libusb les obtient
librement. Le tracker est atteint via l'interface 0 (spécifique au fournisseur,
endpoints bulk), jamais via /dev/video*.
:::

* **enable** `bool` Configuration de l'hôte UMI : entrées multimodales, toucher + voix + regard (Onboard, Talon, Tobii)
* **autoLoginUser** `nullOr str` Utilisateur en auto-login (obligatoire pour une session sans clavier).
* **gazeUsers** `listOf str` Utilisateurs UMI dont la session GDM est initialisée sur Cinnamon/X11 (autoLoginUser est toujours inclus).
* **package** `nullOr package` Paquet Talon (par défaut `pkgs.talon` de l'overlay talon-nix quand il est disponible).

```nix
darkone.host.umi = {
  enable = false;
  autoLoginUser = null;
  gazeUsers = [ ];
  package = pkgs.talon or null;
};
```

### &#x1F4E6; darkone.profile.advanced

Profil pour les utilisateurs avancés (informaticiens, développeurs, administrateurs).

:::note[Profil d'hôte vs profil Home]
Ce module active des fonctionnalités pour tous les utilisateurs du système.
Utilisez les profils HomeManager pour fournir des logiciels adaptés à chaque utilisateur (admin, avancé, étudiant, enfant, adolescent, etc.).
:::

* **enable** `bool` Utilisateur avancé (admin sys, développeur)

```nix
darkone.profile.advanced.enable = false;
```
