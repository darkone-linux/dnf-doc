### &#x1F4E6; darkone.host.gateway.backup-links

Passerelle DNF : liens de secours. Doc&nbsp;: en-tête de `../gateway.nix`.

* **backupLinks** `attrs` Liens de repli, utilisés quand le WAN n'a ni lien, ni bail, ni
  Internet. Nom&nbsp;: `[a-z][a-z0-9-]*`.
  * **type** `enum [ "ethernet" "wifi" ]` `ethernet`&nbsp;: client DHCP sur un port libre, toujours actif. `wifi`&nbsp;:
    client WPA2/WPA3, radio désactivée (rfkill) tant qu'aucun lien
    préféré n'atteint Internet&nbsp;; SSID et phrase de passe sont lus dans sops
    (`backup-link/&lt;name&gt;/ssid`, `backup-link/&lt;name&gt;/psk`).
  * **interface** `str` Interface portant le lien&nbsp;: ni le WAN, ni un port LAN, ni une radio hostapd.
  * **priority** `ints.between 1 99` La plus basse est préférée parmi les liens de secours (métrique de route
    200 + 10 × priority, le WAN restant à 100).
* **linkCheck.targets** `nonEmptyListOf str` Adresses IP pingées via chaque lien&nbsp;; une réponse suffit. IP littérales uniquement&nbsp;: la sonde ne doit pas dépendre du DNS.
* **linkCheck.interval** `ints.positive` Secondes entre deux séries de sondes.
* **linkCheck.failAfter** `ints.positive` Séries échouées avant pénalité d'un lien.
* **linkCheck.recoverAfter** `ints.positive` Séries réussies avant restauration d'un lien pénalisé (hystérésis).

```nix
darkone.host.gateway.backup-links = {
  backupLinks.type = null;
  backupLinks.interface = "wlp4s0";
  backupLinks.priority = 10;
  linkCheck.targets = internetProbeTargets;
  linkCheck.interval = 10;
  linkCheck.failAfter = 3;
  linkCheck.recoverAfter = 6;
};
```

### &#x1F4E6; darkone.host.gateway

La passerelle / routeur principal d'une zone de réseau local.

:::tip[Une passerelle prête à l'emploi&nbsp;!]
La passerelle est configurée dans le fichier `etc/config.yaml`.
Les services activés en supplément (homepage, adguardhome, forgejo, nix-cache...)
sont configurés automatiquement avec une interconnexion réseau cohérente sur la
passerelle et toutes les machines du réseau local.
:::

:::caution[Trafic routé filtré]
`filterForward = true`&nbsp;: seuls LAN &lt;-&gt; WAN et LAN &lt;-&gt; tailnet passent. Tout le
reste est jeté — ajoutez-le à `networking.firewall.extraForwardRules`.
:::

Sous-module (`gateway/`)&nbsp;: `backup-links.nix`, liens de secours.

{/* t:p 090f2b0cda40fa5b9621158a96d67bed77a6415df76ee294e62381c1a76b2825 */}
#### Liens de secours (`backup-links.nix`)

:::tip[Liens de secours&nbsp;: Internet en mode dégradé]
`backupLinks` ajoute des liens de repli (port ethernet libre, client wifi type
point d'accès de téléphone) auxquels la zone se rabat quand le WAN perd son
lien, son bail ou Internet&nbsp;:

```nix
darkone.host.gateway.backupLinks.phone = {
  type = "wifi";          # SSID + phrase de passe: sops `backup-link/phone/{ssid,psk}`
  interface = "wlp4s0";
  priority = 10;          # plus bas = préféré parmi les secours
};
```

Les métriques de route orientent la route par défaut&nbsp;; `dnf-uplink-monitor`
pinge via chaque lien, pénalise celui sans Internet et remet celui revenu
d'une panne à l'épreuve jusqu'à ce qu'il réponde. Un lien wifi garde sa
radio éteinte tant qu'aucun lien préféré n'atteint Internet&nbsp;; un lien
ethernet reste actif, inactif. Détails&nbsp;: `lib/uplinks.nix`.
:::

* **enable** `bool` Activer les fonctions de passerelle pour l'hôte courant (dhcp, dns, proxy, etc.)

```nix
darkone.host.gateway.enable = false;
```

### &#x1F4E6; darkone.host.hcs

Le serveur de coordination headscale principal.

:::tip[Un serveur headscale prêt à l'emploi&nbsp;!]
Le réseau est configuré dans le fichier `etc/config.yaml`.
Les services activés en supplément (authentification, etc.)
sont configurés automatiquement avec une interconnexion réseau cohérente sur
votre réseau global.

Alias Zsh «&nbsp;h&nbsp;» pour «&nbsp;headscale&nbsp;».
:::

:::caution[SSH public]
Le port 22 est ouvert sur toutes les interfaces, Internet compris — seul hôte
de la flotte dans ce cas&nbsp;: il fait tourner le plan de contrôle du tailnet,
son atteinte ne doit donc pas requérir le tailnet.
:::

* **enable** `bool` Activer le serveur de coordination headscale
* **enableClient** `bool` Activer le client tailscale sur le nœud HCS (recommandé pour héberger des services)

```nix
darkone.host.hcs = {
  enable = false;
  enableClient = true;
};
```

### &#x1F4E6; darkone.host.minimal

Toute configuration d'hôte repose sur cette configuration minimale.

:::caution[Déclaration des services]
Un certain nombre de services (immich, nextcloud, forgejo, etc.) peuvent être
déclarés dans `etc/config.yaml` de chaque hôte, quel que soit son type
(serveur, portable, fixe, etc.). **Il est conseillé de les déclarer dans le
fichier yaml pour que le service soit visible sur l'ensemble du réseau&nbsp;!**
:::

* **enable** `bool` Configuration d'hôte minimale
* **secure** `bool` Préférer des options plus sûres (désactiver les utilisateurs mutables...)

```nix
darkone.host.minimal = {
  enable = false;
  secure = false;
};
```

### &#x1F4E6; darkone.host.umi

Profil hôte : poste UMI (Unified Multimodal Input), utilisable sans clavier ni souris.

:::note[UMI : saisie multimodale unifiée]
Objectif d'accessibilité : des entrées coordonnées (tactile, vocale, regard…) remplacent le clavier et la souris, combinées pour s'adapter aux capacités de l'utilisateur. Pile actuelle : Onboard sur un écran tactile, commandes vocales Talon, eye-tracker Tobii Eye Tracker 5 piloté via Talon.
:::

:::note[Étend le profil bureau]
Hérite du profil bureau complet (GNOME, multimédia, bureautique) et ajoute les prérequis UMI : une session Cinnamon X11 pour les utilisateurs UMI, connexion automatique, injection d'événements uinput et règles udev pour Tobii.
:::

:::tip[Coexistence X11 / Wayland]
Talon requiert X11 (Wayland non pris en charge en amont, pas prévu) et GNOME 50 a supprimé sa session Xorg. Les sessions UMI utilisent donc Cinnamon (X11, interface proche de GNOME, zone de notification native), tandis que les autres utilisateurs conservent GNOME Wayland. Les utilisateurs hôtes dont le répertoire personnel active `darkone.home.umi` (profil utilisateur `umi`) voient leur session GDM enregistrée automatiquement forcée sur « cinnamon » via AccountsService à chaque démarrage : un utilisateur sans clavier ne peut pas choisir sa session à l'écran de connexion.
:::

:::caution[Paquet Talon]
`pkgs.talon` provient de l'entrée `talon-nix` intégrée au flocon DNF (x86_64-linux uniquement, tarball propriétaire en amont). Avec `package = null`, les règles udev/uinput et l'accessibilité restent configurées et Talon peut être lancé manuellement (steam-run sur le tarball amont, ce qui permet la mise à jour automatique).
:::

:::tip[Premier lancement]
Le micrologiciel du Tobii 5 doit être initialisé une fois sur une machine Windows (Tobii Experience). Au premier démarrage de Talon, rebranchez l'eye-tracker puis redémarrez Talon (udev), et lancez l'étalonnage depuis le menu Talon.
:::

:::caution[Pas de mousetweaks]
muffin gère lui-même les clics prolongés (types de clic depuis le panneau). Un démon mousetweaks dans la session créerait des clics prolongés en parallèle avec de simples clics gauches (le type choisi ne serait jamais utilisé), ouvrirait sa fenêtre « Clic au survol » et bloquerait la molette de la souris sur la fenêtre racine jusqu'à la déconnexion (`XGrabButton` sur les boutons 4/5).
:::

:::note[Bruit du noyau attendu]
L'eye-tracker déclare deux interfaces de classe vidéo (caméras IR oculaires brutes) que uvcvideo ne peut pas prendre en charge : `Unknown video format`, `No supported video formats found`, `probe with driver uvcvideo failed with error -22`. Ces messages sont inoffensifs et attendus : aucun pilote du noyau ne revendique ces interfaces, libusb y accède donc directement. L'eye-tracker est atteint via l'interface 0 (spécifique au fournisseur, points de terminaison bulk), jamais via /dev/video*.
:::

* **enable** `bool` Configuration UMI de l'hôte : saisie multimodale, tactile + vocale + regard (Onboard, Talon, Tobii)
* **autoLoginUser** `nullOr str` Utilisateur connecté automatiquement (obligatoire pour une session sans clavier), un utilisateur hôte doté du profil `umi`.
* **package** `nullOr package` Paquet Talon (par défaut `pkgs.talon` depuis l'overlay talon-nix s'il est disponible).

```nix
darkone.host.umi = {
  enable = false;
  autoLoginUser = null;
  package = pkgs.talon or null;
};
```

### &#x1F4E6; darkone.profile.advanced

Profil pour les utilisateurs avancés (informaticiens, développeurs, administrateurs).

:::note[Profil d'hôte vs profil Home]
Ce module active des fonctionnalités pour tous les utilisateurs du système.
Utilisez les profils HomeManager pour fournir des logiciels adaptés à chaque utilisateur (admin, avancé, étudiant, enfant, adolescent, etc.).
:::

```nix
darkone.profile.advanced.enable = false;
```
