### &#x1F4E6; darkone.host.ai-space

Espace IA : hôte headless exécutant les agents d'un espace (propriétaire + membres).

Base serveur avec secrets isolés de la flotte : les agents lisent des entrées
non fiables (mail, web, chat), l'hôte ne déchiffre donc que son propre
`usr/secrets/hosts/<hostname>.yaml`. Généralement un invité microVM
(`features: ["microvm-guest:<hypervisor>"]`), le métal nu fonctionne aussi.

Outillage des agents, déclaré une fois par espace (`usr/machines/<host>/configuration.nix`)
et partagé par l'assistant OpenClaw et le Claude Code / Codex / OpenCode de chaque
membre (`darkone.home.aiSpace`, actif par défaut dans le home `space-member`) :

- `mcp` : serveurs MCP, locaux (`command`) ou distants (`url`) ;
- `skills` : contenu `SKILL.md`, un fichier ou un dossier de skill, par nom ;
- `enableClaude`, `enableCodex`, `enableOpenCode` : CLI pour les membres et pour
  la délégation OpenClaw ;
- `packages` : outils dans le PATH des agents et dans les homes des membres ;
- `projectsDir` : projets partagés, inscriptibles par chaque membre et l'agent
  (groupe `projects`, setgid, ACL par défaut), `~/projects` dans les homes des membres.

```nix
darkone.host.ai-space = {
  mcp.fetch = { command = "uvx"; args = [ "mcp-server-fetch" ]; };
  mcp.github = {
    command = "github-mcp-server";
    args = [ "stdio" ];
    secretEnv = [ "GITHUB_PERSONAL_ACCESS_TOKEN" ]; # sops: mcp/github/<VAR>
  };
  skills.commit-style = ./skills/commit-style;
  packages = [ pkgs.uv pkgs.pandoc pkgs.github-mcp-server ];
};
```

:::caution[Secrets : `secretEnv` uniquement]
`env` et `headers` finissent dans le store Nix lisible par tous. `secretEnv`
lit le fichier sops de l'espace, pour les serveurs locaux : un serveur distant ne
prend pas de secret.
:::

* **enable** `bool` Hôte d'espace IA (espace de travail isolé des agents)
* **mcp** `attrs` Serveurs MCP de l'espace : OpenClaw et Claude Code / Codex / OpenCode des membres.
* **skills** `attrs` Skills de l'espace, par nom : `SKILL.md` en ligne, un fichier `SKILL.md` ou
  un dossier de skill. Fournis à OpenClaw et au Claude Code / Codex /
  OpenCode des membres.
* **enableClaude** `bool` Claude Code pour les membres et pour OpenClaw (délégation d'agent de code).
* **enableCodex** `bool` Codex CLI pour les membres et pour OpenClaw (délégation d'agent de code).
* **enableOpenCode** `bool` OpenCode pour les membres et pour OpenClaw (délégation d'agent de code).
* **packages** `listOf package` Outils de l'espace : PATH d'OpenClaw et homes des membres.
* **projectsDir** `str` Projets partagés de l'espace : chaque membre et l'agent OpenClaw
  (son répertoire de travail) les lisent et y écrivent, `~/projects` dans les homes des membres.

```nix
darkone.host.ai-space = {
  enable = false;
  mcp = { };
  skills = { };
  enableClaude = true;
  enableCodex = true;
  enableOpenCode = true;
  packages = [ ];
  projectsDir = "/var/lib/projects";
};
```

### &#x1F4E6; darkone.host.gateway.backup-links

Passerelle DNF : liens de secours. Doc&nbsp;: en-tête de `../gateway.nix`.

* **backupLinks** `attrs` Liens de repli, utilisés quand le WAN n'a ni lien, ni bail, ni
  Internet. Nom&nbsp;: `[a-z][a-z0-9-]*`.
  * **type** `enum [ "ethernet" "wifi" ]` `ethernet`&nbsp;: client DHCP sur un port libre, toujours actif. `wifi`&nbsp;:
    client WPA2/WPA3, radio désactivée (rfkill) tant qu'aucun lien
    préféré n'atteint Internet&nbsp;; SSID et phrase de passe sont lus dans sops
    (`backup-link/&lt;name&gt;/ssid`, `backup-link/&lt;name&gt;/psk`).
  * **interface** `str` Interface portant le lien&nbsp;: ni le WAN, ni un port LAN, ni une radio hostapd.
  * **priority** `ints.between 1 99` La plus basse est préférée parmi les liens de secours (métrique de route
    200 + 10 × priority, le WAN restant à 100).
* **linkCheck.targets** `nonEmptyListOf str` Adresses IP pingées via chaque lien&nbsp;; une réponse suffit. IP littérales uniquement&nbsp;: la sonde ne doit pas dépendre du DNS.
* **linkCheck.interval** `ints.positive` Secondes entre deux séries de sondes.
* **linkCheck.failAfter** `ints.positive` Séries échouées avant pénalité d'un lien.
* **linkCheck.recoverAfter** `ints.positive` Séries réussies avant restauration d'un lien pénalisé (hystérésis).

```nix
darkone.host.gateway.backup-links = {
  backupLinks.type = null;
  backupLinks.interface = "wlp4s0";
  backupLinks.priority = 10;
  linkCheck.targets = internetProbeTargets;
  linkCheck.interval = 10;
  linkCheck.failAfter = 3;
  linkCheck.recoverAfter = 6;
};
```

### &#x1F4E6; darkone.host.gateway

La passerelle / routeur principal d'une zone de réseau local.

:::tip[Une passerelle prête à l'emploi !]
La passerelle est configurée dans le fichier `etc/config.yaml`.
Les services activés en plus (homepage, adguardhome, forgejo, nix-cache...)
sont configurés automatiquement avec un câblage réseau cohérent sur la
passerelle et sur toutes les machines du réseau local.
:::

:::caution[SSH public jusqu'à la prise en charge par le tailnet]
`wanSsh.enable` ouvre sshd sur l'interface WAN (clé uniquement, fail2ban), pour
installer une passerelle distante joignable via une redirection de port de la box. Par défaut : activé
tant que headscale est actif et que la zone ne déclare pas de `gateway.vpn.ipv4` ;
le déclarer puis appliquer ferme le port. L'initrd (déverrouillage LUKS, 2222)
n'a pas de pare-feu : cette option ne s'y applique pas.
:::

:::caution[Le trafic routé est filtré]
`filterForward = true` : seuls LAN &lt;-&gt; WAN et LAN &lt;-&gt; tailnet se croisent. Tout
le reste est supprimé : ajoutez-le à `networking.firewall.extraForwardRules`.
:::

Sous-module (`gateway/`) : `backup-links.nix`, liaisons montantes de secours.

{/* t:p f7e4f97eb755dfcde71a957348f5b9839413ce9205f946a3e551936e35dc1a44 */}
#### Liaisons montantes de secours (`backup-links.nix`)

:::tip[Liaisons de secours : Internet en mode dégradé]
`backupLinks` ajoute des liaisons montantes (port ethernet de rechange, client
wifi comme un partage de connexion de téléphone) vers lesquelles la zone bascule quand le WAN perd sa liaison, son bail
ou l'Internet&nbsp;:

```nix
darkone.host.gateway.backupLinks.phone = {
  type = "wifi";          # SSID + passphrase: sops `backup-link/phone/{ssid,psk}`
  interface = "wlp4s0";
  priority = 10;          # lower = preferred among backups
};
```

Les métriques de route pilotent la route par défaut ; `dnf-uplink-monitor` fait un ping via
chaque liaison, pénalise celle sans Internet et en retient une après une panne
en probation jusqu'à ce qu'elle réponde. Une liaison wifi garde sa radio
éteinte jusqu'à ce qu'aucune liaison préférée n'atteigne Internet ; une liaison ethernet reste active,
au repos. Détails : `lib/uplinks.nix`.
:::

* **enable** `bool` Active les fonctionnalités de passerelle pour l'hôte courant (dhcp, dns, proxy, etc.)
* **wanSsh.enable** `bool` SSH public sur l'interface WAN, pour joindre une passerelle distante pas encore sur le tailnet

```nix
darkone.host.gateway = {
  enable = false;
  wanSsh.enable = dnfLib.gatewayAwaitsTailnet network zone;
};
```

### &#x1F4E6; darkone.host.hcs

Le serveur de coordination headscale principal.

:::tip[Un serveur headscale prêt à l'emploi&nbsp;!]
Le réseau est configuré dans le fichier `etc/config.yaml`.
Les services activés en supplément (authentification, etc.)
sont configurés automatiquement avec une interconnexion réseau cohérente sur
votre réseau global.

Alias Zsh «&nbsp;h&nbsp;» pour «&nbsp;headscale&nbsp;».
:::

:::caution[SSH public]
Le port 22 est ouvert sur toutes les interfaces, Internet compris — seul hôte
de la flotte dans ce cas&nbsp;: il fait tourner le plan de contrôle du tailnet,
son atteinte ne doit donc pas requérir le tailnet.
:::

* **enable** `bool` Activer le serveur de coordination headscale
* **enableClient** `bool` Activer le client tailscale sur le nœud HCS (recommandé pour héberger des services)

```nix
darkone.host.hcs = {
  enable = false;
  enableClient = true;
};
```

### &#x1F4E6; darkone.host.minimal

### &#x1F4E6; darkone.host.umi

Profil hôte : poste de travail UMI (Unified Multimodal Input), utilisable sans clavier ni souris.

:::note[UMI: Unified Multimodal Input]
Objectif d'accessibilité : des entrées coordonnées (tactile, voix, regard…) remplacent clavier et souris, combinées selon les capacités de l'utilisateur. Pile actuelle : Onboard sur écran tactile, commandes vocales Talon, Tobii Eye Tracker 5 piloté via Talon.
:::

:::note[Extension du bureau]
Hérite du profil bureau complet (GNOME, multimédia, bureautique) et ajoute les prérequis UMI : une session Cinnamon X11 pour les utilisateurs UMI (mode sombre par défaut), la connexion automatique, l'injection d'événements uinput et les règles udev Tobii.
:::

:::tip[Coexistence X11 / Wayland]
Talon requiert X11 (Wayland non pris en charge en amont, pas prévu) et GNOME 50 a abandonné sa session Xorg ; les sessions UMI s'exécutent donc sous Cinnamon (X11, ergonomie type GNOME, tray système natif) tandis que les autres utilisateurs conservent GNOME Wayland. Les utilisateurs de l'hôte dont la configuration home active `darkone.home.umi` (profil utilisateur `umi`) voient leur session GDM enregistrée épinglée sur « cinnamon » via AccountsService, à chaque démarrage : un utilisateur sans clavier ne peut pas choisir de session au greeter.
:::

:::caution[Paquet Talon]
`pkgs.talon` provient de l'input `talon-nix` câblé dans le flake DNF (x86_64-linux uniquement, tarball propriétaire en amont). Avec `package = null`, udev/uinput/a11y restent configurés et Talon peut être lancé manuellement (steam-run sur le tarball en amont, ce qui conserve le fonctionnement du auto-update).
:::

:::tip[Premier lancement]
Le firmware Tobii 5 doit être initialisé une fois sur une machine Windows (Tobii Experience). Au premier démarrage de Talon, rebrancher le tracker puis redémarrer Talon (udev), et lancer l'étalonnage depuis le menu Talon.
:::

:::caution[Pas de mousetweaks]
muffin réalise lui-même les clics de maintien (types de clic depuis le panneau). Un daemon mousetweaks dans la session effectuerait des maintiens en parallèle avec de simples clics gauche (le type choisi n'est jamais utilisé), ferait apparaître sa fenêtre « Clic de maintien » et capturerait la molette de la souris sur la fenêtre racine jusqu'à la déconnexion (`XGrabButton` sur les boutons 4/5).
:::

:::note[Bruit noyau attendu]
Le tracker déclare deux interfaces de classe vidéo (caméras oculaires IR brutes) que uvcvideo ne peut pas gérer : `Unknown video format`, `No supported video formats found`, `probe with driver uvcvideo failed with error -22`. Inoffensifs et voulus : aucun driver noyau ne réclame les interfaces, elles restent donc libres pour libusb. Le tracker est atteint via l'interface 0 (spécifique au fournisseur, points de terminaison bulk), jamais via /dev/video*.
:::

* **enable** `bool` Configuration hôte UMI : entrées multimodales, tactile + voix + regard (Onboard, Talon, Tobii)
* **autoLoginUser** `nullOr str` Utilisateur de connexion automatique (obligatoire pour une session sans clavier), un utilisateur de l'hôte avec le profil `umi`.
* **package** `nullOr package` Paquet Talon (par défaut `pkgs.talon` de l'overlay talon-nix si disponible).

```nix
darkone.host.umi = {
  enable = false;
  autoLoginUser = null;
  package = pkgs.talon or null;
};
```

darkone.profile.advanced.enable = false;
