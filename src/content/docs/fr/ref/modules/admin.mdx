### &#x1F451; darkone.admin.nix

Configuration NixOS pour le poste administrateur du LAN local.

:::tip[Ferme de build (builders distants)]
Un hôte admin construit localement chaque closure de nœud et la pousse
(`buildOnTarget` vide, voir `assets/just/project.just`), c'est donc lui qui
compile réellement. Tout hôte de la flotte marqué `build-farm` dans
`config.yaml` devient l'un de ses `nix.buildMachines`, joint en SSH avec
l'utilisateur de déploiement `nix`.

La délégation est volontairement étroite. `mandatoryFeatures` (défaut
`big-parallel`) signifie que la ferme ne se voit proposer **que** les
derivations qui déclarent `requiredSystemFeatures = [ "big-parallel" ]` :
kernel, chromium, firefox, llvm, rustc… c'est-à-dire les builds longs pour
lesquels une machine costaude est voulue. Tout le reste reste local, ce qui
compte quand la ferme se trouve derrière une liaison lente : seul le résultat
demandé repart.

Ne retirez jamais `big-parallel` de `nix.settings.system-features` de cet hôte
pour forcer la délégation : le conserver signifie qu'une ferme injoignable fait
refuser le hook de build et la derivation est simplement buildée localement au
lieu d'échouer.

:::caution[Clé de déploiement requise]
`sshKey` pointe sur la clé de déploiement partagée que `just configure-admin-host`
génère dans le home de l'utilisateur `nix`. Les hôtes admin la détiennent par
construction ; un hôte qui active ce module sans la clé journalise des échecs
SSH à chaque build délégué.
:::

:::note[Pourquoi pas un cache binaire]
Un `harmonia` sur la ferme partagerait ses résultats de build, mais harmonia
sert tout `/nix/store` et ne peut pas exprimer « seulement ce que j'ai compilé » :
il capte le trafic que le cache public devrait servir. Le déchargement est une
question d'ordonnancement de build, pas de substitution : d'où `buildMachines`
ici et une priorité de substituteur en dernier recours dans `service/nix-cache.nix`.
:::

* **enable** `bool` Active les outils de construction de configuration NIX
* **enableNh** `bool` Active l'outil de gestion nix helper (nh)
* **remoteBuilders.enable** `bool` Décharge les builds vers les hôtes de la flotte marqués `build-farm` dans
  `config.yaml`. Inerte tant qu'aucun hôte ne porte le drapeau.
* **remoteBuilders.maxJobs** `int` Emplacements de build parallèles à utiliser sur chaque ferme.
* **remoteBuilders.speedFactor** `int` Indice de vitesse relatif d'une ferme, comparé à cet hôte.
* **remoteBuilders.mandatoryFeatures** `listOf str` Fonctionnalités qu'une derivation DOIT exiger pour qu'une ferme se la voie proposer. C'est
  ce qui maintient les petites derivations hors d'une liaison distante (potentiellement lente).
  Une liste vide envoie chaque derivation éligible à la ferme.
* **remoteBuilders.supportedFeatures** `listOf str` Fonctionnalités système qu'une ferme peut fournir.
* **remoteBuilders.systems** `listOf str` Plateformes pour lesquelles une ferme build. Explicite plutôt que dérivé : `hosts.nix`
  ne porte une architecture que lorsqu'elle diffère du défaut.

```nix
darkone.admin.nix = {
  enable = false;
  enableNh = false;
  remoteBuilders.enable = true;
  remoteBuilders.maxJobs = 8;
  remoteBuilders.speedFactor = 2;
  remoteBuilders.mandatoryFeatures = [ ];
  remoteBuilders.supportedFeatures = [ ];
  remoteBuilders.systems = [ ];
};
```
