### &#x1F511; darkone.security.complement

Mesures complémentaires transversales — Annexe A (C1 à C12). (wip)

Ces mesures n'ont pas de numéro ANSSI mais sont essentielles à l'esprit du guide.
Couvre les correctifs linux-hardened (C1), Lockdown LSM (C2), USBGuard (C3),
nftables deny-by-default (C4), SSH renforcé (C5), LUKS2 (C6), NTP/NTS (C7),
DNS sécurisé (C8), core dumps désactivés (C9), PAM anti force brute (C10),
bannières légales (C11), et restriction cron/at (C12).

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) sont activées en fonction du niveau, de la catégorie et des exclusions
définis dans `darkone.system.security` (via `isActive`).
:::

:::note[Niveau Lockdown LSM (C2)]
- `none` : pas de Lockdown.
- `integrity` : interdit les modifications du noyau depuis l'espace utilisateur.
- `confidentiality` : idem + interdit la lecture des secrets du noyau.
:::

:::caution[C2 — Lockdown LSM]
`lockdown=confidentiality` interdit kexec, les écritures dans /dev/mem, MSR, l'hibernation.
Casse `dmidecode` sur certaines zones, `flashrom`, `i2c-tools`.
:::

:::caution[C4 — Filtrage sortant]
La politique deny-by-default en sortie casse les outils accédant aux CDNs (curl,
téléchargements noyau). Requis : un proxy HTTP(S) sortant contrôlé.
:::

:::caution[C5 — SSH renforcé]
Les tunnels, le forwarding d'agent et X11 sont désactivés. `ssh -J` aussi : ProxyJump
ouvre un canal `direct-tcpip`, exactement ce que `AllowTcpForwarding`
refuse — l'accès admin est direct via la tailnet, jamais en rebond. Ce
module écrase la config SSH de `core.nix`.
:::

* **enable** `bool` Activer les mesures complémentaires ANSSI (C1 à C12).
* **lockdownLevel** `enum [ "none" "integrity" "confidentiality" ]` Niveau Lockdown LSM (C2)
* **lsmStack** `listOf str` Ordre de la pile LSM (C2, R11, R20). Modifie boot.kernelParams lsm=...
* **ntpServers** `listOf str` Serveurs NTP/NTS (C7).
* **useNts** `bool` Activer NTS (Network Time Security) pour l'authentification NTP (C7).
* **sshBanner** `str` Bannière SSH affichée avant l'authentification (C11).
* **cronAllowedUsers** `listOf str` Utilisateurs autorisés à planifier des tâches cron (C12).
* **atAllowedUsers** `listOf str` Utilisateurs autorisés à planifier des tâches at (C12). Reflète cronAllowedUsers par défaut.
* **egressAllowlist** `listOf str` Adresses IPv4/IPv6 ou CIDRs autorisées en sortie sous la politique renforcée
  deny-by-default de C4. Liste vide conserve la politique mais seul
  le trafic loopback et établi/lié passe (proxy requis).

```nix
darkone.security.complement = {
  enable = false;
  lockdownLevel = "integrity";
  lsmStack = [ ];
  ntpServers = [ ];
  useNts = true;
  sshBanner = ''
        ╔═════════════════════════════════════════════════════════╗
        ║                    DNF NETWORK NODE                     ║
        ║             Restricted and monitored access.            ║
        ║ Unauthorized access may result in criminal prosecution  ║
        ║ under Articles 323-1 to 323-8 of the French Penal Code. ║
        ╚═════════════════════════════════════════════════════════╝
      '';
  cronAllowedUsers = [ ];
  atAllowedUsers = [ ];
  egressAllowlist = [ ];
};
```

### &#x1F511; darkone.security.filesystem

Partitionnement, arborescence de fichiers et permissions (R28–R29, R50–R57). (wip)

Couvre les options de montage sécurisées (R28), la restriction de /boot (R29),
les permissions des fichiers sensibles (R50), les mots de passe exclus du magasin (R51),
les sockets (R52), les fichiers orphelins (R53), le bit sticky (R54),
les répertoires temporaires par utilisateur (R55) et le setuid (R56, R57).

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) sont activées en fonction du niveau, de la catégorie et des exclusions
définies dans `darkone.system.security` (via `isActive`).
:::

:::caution[R28 — noexec /tmp]
Le `noexec` sur /tmp bloque l'exécution *et* `dlopen` : il perturbe les installateurs et
compilateurs exécutant ce qu'ils décompressent (pip, cargo, gcc) ainsi que tout runtime
extrait des bibliothèques native sur place (Bun, Electron, outils d'agent). Les builds Nix
sont couverts — le TMPDIR du daemon passe en /var/tmp. Exclusion possible par hôte avec
`darkone.security.filesystem.tmpNoexec = false`.
:::

:::caution[R28 — basculement vers /tmp hardené au boot, pas au switch]
Un hôte déjà configuré avec `boot.tmp.useTmpfs` porte un `tmp.mount` statique, que
cette règle remplace par une entrée fstab : le switch l'*arrête* donc, et
`PrivateTmp=yes` implique `RequiresMountsFor=/tmp`, donc chaque unité concernée tombe
avec lui — `dbus-broker` compris. `switch-to-configuration` pilote systemd via D-Bus,
il perd donc son propre transport en cours d'exécution et abandonne, à chaque fois.
Utiliser `apply <host> boot` et redémarrer ; ce niveau nécessite un redémarrage pour
`boot.kernelParams` de toute façon. Les hôtes n'ayant jamais utilisé `useTmpfs`
gagnent simplement un montage, ce qui est sans danger.
:::

:::caution[R29 — /boot noauto]
Le `noauto` sur /boot nécessite un remontage manuel à chaque mise à jour NixOS.
Un wrapper `nixos-rebuild` doit garantir le montage/démontage automatique.
:::

* **enable** `bool` Activer le renforcement ANSSI du système de fichiers (R28–R29, R50–R57).
* **allowedSetuid** `listOf str` Liste blanche des binaires setuid/setgid tolérés (R56, R57).
* **tmpfs** `bool` Indique si R28 prend en charge `/tmp` en tant que tmpfs durci dimensionné sur
  `boot.tmp.tmpfsSize`. Régler sur `false` pour laisser `/tmp` sur le système de fichiers
  où il se trouve déjà — un hôte conservant plusieurs Go de brouillon persistant perd à la fois
  les données et la RAM qui iraient avec.
* **tmpNoexec** `bool` Indique si le `/tmp` de R28 porte `noexec`. Le `noexec` bloque l'exécution
  directe *et* `dlopen`, il perturbe donc tout runtime décompressant des bibliothèques
  native sur place (Bun, Electron, outils d'agent) ainsi que tout ce qui compile
  puis s'exécute dans `TMPDIR`. N'est pertinent que lorsque `tmpfs` vaut `true`.
* **extraMountHardening** `listOf str` Points de montage à durcir avec `nosuid,nodev,noexec` (R28). Chaque chemin
  listé DOIT être une partition séparée déclarée ailleurs (hardware-configuration / disko) ;
  les options sont fusionnées dans l'entrée `fileSystems` existante. Une liste explicite
  (plutôt qu'un indicateur global) évite de deviner la disposition et ne crée jamais de
  montages fictifs. Ne pas lister `/home` si les utilisateurs y exécutent des scripts —
  `noexec` les casserait.

```nix
darkone.security.filesystem = {
  enable = false;
  allowedSetuid = [ ];
  tmpfs = true;
  tmpNoexec = true;
  extraMountHardening = [ ];
};
```

### &#x1F511; darkone.security.integrity

Intégrité du système de fichiers &nbsp;: HIDS (R76–R77). (wip)

Couvre le scellement et la vérification d'intégrité via AIDE (R76) et la protection
de la base scellée par signature GPG plus copie distante (R77).

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) sont activées selon le niveau, la catégorie et les exclusions
définis dans `darkone.system.security` (via `isActive`).
:::

:::caution[R76 — AIDE]
Un scan complet peut prendre 15–60 min selon la taille du FS et le CPU.
Planifier pendant les heures creuses. Faux positifs fréquents sur /etc/resolv.conf,
/var/lib, /var/cache : les ajouter aux exclusions.
:::

:::caution[R77 — Base signée]
La base AIDE doit être re-signée à chaque mise à jour majeure de NixOS
(le store change). Prévoir une procédure de mise à jour de la baseline.
:::

* **enable** `bool` Active l'intégrité HIDS ANSSI — AIDE (R76–R77).
* **aideRemoteCopy** `nullOr submodule` Copie distante de la base AIDE signée GPG (R77). null = désactivée.
  * **host** `str` Hôte distant pour la copie de la base AIDE.
  * **sshKeyFile** `path` Chemin de la clé SSH privée pour la copie distante.

```nix
darkone.security.integrity = {
  enable = false;
  aideRemoteCopy = null;
  aideRemoteCopy.host = null;
  aideRemoteCopy.sshKeyFile = null;
};
```

### &#x1F511; darkone.security.kernel-build

Configuration du noyau statique — nécessite recompilation (R15–R27). (en cours)

Ces règles nécessitent un noyau personnalisé via `boot.kernelPackages`.
NixOS le permet via `structuredExtraConfig`. Toutes ces règles portent
le tag `kernel-recompile` : elles sont ignorées si ce tag est dans `excludes`.

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) sont activées selon le niveau, la catégorie et les exclusions
définis dans `darkone.system.security` (via `isActive`).
:::

:::danger[Pas de cache binaire NixOS]
L'activation de ces règles implique une recompilation locale du noyau
(~30–60 min par mise à jour selon le CPU). Aucun cache binaire public ne couvre
un noyau personnalisé. Réservez à la flotte avec les bons outils MCO.
:::

:::caution[Modules hors arborescence]
R18 (modules signés) rend la signature de tout module externe obligatoire
(NVIDIA, ZFS, VirtualBox, v4l2loopback…) via le pipeline Nix.
:::

* **enable** `bool` Activer le module de recompilation du noyau ANSSI (R15–R27).

```nix
darkone.security.kernel-build.enable = false;
```

### &#x1F511; darkone.security.kernel-params

Configuration dynamique du noyau : paramètres de démarrage et sysctls (R8–R14). (wip)

Règles applicables sans recompiler le noyau. Couvre les options mémoire (R8),
les sysctls système (R9), la désactivation du chargement de modules (R10), Yama/ptrace (R11),
les sysctls réseau IPv4 (R12), la désactivation d'IPv6 (R13)
et les sysctls des systèmes de fichiers (R14).

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) sont activées selon le niveau, la catégorie et les exclusions
définis dans `darkone.system.security` (via `isActive`).
:::

:::caution[R8 — SMT désactivé]
`l1tf=full,force`, `mds=full,nosmt` et `mitigations=auto,nosmt` désactivent
l'hyperthreading, qui représente environ 30 % du débit multi-thread — un prix qu'une
ferme de compilation ne peut pas toujours payer. `disableSmt = false` conserve le reste de R8.
:::

:::caution[R8 — les extras de l'allocateur remplacent l'effacement demandé par l'ANSSI]
`page_poison=on` est prioritaire sur `init_on_alloc`/`init_on_free` — le noyau
l'indique au démarrage — R8 livre donc une fonctionnalité de débogage là où l'ANSSI
demande un effacement mémoire, et `slub_debug=FZP` accompagne chaque cache slab.
`memoryDebug = false` supprime les trois et rend la main à `init_on_*` ; mesuré à
7 % d'une compilation (95 s à 88 s, ms-a2, SMT activé), la raison est donc la conformité
plutôt que la performance.
:::

:::caution[R9 — restreindre les namespaces utilisateur est optionnel]
`kernel.unprivileged_userns_clone` est une clé Debian / linux-hardened, absente
du noyau principal : l'écrire fait échouer `systemd-sysctl`. L'équivalent
du noyau principal (`user.max_user_namespaces = 0`) casse Flatpak, bubblewrap et Podman
sans root, d'où `restrictUserns` — désactivé par défaut.
:::

:::caution[R12 — filtrage du chemin inverse]
Le mode strict (`rp_filter = 1`) supprime tout chemin de retour asymétrique. Un routeur
de sous-réseau Tailscale annonçant des routes avec `--snat-subnet-routes=false`
correspond exactement à ce cas, les routeurs retombent donc en mode souple (2). C'est
aussi le cas d'une passerelle avec des liens de secours : les réponses aux sondes
arrivent sur un lien qui n'est pas la route préférée.
:::

:::caution[R10 — Modules désactivés]
Tout nouveau périphérique nécessitant un module non préchargé impose un redémarrage.
Mutuellement exclusif avec `nixos-rebuild switch` côté pilote.
:::

* **enable** `bool` Activer les paramètres noyau dynamiques ANSSI (R8–R14).
* **restrictUserns** `bool` R9 : interdire les namespaces utilisateur non privilégiés (`user.max_user_namespaces`).
  Casse Flatpak, bubblewrap et Podman sans root, reste donc optionnel et
  convient aux serveurs qui n'en utilisent aucun.
* **disableSmt** `bool` R8 : désactiver l'hyperthreading. Trois paramètres le portent ; `false` les
  ramène chacun à sa forme préservant le SMT et laisse les quatorze autres
  inchangés. À noter : `l1tf=full` supprime le SMT même sans `force` — il ne laisse
  que le paramètre sysfs — le repli est donc `flush`.
* **memoryDebug** `bool` R8 : les extras de l'allocateur — `slub_debug=FZP`, `page_poison=on` et
  `slab_nomerge=yes`. Aucun des trois ne figure dans la liste ANSSI R8, et
  `page_poison` évince `init_on_alloc`/`init_on_free`, que l'ANSSI demande pourtant :
  le noyau le précise au démarrage et privilégie la fonctionnalité de débogage.
  La désactivation restaure l'effacement spécifié et rend 7 % d'une
  compilation (95 s à 88 s, ms-a2, SMT activé).
* **disableIpv6** `bool` R13 : désactiver complètement IPv6. Désactivé par défaut — l'ANSSI elle-même
  préfère durcir IPv6 plutôt que de le supprimer, et un hôte public en a généralement besoin.

```nix
darkone.security.kernel-params = {
  enable = false;
  restrictUserns = false;
  disableSmt = true;
  memoryDebug = true;
  disableIpv6 = false;
};
```

### &#x1F511; darkone.security.mac

Contrôle d'accès obligatoire — MAC (R37, R45–R49). (en cours)

R37 est une méta-règle : valide si au moins R45 (AppArmor) ou R46 (SELinux)
est active. SELinux (R46–R49) n'est pas supporté sur NixOS et est exclu
par défaut via `exceptions`. AppArmor (R45) est partiellement supporté.

:::tip[Mise en sandbox]
Lorsque MAC n'est pas disponible, NixOS s'appuie souvent sur les options systemd
(systemd sandbox) pour isoler les services.
:::

:::note[NixOS et MAC]
SELinux est structurellement non supporté sur NixOS (R46–R49 sont des exceptions par
défaut). AppArmor est disponible mais avec peu de profils prêts à l'emploi.
L'absence de profil pour un service exposé est une fausse sensation de sécurité.
:::

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) sont activées selon le niveau, la catégorie et les exclusions
définis dans `darkone.system.security` (via `isActive`).
:::

:::caution[Tag no-mac]
Utilisez le tag `no-mac` dans `excludes` pour désactiver R37 et R45 avec une
justification explicite dans `exceptions.R37.rationale`.
:::

* **enable** `bool` Activer le module MAC ANSSI — AppArmor/SELinux (R37, R45–R49).

```nix
darkone.security.mac.enable = false;
```

### &#x1F511; darkone.security.network

Services réseau — isolation et supervision (R78–R80). (wip)

Couvre l'isolation des services réseau (R78 : catégorie serveur),
le durcissement et la surveillance des services exposés (R79 : fail2ban,
en-têtes HTTP, TLS ANSSI) et la réduction de la surface réseau (R80).

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) sont activées en fonction du niveau, de la catégorie et des exclusions
définies dans `darkone.system.security` (via `isActive`).
:::

:::caution[R79 — CSP strict]
`Content-Security-Policy: default-src 'self'` casse les outils sans nonces
(tableaux de bord avec CDN, widgets tiers). Le préchargement HSTS est irréversible —
ne le configurer que sur un domaine entièrement contrôlé.
:::

:::caution[R79 — les en-têtes nginx sont optionnels par vhost]
`add_header` remplace le jeu parent au lieu de s'y ajouter, donc un bloc
global est abandonné par le premier vhost ou location déclarant un en-tête
propre — et gixy fait échouer le build à cause de l'occultation. Le jeu est
fourni sous `/etc/nginx/dnf-security-headers.conf`, à `include` depuis le
`extraConfig` propre au vhost. Seules les directives TLS restent globales.
:::

:::caution[R79 — Chaque prison nécessite un filtre]
fail2ban fonctionne ici avec le backend systemd : une prison nécessite à la fois une
définition `filter.d` et un `journalmatch`, sinon elle abandonne l'ensemble du
daemon au démarrage — perdant la prison `sshd` fonctionnelle. `exposedServices`
est donc soumis à une assertion vérifiant `filters` ; caddy, matrix et idm
doivent encore avoir les leurs rédigés.
:::

:::caution[R80 — Filtrage des écouteurs]
Certains services (KDE Connect, mDNS) écoutent par défaut sur toutes les interfaces.
Les déclarer dans `network.publicListeners` ou les reconfigurer.
:::

* **enable** `bool` Activer le durcissement réseau ANSSI (R78–R80).
* **exposedServices** `listOf str` Services publics à mettre en prison avec fail2ban (R79). Chaque entrée DOIT
  résoudre vers un filtre — celui fourni par fail2ban, ou celui déclaré dans `filters` —
  sinon l'assertion refuse le build.
* **filters** `attrs` Filtres utilisables dans `exposedServices`, en plus de ceux fournis par fail2ban.
  Caddy, Synapse et Kanidm nécessitent que les leurs soient rédigés contre de
  vraies sorties journal — les déclarer ici une fois les motifs confirmés.
  * **journalmatch** `str` Correspondance journal pour la prison (fail2ban fonctionne avec le backend systemd).
  * **failregex** `str` Motif d'échec, écrit dans `filter.d/&lt;name&gt;.conf`. Vide lorsque
    fourni par fail2ban et que seule la correspondance manque.
* **publicListeners** `listOf str` Services autorisés à écouter sur 0.0.0.0 / :: (R80).
* **httpsHeaders** `bool` Ajoute les en-têtes de sécurité HTTP ANSSI dans Nginx/Caddy (R79).
* **tlsCiphers** `listOf str` Suite de cipher TLS ANSSI pour Nginx (R79).

```nix
darkone.security.network = {
  enable = false;
  exposedServices = [ ];
  filters.journalmatch = "_SYSTEMD_UNIT=forgejo.service";
  filters.failregex = "";
  publicListeners = [ ];
  httpsHeaders = true;
  tlsCiphers = [ ];
};
```

### &#x1F511; darkone.security.packages

Gestion des paquets et mises à jour (R58–R61). (wip)

Couvre l'installation de ce qui est strictement nécessaire (R58), les dépôts de confiance (R59),
les dépôts durcis (R60 : linux_hardened), et les mises à jour régulières (R61).

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) sont activées selon le niveau, la catégorie et les exclusions
définis dans `darkone.system.security` (via `isActive`).
:::

:::caution[R59 — allow-import-from-derivation=false]
Casse certains flakes complexes (Haskell, Python lourd avec générateurs Nix).
Documenter les exceptions dans nix.settings.
:::

:::caution[R60 — linux_hardened]
Le noyau linux_hardened peut prendre une version mineure de retard sur nixpkgs-unstable.
Les modules tiers (NVIDIA, ZFS) ne sont pas garantis compatibles.
:::

* **enable** `bool` Active la gestion ANSSI des paquets (R58–R61).
* **trustedSubstituters** `listOf str` Allowlist des caches binaires Nix autorisés (R59).
* **trustedPublicKeys** `listOf str` Clés publiques des caches binaires autorisés (R59).
* **allowedUris** `listOf str` Allowlist de préfixes d'URI fetchables pendant l'évaluation (R59).
  Restreint builtins.fetch* / les inputs de flake aux miroirs internes.
  Liste vide : restriction désactivée.
* **maxSystemPackages** `nullOr int` Seuil souple sur le nombre de paquets système (R58).
  Émet un avertissement d'évaluation quand il est dépassé ; null désactive la vérification.

```nix
darkone.security.packages = {
  enable = false;
  trustedSubstituters = [ ];
  trustedPublicKeys = [ ];
  allowedUris = [ ];
  maxSystemPackages = 200;
};
```

### &#x1F511; darkone.security.pam

PAM — Authentification et stockage des mots de passe (R67–R68). (wip)

Couvre l'authentification PAM distante sécurisée (R67 : SSSD, Kerberos,
pam_faillock) et le stockage chiffré des mots de passe (R68 : yescrypt).

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) sont activées selon le niveau, la catégorie et les
exclusions définis dans `darkone.system.security` (via `isActive`).
:::

:::note[Compléments]
pam_faillock (anti force brute) est configuré ici pour R67 ; complement.nix
(C10) ne définit que les limites de session. La politique de complexité
(R31) est dans users.nix.
:::

:::danger[R67 — pam_faillock verrouille les comptes pour de bon]
Trois mots de passe échoués verrouillent le compte pendant 15 minutes par
défaut, sur `login`, `su`, `sudo` et — via le sous-ensemble `login` — le
greeter GNOME. Garder une session root ouverte lors du premier déploiement,
et connaître la procédure de retour : `faillock --user <login> --reset`.
SSH est délibéré préservé afin qu'une session de secours par clé reste
toujours accessible.
:::

* **enable** `bool` Activer le module ANSSI PAM — authentification et mots de passe (R67–R68).
* **faillock.deny** `ints.positive` Nombre d'échecs avant le verrouillage par pam_faillock (R67).
* **faillock.unlockTime** `ints.positive` Secondes pendant lesquelles le compte reste verrouillé (R67). Déverrouiller plus tôt avec `faillock --reset`.

```nix
darkone.security.pam = {
  enable = false;
  faillock.deny = 3;
  faillock.unlockTime = 900;
};
```

### &#x1F511; darkone.security.preboot

Configuration matérielle et démarrage sécurisé (R1–R7). (en cours)

Couvre UEFI Secure Boot (R3), lanzaboote, mot de passe du chargeur d'amorçage (R5),
UKIs signés (R6) et IOMMU (R7). R1 et R2 (matériel/firmware) sont
hors de la portée de NixOS et produisent uniquement une note dans le rapport.

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) sont activées selon le niveau, la catégorie et les exclusions
définis dans `darkone.system.security` (via `isActive`).
:::

:::caution[R3/R4 — Secure Boot]
L'intégration lanzaboote nécessite une inscription de clé physique initiale
(`sbctl enroll-keys`). R4 (remplacement des clés Microsoft) porte un risque d'amorçage
si la machine ne permet pas la restauration.
:::

:::caution[R7 — IOMMU]
Peut causer des crashs avec certains GPU/Thunderbolt ; surcharge E/S ~5–15 %
sur les tableaux NVMe à très haut débit.
:::

* **enable** `bool` Activer le démarrage sécurisé ANSSI — Secure Boot, IOMMU (R1–R7).

```nix
darkone.security.preboot.enable = false;
```

### &#x1F511; darkone.security.services

Durcissement des services systemd (R62–R66). (wip)

Couvre la désactivation des services inutiles (R62), la réduction des fonctionnalités via
les options de sécurité systemd (R63), la restriction des privilèges (R64),
l'isolation (R65), et le durcissement des composants de conteneurisation (R66).

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) sont activées selon le niveau, la catégorie et les exclusions
définis dans `darkone.system.security` (via `isActive`).
:::

:::caution[R63 — MemoryDenyWriteExecute]
Casse les runtimes JIT (Java, V8, .NET, LuaJIT, Wasm). Utiliser le
tag `needs-jit` dans `excludes` ou exclure le service individuellement.
:::

:::caution[R66 — Docker userns-remap]
Casse les bind-mounts hôte-vers-conteneur (décalage d'UID). Migration des volumes
existants requise avant activation.
:::

* **enable** `bool` Active le durcissement ANSSI des services systemd (R62–R66).
* **rootServicesAllowed** `listOf str` Services systemd autorisés à tourner en root sans CapabilityBoundingSet (R64).
* **hardenedUnits** `listOf str` Unités systemd sur lesquelles la baseline de durcissement ANSSI est appliquée
  (R52 RuntimeDirectoryMode, R55 PrivateTmp, R63 sandbox complet via
  `dnfLib.mkHardenedServiceConfig`). Vide par défaut : un sandboxing
  général peut casser des services qui ont besoin d'accès en écriture ou de
  syscalls supplémentaires, donc les unités sont opt-in. Lister les unités
  propres au framework connues pour tolérer le confinement ; les overrides
  `serviceConfig` par unité gagnent toujours.

```nix
darkone.security.services = {
  enable = false;
  rootServicesAllowed = [ ];
  hardenedUnits = [ ];
};
```

### &#x1F511; darkone.security.sudo

Durcissement de sudo (R38–R44). (wip)

Couvre le groupe sudo dédié (R38), les directives sudo renforcées (R39),
la restriction des cibles non-root (R40), la limitation NOEXEC (R41),
l'interdiction des négations (R42), la spécification explicite des arguments
(R43), et l'utilisation de sudoedit (R44).

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) sont activées selon le niveau, la catégorie et les
exclusions définis dans `darkone.system.security` (via `isActive`).
:::

:::caution[R39 — `noexec` et `requiretty` supprimés]
Les deux sont incompatibles avec un déploiement piloté par agent : colmena
escalade avec `sudo -H --` via SSH (pas de PTY, donc `requiretty` refuse), et
`switch-to-configuration` engendre des processus fils (donc `noexec` le bloque).
La traçabilité repose sur `use_pty` + `log_input`/`log_output` à la place.
:::

:::caution[R39 — rootpw]
`rootpw` force un mot de passe root partagé entre les administrateurs.
Préférer `targetpw` ou `runaspw` selon la politique d'équipe.
:::

* **enable** `bool` Activer le durcissement ANSSI de sudo (R38–R44).
* **allowedRootRules** `listOf str` Règles sudo autorisées à cibler root (R40). Les autres doivent cibler un compte de service.

```nix
darkone.security.sudo = {
  enable = false;
  allowedRootRules = [ ];
};
```

### &#x1F511; darkone.security.users

Comptes utilisateurs et authentification (R30–R36). (wip)

Couvre les comptes inutilisés (R30), la politique de mots de passe (R31),
le verrouillage par inactivité (R32), la redevabilité des administrateurs
(R33), les comptes de service (R34), les comptes de service uniques (R35),
et le umask (R36).

:::caution[Activation]
L'option `enable` suit `darkone.system.security.enable` par défaut.
Les règles (Rxx/Cxx) s'activent selon le niveau, la catégorie et les
exclusions définis dans `darkone.system.security` (via `isActive`).
:::

:::caution[R30 — mutableUsers=false]
NixOS n'autorise plus les modifications ad hoc via `passwd`/`useradd`. Tout
changement de compte nécessite un déploiement NixOS complet (`colmena apply`).
:::

:::caution[R36 — umask 0077]
Casse la collaboration en groupe (`/srv/share`). Documenter que
`chmod g+rwx <file>` est requis pour le partage en groupe.
:::

* **enable** `bool` Activer la gestion ANSSI des comptes (R30–R36).
* **idleTimeout** `ints.unsigned` Secondes avant qu'un shell de connexion inactif ne se ferme (R32,
  `TMOUT`). `0` supprime entièrement le délai TTY ; le verrouillage
  d'inactivité GNOME n'est pas affecté. Les postes de travail conservant
  des terminaux à longue durée (ferme de build, outils d'agent) définissent `0`.

```nix
darkone.security.users = {
  enable = false;
  idleTimeout = 600;
};
```
