### &#x1F3E0; darkone.home.advanced

Profil `home` pour les utilisateurs avancés (informaticiens, développeurs, administrateurs).

:::note[Clés SSH depuis Vaultwarden]
`enableVaultwardenSsh` transforme `rbw` en agent SSH : les clés privées restent dans
le coffre de l'utilisateur (chiffrées de bout en bout), jamais en clair sur le disque ni dans sops.
L'utilisateur exécute `rbw unlock` une fois par session.
:::

* **enable** `bool` Activer les fonctionnalités pour utilisateurs avancés
* **enableTools** `bool` Divers outils pour utilisateurs avancés
* **enablePhoneTools** `bool` Outils pour smartphone (scrcpy)
* **enableAdmin** `bool` Activer les fonctionnalités d'administration (réseau, outils système)
* **enableNixAdmin** `bool` Activer les fonctionnalités d'administration Nix
* **enableDnfDeveloper** `bool` Activer tous les outils pour un développeur Codev DNF
* **enableDeveloper** `bool` Activer les outils pour développeur
* **enableVscode** `bool` VS Code. Opt-in : ~0,3 GiB à télécharger, Zed est l'éditeur par défaut
* **enableSlidev** `bool` Présentations Slidev (`slidev-cli`, plus son extension VS Code si
  `enableVscode`). Opt-in : ~0,4 GiB à télécharger
* **enableEssentials** `bool` Outils fréquemment utilisés
* **enableVaultwardenSsh** `bool` Agent SSH s'appuyant sur le coffre Vaultwarden de l'utilisateur (rbw). À ne pas activer sur
  un hôte atteint via `ssh -A` : l'agent local masquerait celui transmis

```nix
darkone.home.advanced = {
  enable = false;
  enableTools = false;
  enablePhoneTools = false;
  enableAdmin = false;
  enableNixAdmin = false;
  enableDnfDeveloper = false;
  enableDeveloper = true;
  enableVscode = false;
  enableSlidev = false;
  enableEssentials = true;
  enableVaultwardenSsh = false;
};
```

### &#x1F3E0; darkone.home.ai

Outils de codage IA et utilitaires associés.

:::note[Drapeaux]
- `darkone.home.ai.enable` : paquets utilitaires (aichat, llm, fabric-ai, gh,
  lazygit, direnv, outils Rust et qualité de code) et les drapeaux d'agent ci-dessous.
- `darkone.home.ai.enable{Claude,OpenCode,Codex,Antigravity,Aider,Goose}` :
  un agent de codage IA chacun.
- `darkone.home.ai.preferLocal` : OpenCode utilise par défaut le modèle ollama
  local sur un hôte `darkone.service.ai`.
:::

:::tip[Câblage par hôte]
Sur un hôte ollama local (`darkone.service.ai`) : `gollama` et la CLI
`ollama`, et Aider revient au modèle local quand Claude est désactivé.

La CLI GitHub (`gh`) et la CLI Copilot (`copilot`) sont installées. Claude Code
applique une matrice de permissions autoriser/demander/refuser et un hook de
gouvernance RTK sur les appels Bash.
:::

:::caution[settings.json modifiable]
Claude Code et Antigravity CLI réécrivent leur propre `settings.json` : un
lien symbolique en lecture seule les casse, et fait échouer le prochain switch
sur le `.bkp`. Le socle Nix est fusionné par jq dans un fichier MODIFIABLE à
chaque switch à la place ; les clés d'exécution (plugins, espaces de travail
de confiance) sont préservées.
:::

* **enable** `bool` Activer les outils IA et les utilitaires associés
* **enableClaude** `bool` CLI Claude Code
* **enableOpenCode** `bool` Agent IA terminal OpenCode
* **enableCodex** `bool` CLI OpenAI Codex
* **enableAntigravity** `bool` CLI Google Antigravity
* **enableAider** `bool` Programmation en binôme IA avec Aider
* **enableGoose** `bool` Agent de codage IA Goose (Block Inc.)
* **preferLocal** `bool` Préférer les modèles locaux plutôt que cloud

```nix
darkone.home.ai = {
  enable = false;
  enableClaude = false;
  enableOpenCode = false;
  enableCodex = false;
  enableAntigravity = false;
  enableAider = false;
  enableGoose = false;
  preferLocal = false;
};
```

### &#x1F3E0; darkone.home.audio

Outils et effets audio.

Installe l'encodeur MP3 (`lame`) et, avec GNOME, un lecteur audio
(`vlc`), puis ajoute les éditeurs et effets (`audacity`, `easyeffects`) quand
`enableTools` est défini. La réduction de bruit en temps réel (`noisetorch`) est
volontairement désactivée car elle requiert PulseAudio.

* **enableTools** `bool` Outils / éditeurs audio (audacity, easyeffects)

```nix
darkone.home.audio = {
  enable = false;
  enableTools = false;
};
```

### &#x1F3E0; darkone.home.gnome

Réglages GNOME pour home-manager.

Masque les lanceurs : le simple `xterm`, les paramètres Qt5/Qt6 et le manuel
NixOS pour tous les profils, `scrcpy` et `scrcpy-console` s'ils sont installés,
Extensions pour les profils non techniques, et (`hideTechnicalIcons`)
Paramètres, Imprimantes et File Roller pour les profils débutant / enfant.

connexion qui suit un changement de mot de passe administrateur (lu par le
module gnome de NixOS).

:::caution[Signets NFS]
Ne pas déclarer `gtk.gtk3.bookmarks` depuis ce module — tant que les partages
home NFS sont actifs, `home/profiles/minimal/nfs.nix` détient ce fichier et
l'écrase.
:::

* **enable** `bool` Activer les réglages gnome pour home manager
* **hideTechnicalIcons** `bool` Masquer certaines icônes pour débutants / enfants / bébés
* **keepKeyring** `bool` Conserver le trousseau de connexion quand l'administrateur change le mot de passe de session (trousseau avec un mot de passe propre)

```nix
darkone.home.gnome = {
  enable = false;
  hideTechnicalIcons = false;
  keepKeyring = false;
};
```

### &#x1F3E0; darkone.home.music

Applications graphiques de création musicale et sonore.

Classées par public : `enablePro` (ardour, reaper, renoise,
rosegarden), `enableCreator` (decibels, hydrogen), `enableScore`
(musescore, muse-sounds-manager), `enableFun` (mixxx, mousai),
`enableCli` (mpg123, cmus, lilypond), `enableEasy` (gnome-music vs.
audacious, GNOME uniquement), `enableMpd` (daemon MPD, ncmpcpp, mpd-mpris), et
`enableDev` (lilypond).

:::note[Bibliothèque musicale NFS-aware]
Quand l'hôte est un client NFS et que le réseau expose un service `nfs`
dans la même zone, MPD lit son répertoire musical depuis le montage NFS
(`/mnt/nfs/homes/$USER/Music`). Sinon il revient à la valeur locale
`srv-dirs.homes`, puis à `~/Music`.
:::

* **enable** `bool` Module home de création musicale
* **enablePro** `bool` Outils professionnels exigeants (rose, ardour...)
* **enableFun** `bool` Outils audio ludiques (mixxx...)
* **enableCli** `bool` Outils audio en ligne de commande (mpg123, cmus, moc...)
* **enableDev** `bool` Logiciels audio pour développeurs (lilypond...)
* **enableMpd** `bool` Daemon MPD et lecteurs (mpd, ncmpcpp...)
* **enableEasy** `bool` Outils simples plutôt qu'efficaces (gnome-music vs audacious...)
* **enableScore** `bool` Logiciels de notation (musescore...)
* **enableCreator** `bool` Outils de création pour débutants (lmms, hydrogen...)

```nix
darkone.home.music = {
  enable = false;
  enablePro = false;
  enableFun = false;
  enableCli = false;
  enableDev = false;
  enableMpd = false;
  enableEasy = false;
  enableScore = false;
  enableCreator = false;
};
```

### &#x1F3E0; darkone.home.office

Bureau de travail : navigateurs, suite bureautique, communication, cloud et outils PDF.

Les paquets sont filtrés selon le public (`enableEssentials`, `enableOffice`,
`enableTools`, `enableCommunication`...). Sous-modules (`office/`) :

- `browsers.nix` : Firefox ESR (LibreWolf, Chromium) avec des politiques partagées :
  page d'accueil et locale de la zone, protection contre le suivi, Bitwarden épinglé lorsque
  le réseau exécute Vaultwarden.
- `cartable-fantastique.nix` : barre d'outils Cartable Fantastique dans LibreOffice
  (`cartableFantastique`, par défaut pour le profil `child`).
- `matrix.nix` : Element Desktop dès que le réseau exécute Matrix,
  préconfiguré (SSO Kanidm) ; Fractal avec `enableCommunication`.
- `nextcloud.nix` : client de bureau lié à l'instance du réseau, et
  `nextcloud-webdav-login` pour les Comptes en ligne GNOME.
- `pandoc.nix` : `md2pdf` et les paramètres par défaut de pandoc (`enablePandoc`).

* **enable** `bool` Paquets utiles par défaut
* **enableMore** `bool` Plus de paquets alternatifs
* **enableUnsafeFeatures** `bool` Fonctionnalités pour utilisateurs avancés non-enfants
* **enableUBlock** `bool` Activer l'extension uBlock
* **enableTools** `bool` Petits outils (GNOME) (iotas, dialect, etc.)
* **enableProductivity** `bool` Applications de productivité (obsidian, gestion du temps, projets, etc.)
* **enableCommunication** `bool` Outils de communication
* **enableOffice** `bool` Paquets bureautiques (libreoffice, hunspell, polices...)
* **enableFirefox** `bool` Activer Firefox
* **enableLibreWolf** `bool` Activer LibreWolf (alternative à Firefox)
* **enableChromium** `bool` Activer Chromium
* **enableBrave** `bool` Activer Brave Browser
* **enableEmail** `bool` Paquets de gestion de courriel (thunderbird)
* **enableSecurity** `bool` Outils de sécurité (keepass)
* **enableCalendarContacts** `bool` Calendrier, contacts, tâches et applications associées
* **enablePandoc** `bool` Chaîne d'outils Markdown vers PDF : pandoc, typst, polices Gentium et DejaVu,
  et la commande `md2pdf` (corps Gentium, A4, langue de la zone).

  ```sh
  md2pdf notes.md              # A4, 10pt -&gt; notes.pdf
  md2pdf --big notes.md        # A4, 12pt
  md2pdf --tablet notes.md     # A6, 9pt (11pt avec --big), agrandi pour tablette
  md2pdf -e context notes.md   # Moteur ConTeXt (enablePandocContext)
  ```

  Le moteur est typst. Il rend le code TeX brut habituel dans les notes (`\pagebreak`,
  `\placecontent`, `\centerline`...) et signale tout autre code. Les colonnes de tableau
  s'adaptent à leur contenu, sauf si les tirets des séparateurs diffèrent en
  longueur (`|--|--------|`) : les largeurs suivent alors ces tirets. Un simple
  `pandoc notes.md -o notes.pdf` utilise le même moteur, la même langue et les mêmes polices.
  Sous GNOME, les trois mises en page sont également proposées par clic droit dans
  Nautilus (menu Scripts).
* **enablePandocContext** `bool` ConTeXt comme moteur PDF alternatif, `md2pdf -e context` (~900 MiB, nécessite enablePandoc)
* **pandocAuthor** `nullOr str` Créateur inscrit dans les PDFs générés par `md2pdf`. `null` utilise le nom complet du compte.
* **enableEssentials** `bool` Outils essentiels
* **hunspellLang** `str` [Dictionnaire Hunspell](https://mynixos.com/nixpkgs/packages/hunspellDicts)
* **cartableFantastique** `nullOr ( enum [ "primaire" "college" "adaptateur" ] )` Édition de la barre d'outils [Cartable Fantastique](https://www.cartablefantastique.fr/outils-pour-compenser/le-plug-in-libre-office/)
  installée dans LibreOffice, à destination des élèves dyspraxiques ou atteints d'autres troubles DYS.
  `null` n'installe rien.

  - `primaire` : barres Lire, Écrire, Mathématiques et Tableau.
  - `college` : ajoute les langues, la chimie, l'électricité et l'éditeur d'équations.
  - `adaptateur` : ajoute des outils pour l'adulte adaptant le matériel scolaire.

  Installée par compte, dans son profil LibreOffice, lors de l'activation de Home Manager.
  Nécessite `enableOffice`. La synthèse vocale passe par `spd-say` (speech-dispatcher, activé par défaut
  sur les bureaux NixOS).

  :::caution[Pas de suppression automatique]
  En repassant à `null`, l'extension reste installée : supprimez-la depuis *Outils → Gestionnaire d'extensions*.
  :::
* **enableElementAutoStart** `bool` Démarrage automatique d'Element Desktop (masqué) à la connexion lorsque le réseau exécute Matrix
* **enableFractalAutoStart** `bool` Démarrage automatique de Fractal à la connexion, avec `enableCommunication` (opt-in : pas de mode arrière-plan, sa fenêtre s'ouvre)
* **nextcloud.enable** `bool` Installer le client de bureau Nextcloud, prélié à l'instance du réseau
* **nextcloud.server** `nullOr str` Instance Nextcloud à laquelle le client se lie. `null` sélectionne celle déclarée
  sur le réseau (cette zone en priorité). Définissez-la pour cibler une instance locale ou externe.
* **nextcloud.enableAutoStart** `bool` Démarrer le client Nextcloud en arrière-plan à la connexion
* **nextcloud.enableWebdav** `bool` Fournir `nextcloud-webdav-login`, un assistant ponctuel qui s'authentifie
  via le navigateur (SSO Kanidm) et enregistre le résultat comme un Compte en ligne GNOME :
  fichiers via WebDAV dans le gestionnaire de fichiers, ainsi que calendrier
  et contacts dans Evolution. Nécessaire car Nextcloud refuse de créer
  un mot de passe d'application depuis son interface web pour un utilisateur OIDC.

  L'assistant affiche également le mot de passe d'application, afin que tout autre client WebDAV
  puisse l'utiliser avec ce compte.

  :::note[Uniquement GNOME]
  Le compte est écrit à l'emplacement lu par les Comptes en ligne GNOME, que
  `darkone.graphic.gnome` active de lui-même dès que le réseau
  propose un cloud. Sur un autre bureau, le mot de passe affiché reste utilisable.
  :::

  Ignoré si `darkone.home.office.nextcloud.enable` est désactivé.
* **nextcloud.syncDir** `nullOr str` Dossier local prérempli dans l'assistant de configuration, relatif à `$HOME`.

  :::caution[Pas de synchronisation par défaut]
  Laisser à `null` intentionnellement. L'assistant s'arrête alors sur la page du dossier et
  l'utilisateur décide de ce qu'il veut synchroniser, le cas échéant. Le définir ignore
  cette page.
  :::
* **shared** `raw` Valeurs bureautiques partagées avec les sous-modules `office/`.

```nix
darkone.home.office = {
  enable = false;
  enableMore = false;
  enableUnsafeFeatures = false;
  enableUBlock = false;
  enableTools = false;
  enableProductivity = false;
  enableCommunication = false;
  enableOffice = false;
  enableFirefox = false;
  enableLibreWolf = false;
  enableChromium = false;
  enableBrave = false;
  enableEmail = false;
  enableSecurity = false;
  enableCalendarContacts = false;
  enablePandoc = false;
  enablePandocContext = false;
  pandocAuthor = "Jane Doe";
  enableEssentials = true;
  hunspellLang = "en-us";
  cartableFantastique = "primaire";
  enableElementAutoStart = true;
  enableFractalAutoStart = false;
  nextcloud.enable = detectedNextcloud != null;
  nextcloud.server = "https://cloud.example.com";
  nextcloud.enableAutoStart = true;
  nextcloud.enableWebdav = true;
  nextcloud.syncDir = "Nextcloud";
  shared = {
        inherit
          lang
          country
          hasHomepage
          homeUrl
          hasMatrix
          hasVaultwarden
          nextcloudUrl
          hasNextcloud
          hasNextcloudWebdav
          ;
      };
};
```

### &#x1F3E0; darkone.home.umi

Saisie multimodale unifiée (UMI)

Écran tactile + voix + regard (autodémarrage de Talon + Onboard).

:::note[Dépendance de session à l'hôte]
- **Hôte `darkone.host.umi`** : session Cinnamon X11 (udev, uinput, Talon fourni par l'hôte).
  Talon et un clavier Onboard ancré (prédiction de mots, modificateurs persistants) démarrent avec la session,
  le clavier étant masqué jusqu'à ce qu'il soit sollicité. Le tableau de bord, les icônes et le texte
  sont agrandis pour faciliter le ciblage par le regard (`panelHeight`, `textScaling`).
  Tableau de bord DNF (`enablePanel`) : lanceurs | fenêtres ouvertes, puis types de clic au survol,
  zone de pause, commutateur de regard (applet `umi-mouse`), menu d'accessibilité, bascule Onboard.
  Les favoris du menu (`menuFavorites`) s'ouvrent avec l'étalonnage du suivi oculaire.
  Les fenêtres d'application s'ouvrent en mode maximisé, le tableau de bord restant à portée (`enableMaximize`).
- **Tout autre hôte** : GNOME Wayland avec son accessibilité native : clavier virtuel, gros pointeur et texte agrandi.
  Talon et Onboard, réservés à X11, restent désactivés.

Clic au maintien (dwell click) : opt-in (`enableDwell`) sous GNOME. Sous Cinnamon, un script utilisateur Talon
le fait suivre le suivi oculaire, avec contrôle du regard (`enableTrackerAuto`).
Talon 0.4 et 1.0 pris en charge ; le mode « Always On » de la 1.0 est désactivé, le suiveur
s'éteint avec le contrôle du regard.
:::

:::note[Grille d'applications (hôte UMI)]
`enableRofiMenu` : le premier lanceur du tableau de bord ouvre une grille rofi plein écran,
pages de tuiles `rofiGridResolution` tournées par des boutons en bordure, un clic lance
l'application, les panneaux de paramètres sont exclus. `hiddenApps` masque les entrées de la grille
et du menu Cinnamon. rofi capte le pointeur : le tableau de bord est hors de portée.
:::

:::note[SuperTuxKart uniquement à la souris (hôte UMI)]
`enableStkWithMouse` : le lanceur du jeu exécute `dnf-stk-mouse`, qui transforme
toute souris physique en touches par défaut de STK tant que la fenêtre du jeu a le focus.
Stick avant/arrière : accélérer/freiner, latéral : virer ; clic gauche : dérapage,
double-clic : tir, clic droit : nitro. Le pointeur reste inchangé (menus).
:::

:::note[Positions du regard, la tête affine (Talon 1.0)]
Valeurs par défaut mesurées sur un Tobii 5 : filtre de regard Talon (`gazeFilterSpeed`),
filtre plus rapide du curseur (`cursorFilterSpeed`), contrôle de la tête activé avec une tête
sensible (`headSpeed` 5, `head_bezier.vmax` mis à l'échelle). Les modes du menu Eye Tracking
sont déclarés (`enableGazeControl`, `enableHeadControl`, `enableHeadJump`,
`enableMouseJump`, `enableGazeFocus`) et réappliqués à chaque démarrage de Talon.
:::

:::tip[Réglage à chaud]
Depuis la REPL de Talon (perdu au redémarrage) : `actions.user.umi_head_speed(5)`,
`actions.user.umi_filter_speed(1, 4)`, `print(actions.user.umi_tuning())`.
:::

:::tip[Scripts communautaires]
Définir `communityScripts` vers un arbre github:talonhub/community récupéré permet d'obtenir
déclarativement le contrôle vocal et le contrôle du curseur par le regard (zoom mouse, pop click).
:::

:::note[Double schéma de configuration]
Les paramètres s'écrivent dans deux familles : `org/cinnamon/*` pour la session hôte UMI,
`org/gnome/*` pour les sessions GNOME ailleurs. Sous Cinnamon, csd synchronise
les touches souris d'accessibilité dans les deux sens entre les deux familles.
Exception : les clés verrouillées par le module GNOME DNF ne sont jamais écrites ici ;
l'écriture d'une clé verrouillée annule l'ensemble du `dconf load` de Home Manager.
Le verrouillage de l'écran reste activé côté GNOME (verrouillé par le module GNOME DNF) ;
`idle-delay = 0` évite de le déclencher, et la session Cinnamon a son propre verrouillage
totalement désactivé.
:::

:::caution[Trousseau de connexion de l'utilisateur en autologin : sans mot de passe, sur tous les hôtes]
Une session en autologin ne saisit aucun mot de passe : un trousseau scellé par un mot de passe
provoque une invite gcr que l'utilisateur UMI ne peut pas répondre. Son trousseau de connexion
est initialisé avec un mot de passe vide (ini brut, déverrouillé sans invite) ; un trousseau scellé
est supprimé à chaque activation, `user.keystore` inclus, et ses secrets sont perdus.

- Au repos, LUKS le protège ; l'autologin donne déjà la session à quiconque démarre la machine.
- L'hôte UMI éloigne tout mot de passe de gnome-keyring pour cet utilisateur :
  un trousseau brut déverrouillé par un mot de passe est rechiffré avec celui-ci
  à la prochaine écriture (`pam_gdm` et la phrase de passe de démarrage incluses).
- Les autres utilisateurs, et toute connexion par mot de passe ailleurs : inchangés.
:::

* **enable** `bool` Configuration UMI de saisie multimodale (Talon + Onboard)
* **enableTalonAutostart** `bool` Démarrer Talon à la connexion de session, une fois le tableau de bord initialisé (talon doit être dans le PATH).
* **communityScripts** `nullOr package` Arbre talonhub/community déployé dans ~/.talon/user/community.
* **enableDwell** `bool` Clic au maintien : clic en maintenant le pointeur immobile. Désactivé par défaut — uniquement utilisable
  avec un suivi oculaire, et avec une souris il se déclenche sur l'emplacement laissé
  (typiquement le menu d'accessibilité basculant le zoom ou le clavier virtuel)
* **dwellTime** `float` Délai du clic au maintien en secondes.
* **enableTrackerAuto** `bool` Suivi oculaire branché : contrôle du curseur par le regard Talon et clic au survol activés ;
  débranché : clic au survol désactivé (session Cinnamon). Prend le dessus sur
  `enableDwell` sous Cinnamon.
* **gazeFilterSpeed** `nullOr numbers.positive` Coefficient de filtre de regard Talon (par œil), avec
  `enableTrackerAuto` : plus haut = plus réactif et moins lissé. Par défaut :
  celui de Talon, la tête affine les derniers millimètres ; `null` conserve
  la valeur de Talon.
* **cursorFilterSpeed** `nullOr numbers.positive` Coefficient de filtre du curseur Talon, avec
  `enableTrackerAuto` : plus haut = plus réactif, plus de dépassement. `null`
  conserve la valeur de Talon (2,0).
* **headSpeed** `nullOr numbers.positive` Sensibilité du contrôle de la tête Talon, avec `enableTrackerAuto` et
  `enableHeadControl` : au-dessus de 1, un léger mouvement de tête déplace le curseur,
  en dessous de 1, les mouvements amples ou mal contrôlés sont amortis. `null`
  conserve la valeur de Talon (1).
* **enableGazeControl** `bool` Contrôle du regard Talon, avec `enableTrackerAuto` : le curseur suit le regard.
* **enableHeadControl** `bool` Contrôle de la tête Talon, avec `enableTrackerAuto` : les mouvements de tête affinent
  le curseur placé par le regard (`headSpeed`). À désactiver si la tête est instable,
  car cela éloigne le curseur du point de regard.
* **enableHeadJump** `bool` Saut de tête Talon, avec `enableTrackerAuto` : un mouvement de tête amène
  le curseur au point de regard
* **enableMouseJump** `bool` Saut de souris Talon, avec `enableTrackerAuto` : déplacer une souris physique
  vers le point de regard y amène le curseur. Désactivé par défaut, cela déplace
  brutalement le pointeur d'un aidant
* **enableGazeFocus** `bool` Focus par le regard Talon (expérimental), avec `enableTrackerAuto` : la fenêtre
  regardée obtient le focus
* **panelHeight** `ints.between 40 96` Hauteur du tableau de bord Cinnamon en pixels, ses icônes suivent (cibles pour le regard).
* **textScaling** `float` Facteur de mise à l'échelle du texte de la session Cinnamon (les boutons grandissent avec leurs libellés).
* **enablePanel** `bool` Tableau de bord Cinnamon géré par DNF : lanceurs et fenêtres ouvertes séparés,
  contrôles de clic au survol (types de clic, zone de pause), menu d'accessibilité,
  bascule clavier ; pas d'icône Bluetooth ni de barre d'angle. Réécrit à
  chaque activation.
* **enableMaximize** `bool` Les fenêtres d'application s'ouvrent en mode maximisé (extension Cinnamon), le tableau de bord
  reste à portée. Les boîtes de dialogue, Onboard et les fenêtres à taille fixe conservent
  leur taille.
* **panelLaunchers** `listOf str` Lanceurs du tableau de bord (identifiants de fichiers .desktop), avec `enablePanel`.
* **menuFavorites** `listOf str` Favoris du menu Cinnamon (identifiants de fichiers .desktop), réécrits à chaque
  activation. `dnf-umi-calibrate.desktop`, avec `enableTrackerAuto`,
  lance l'étalonnage du suivi oculaire.
* **enableRofiMenu** `bool` Grille d'applications plein écran (rofi), hôte UMI uniquement : pages de grandes
  tuiles tournées par des boutons en bordure, un clic lance l'application, les panneaux
  de paramètres sont exclus. Ouverte par le premier lanceur du tableau de bord (avec `enablePanel`).
* **rofiGridResolution** `submodule` Grille d'applications par page, en tuiles, avec `enableRofiMenu`. La valeur
  par défaut 6 × 4 correspond à des icônes de 96 px sur un écran 1600×900 ; moins de tuiles
  les agrandit.
  * **columns** `ints.between 1 12` Tuiles par ligne.
  * **rows** `ints.between 1 8` Lignes de tuiles par page.
* **hiddenApps** `listOf str` Applications masquées de la grille et du menu Cinnamon (identifiants de fichiers .desktop),
  hôte UMI uniquement. Les lancements par identifiant et les associations de fichiers restent fonctionnels.
* **enableStkWithMouse** `bool` SuperTuxKart piloté uniquement à la souris, hôte UMI uniquement : le stick (ou
  les mouvements de souris) accélère, freine et vire, clic gauche dérape, double-clic
  tire, clic droit utilise le nitro. Installe le jeu, son lanceur
  exécute le convertisseur

```nix
darkone.home.umi = {
  enable = false;
  enableTalonAutostart = true;
  communityScripts = null;
  enableDwell = false;
  dwellTime = 1.6;
  enableTrackerAuto = true;
  gazeFilterSpeed = 1.0;
  cursorFilterSpeed = 4.0;
  headSpeed = 0.3;
  enableGazeControl = true;
  enableHeadControl = true;
  enableHeadJump = false;
  enableMouseJump = false;
  enableGazeFocus = false;
  panelHeight = 64;
  textScaling = 1.5;
  enablePanel = true;
  enableMaximize = true;
  panelLaunchers = [ ];
  menuFavorites = [ ];
  enableRofiMenu = true;
  rofiGridResolution.columns = 6;
  rofiGridResolution.rows = 4;
  hiddenApps = [ ];
  enableStkWithMouse = false;
};
```

### &#x1F3E0; darkone.home.video

Outils et applications vidéo.

Installe toujours le lecteur par défaut (`celluloid`, interface GTK4/libadwaita
sur mpv) et contrôle le reste par public : `enableTools` (ffmpeg, mlt, vlc,
video-trimmer, parabolic), `enableEditing` (kdenlive, shotcut),
`enableCreator` (OBS Studio avec `obs-backgroundremoval`, `obs-vkcapture`,
etc.), `enableUnfree` (davinci-resolve) et `enableAlternative` (mpv).

:::caution[Pas GNOME Showtime]
Showtime 50 plante en interbloqué sur certains fichiers — `get_state(CLOCK_TIME_NONE)` sur le
fil principal, [GNOME/showtime#299](https://gitlab.gnome.org/GNOME/showtime/-/work_items/299).
Le processus bloqué conserve le nom D-Bus `org.gnome.Showtime`, si bien que
chaque lancement ultérieur est activé sur lui et ne fait silencieusement rien :
ni fenêtre, ni journal.
Non corrigé en amont en 50.0.
:::

* **enable** `bool` Module home de création et d'outils vidéo
* **enableTools** `bool` Outils vidéo pour professionnels
* **enableEditing** `bool` Outils de montage vidéo (kdenlive...)
* **enableCreator** `bool` Outils de création vidéo (obs...)
* **enableUnfree** `bool` Apps vidéo non libres (davinci...)
* **enableAlternative** `bool` Apps vidéo alternatives (mpv...)

```nix
darkone.home.video = {
  enable = false;
  enableTools = false;
  enableEditing = false;
  enableCreator = false;
  enableUnfree = false;
  enableAlternative = false;
};
```
