### &#x1F3E0; darkone.home.advanced

Profil d'accueil pour les utilisateurs avancés (informaticiens, développeurs, administrateurs).

:::note[Clés SSH depuis Vaultwarden]
`enableVaultwardenSsh` transforme `rbw` en agent SSH : les clés privées restent
dans le coffre de l'utilisateur (chiffrement de bout en bout), jamais en clair
sur disque ni dans sops. L'utilisateur lance `rbw unlock` une fois par session.
:::

* **enable** `bool` Activer les fonctionnalités utilisateur avancées
* **enableTools** `bool` Outils variés pour les utilisateurs avancés
* **enablePhoneTools** `bool` Outils pour smartphone (scrcpy)
* **enableAdmin** `bool` Activer les fonctionnalités administrateur (réseau, outils système)
* **enableNixAdmin** `bool` Activer les fonctionnalités d'administration nix
* **enableDnfDeveloper** `bool` Activer tous les outils pour DNF Codev Developer
* **enableDeveloper** `bool` Activer les outils développeur
* **enableEssentials** `bool` Outils fréquemment utilisés
* **enableVaultwardenSsh** `bool` Agent SSH adossé au coffre Vaultwarden de l'utilisateur (rbw). Ne pas activer sur
  un hôte joint via `ssh -A` : l'agent local masquerait celui relayé

```nix
darkone.home.advanced = {
  enable = false;
  enableTools = false;
  enablePhoneTools = false;
  enableAdmin = false;
  enableNixAdmin = false;
  enableDnfDeveloper = false;
  enableDeveloper = true;
  enableEssentials = true;
  enableVaultwardenSsh = false;
};
```

### &#x1F3E0; darkone.home.ai

Outils d'IA de codage et utilitaires de support.

:::note[Flags]
- `darkone.home.ai.enable` interrupteur principal qui installe les paquets
  utilitaires (aichat, llm, fabric-ai, gh, lazygit, direnv, outils de
  qualité de code, etc.) et active le système de flags par agent ci-dessous.
- `darkone.home.ai.enable{Claude,OpenCode,Codex,Aider,Goose}` installe et
  configure chacun un agent d'IA de codage spécifique.
- `darkone.home.ai.preferLocal` combiné à un hôte `darkone.service.ai` local
  ollama, les agents utilisent par défaut le modèle local au lieu des APIs cloud.
:::

:::tip[Câblage par hôte]
Ce module lit `osConfig.darkone.service.ai.enable` pour détecter un
hôte ollama local. Sur ces hôtes, `gollama`, le CLI `ollama`, et les
modèles locaux par défaut pour Aider / OpenCode sont activés automatiquement.

`programs.gh` est activé avec l'extension `github-copilot-cli`.
OpenCode obtient deux serveurs MCP (filesystem, fetch) via `npx -y`.
Claude Code applique une matrice de permissions allow/ask/deny et un
hook de gouvernance RTK sur les appels Bash.
:::

:::caution[settings.json inscriptible]
Claude Code et Antigravity CLI réécrivent leur propre `settings.json` :
un magasin en lecture seule en symlink les casse, et fait échouer le
prochain switch sur le `.bkp`. Le socle Nix est fusionné par jq dans un
fichier INSCRIPTIBLE à chaque switch ; les clés d'exécution (plugins,
espaces de travail de confiance) sont préservées.
:::

* **enable** `bool` Activer les outils d'IA et les utilitaires de support
* **enableClaude** `bool` CLI Claude Code
* **enableOpenCode** `bool` Agent d'IA terminal OpenCode
* **enableCodex** `bool` CLI OpenAI Codex
* **enableAntigravity** `bool` CLI Google Antigravity
* **enableAider** `bool` Programmation en binôme avec Aider AI
* **enableGoose** `bool` Agent de codage IA Goose (Block Inc.)
* **preferLocal** `bool` Préférer les modèles locaux plutôt que ceux du cloud

```nix
darkone.home.ai = {
  enable = false;
  enableClaude = false;
  enableOpenCode = false;
  enableCodex = false;
  enableAntigravity = false;
  enableAider = false;
  enableGoose = false;
  preferLocal = false;
};
```

```nix

  enable = false;
  enableTools = false;
};
```

### &#x1F3E0; darkone.home.gnome

Réglages Gnome pour home-manager.

Masque sans condition les lanceurs `xterm` nu, les réglages Qt5/Qt6 et le
manuel NixOS, les Extensions pour les profils non techniques, enregistre des
entrées `.desktop` soignées pour `scrcpy` et `scrcpy-console` quand le paquet
fait partie des `home.packages` de l'utilisateur, et (quand `hideTechnicalIcons`
est défini) masque les icônes Paramètres, Imprimantes et File Roller pour les
profils débutant / enfant.

:::caution[Signets NFS]
Ne pas déclarer `gtk.gtk3.bookmarks` depuis ce module : tant que les partages
NFS du home sont actifs, `home/profiles/minimal/nfs.nix` possède ce fichier
et l'écrase.
:::

* **enable** `bool` Activer les réglages gnome pour home manager
* **hideTechnicalIcons** `bool` Masquer certaines icônes pour les débutants / enfants / petits

```nix
darkone.home.gnome = {
  enable = false;
  hideTechnicalIcons = false;
};
```

### &#x1F3E0; darkone.home.office

Outils courants pour le poste bureautique.

* **enable** `bool` Paquets utiles par défaut
* **enableMore** `bool` Paquets alternatifs supplémentaires
* **enableUnsafeFeatures** `bool` Fonctions pour les utilisateurs avancés non enfants
* **enableUBlock** `bool` Activer le plugin uBlock
* **enableTools** `bool` Petits outils (GNOME) : iotas, dialect, etc.
* **enableProductivity** `bool` Applications de productivité (Obsidian, gestion du temps, projets, etc.)
* **enableCommunication** `bool` Outils de communication
* **enableOffice** `bool` Paquets bureautiques (LibreOffice, hunspell, polices...)
* **enableFirefox** `bool` Activer Firefox
* **enableLibreWolf** `bool` Activer LibreWolf (alternative à Firefox)
* **enableChromium** `bool` Activer Chromium
* **enableBrave** `bool` Activer le navigateur Brave
* **enableEmail** `bool` Paquets de gestion du courrier (Thunderbird)
* **enableSecurity** `bool` Outils de sécurité (KeePass)
* **enableCalendarContacts** `bool` Agenda, contacts, tâches et applications associées
* **enablePandoc** `bool` Chaîne Markdown vers PDF : pandoc, typst, polices Gentium et DejaVu,
  ainsi que la commande `md2pdf` (corps Gentium, A4, langue de la zone).

  ```sh
  md2pdf notes.md              # A4, 10pt -&gt; notes.pdf
  md2pdf --big notes.md        # A4, 12pt
  md2pdf --tablet notes.md     # A6, 9pt (11pt with --big), zoomed on a tablet
  md2pdf -e context notes.md   # ConTeXt engine (enablePandocContext)
  ```

  Le moteur est typst. Il rend le TeX brut usuel dans les notes (`\pagebreak`,
  `\placecontent`, `\centerline`...) et signale tout le reste. Les colonnes
  de tableau s'ajustent à leur contenu, sauf si les tirets du séparateur
  diffèrent en longueur (`|--|--------|`) : les largeurs suivent alors ces
  tirets. Un simple `pandoc notes.md -o notes.pdf` utilise le même moteur,
  la même langue et les mêmes polices. Sous GNOME, les trois mises en page
  sont aussi proposées au clic droit dans Nautilus (menu Scripts).
* **enablePandocContext** `bool` ConTeXt comme moteur PDF alternatif, `md2pdf -e context` (~900 MiB, nécessite enablePandoc)
* **pandocAuthor** `nullOr str` Créateur inscrit dans les PDF par `md2pdf`. `null` reprend le nom complet du compte.
* **enableEssentials** `bool` Outils essentiels
* **huntspellLang** `str` [Langue Hunspell](https://mynixos.com/nixpkgs/packages/hunspellDicts)
* **enableElementAutoStart** `bool` Démarrer Element Desktop à la connexion si un serveur Matrix local est présent
* **enableFractalAutoStart** `bool` Démarrer Fractal à la connexion si un serveur Matrix local est présent (opt-in, voir les réserves ci-dessous)
* **nextcloud.enable** `bool` Installer le client Nextcloud desktop, pré-lié à l'instance réseau
* **nextcloud.server** `nullOr str` Instance Nextcloud à laquelle le client se lie. `null` choisit celle déclarée
  sur le réseau (cette zone en priorité). À définir pour cibler plutôt une instance
  locale ou externe.
* **nextcloud.enableAutoStart** `bool` Lancer le client Nextcloud en arrière-plan à la connexion
* **nextcloud.enableWebdav** `bool` Installer `nextcloud-webdav-login`, un utilitaire ponctuel qui s'authentifie
  via le navigateur (SSO Kanidm) et enregistre le résultat comme compte GNOME
  Online Account : fichiers en WebDAV dans le gestionnaire de fichiers, plus
  agenda et contacts dans Evolution. Nécessaire car Nextcloud refuse de créer
  un mot de passe d'application depuis son interface web pour un utilisateur OIDC.

  L'utilitaire affiche aussi le mot de passe d'application : tout autre
  client WebDAV peut donc viser le même compte.

  :::note[GNOME uniquement]
  Le compte est écrit là où GNOME Online Accounts le lit, ce que
  `darkone.graphic.gnome` active de lui-même dès que le réseau porte un
  cloud. Sur un autre poste, le mot de passe affiché reste utilisable.
  :::

  Ignoré quand `darkone.home.office.nextcloud.enable` est désactivé.
* **nextcloud.syncDir** `nullOr str` Dossier local pré-rempli dans l'assistant de configuration, relatif à `$HOME`.

  :::caution[Aucune synchronisation par défaut]
  Volontairement laissé `null`. L'assistant s'arrête alors sur sa page de
  dossier et l'utilisateur décide quoi, s'il y a lieu, synchroniser. Le
  définir saute cette page.
  :::

```nix
darkone.home.office = {
  enable = false;
  enableMore = false;
  enableUnsafeFeatures = false;
  enableUBlock = false;
  enableTools = false;
  enableProductivity = false;
  enableCommunication = false;
  enableOffice = false;
  enableFirefox = false;
  enableLibreWolf = false;
  enableChromium = false;
  enableBrave = false;
  enableEmail = false;
  enableSecurity = false;
  enableCalendarContacts = false;
  enablePandoc = false;
  enablePandocContext = false;
  pandocAuthor = "Jane Doe";
  enableEssentials = true;
  huntspellLang = "en-us";
  enableElementAutoStart = true;
  enableFractalAutoStart = false;
  nextcloud.enable = detectedNextcloud != null;
  nextcloud.server = "https://cloud.example.com";
  nextcloud.enableAutoStart = true;
  nextcloud.enableWebdav = true;
  nextcloud.syncDir = "Nextcloud";
};
```

### 🏠 darkone.home.umi

Unified Multimodal Input (UMI)

Écran tactile + voix + regard (démarrage automatique de Talon + Onboard).

:::note[La session dépend de l'hôte]
- **Hôte `darkone.host.umi`** : session Cinnamon X11 (udev, uinput, Talon
  fournis par l'hôte). Talon et un clavier Onboard ancré (prédiction de
  mots, modificateurs persistants) démarrent avec la session.
- **Tout autre hôte** : GNOME Wayland avec son accessibilité native : clavier
  à l'écran, gros pointeur et texte. Talon et Onboard, uniquement X11,
  restent désactivés.

Clic par dwell (`enableDwell`) activable dans les deux cas.
:::

:::tip[Scripts communautaires]
Définissez `communityScripts` sur un arbre github:talonhub/community récupéré
pour obtenir le contrôle vocal complet de la souris et du regard (zoom de la
souris, pop click) de façon déclarative.
:::

:::note[Deux schémas]
Les réglages vont vers les deux familles : org/cinnamon/* pour la session
UMI de l'hôte, org/gnome/* pour les sessions GNOME ailleurs (mousetweaks
les lit aussi). Exception : les clés verrouillées par le module gnome de
DNF ne sont jamais écrites ici, une écriture sur une clé verrouillée
interrompt tout le `dconf load` de home-manager.
Le verrouillage de session reste activé côté GNOME (verrouillé par le module
gnome de DNF) ; `idle-delay = 0` évite de le déclencher, et la session
Cinnamon a le sien entièrement désactivé.
:::

:::caution[Keyring de connexion : utilisateur en autologin uniquement, deux modes selon l'hôte]
Une session en autologin ne saisit aucun mot de passe, PAM n'a donc rien à
transmettre à gnome-keyring et chaque application utilisant un secret affiche
une invite gcr que l'utilisateur UMI ne peut pas répondre. Une connexion par
mot de passe déverrouille le keyring comme d'habitude et n'est pas touchée.
Pour l'utilisateur en autologin, la correction dépend de l'hôte :

- **Hôte non chiffré** : le keyring de connexion est initialisé avec un mot de
  passe vide, que gnome-keyring stocke en clair et déverrouille seul (il
  essaie un mot de passe vide avant de demander). Tout keyring préexistant
  protégé par mot de passe est supprimé : sa phrase secrète est
  impossible à saisir ici, elle ne pourrait donc que produire indéfiniment
  l'invite. L'autologin accorde déjà toute la session à quiconque démarre la
  machine, cela ne coûte donc rien en confidentialité.
- **Hôte chiffré** (`darkone.system.luks.volumes` non vide) : rien n'est
  initialisé. La phrase secrète saisie au démarrage est mise en cache dans
  le keyring du noyau et transmise à gnome-keyring par `pam_gdm`, le
  keyring reste donc chiffré avec elle. C'est le seul mode qui protège les
  secrets au repos.

Piège, hôtes chiffrés uniquement : faire tourner la phrase secrète LUKS
(valeur sops modifiée, `luks-passphrase-sync`) laisse le keyring sur
l'ancienne. GNOME affiche alors « The password you use to log in to your
computer no longer matches that of your login keyring ». Supprimez
`~/.local/share/keyrings/login.keyring` et reconnectez-vous.
:::

* **enable** `bool` Configuration de l'entrée multimodale UMI (Talon + Onboard)
* **enableTalonAutostart** `bool` Démarrer Talon à l'ouverture de session (talon doit être dans le PATH).
* **communityScripts** `nullOr package` Arbre talonhub/community déployé dans ~/.talon/user/community.
* **enableDwell** `bool` Clic par dwell : cliquer en laissant le pointeur au repos. Désactivé par défaut — uniquement
  utilisable avec un tracker oculaire, et à la souris il se déclenche sur ce que
  le pointeur a laissé en dessous (typiquement le menu d'accessibilité
  activant le zoom ou le clavier à l'écran)
* **dwellTime** `float` Délai du clic par dwell en secondes.

```nix
darkone.home.umi = {
  enable = false;
  enableTalonAutostart = true;
  communityScripts = null;
  enableDwell = false;
  dwellTime = 1.2;
};
```

### &#x1F3E0; darkone.home.video

Outils et applications vidéo.

Installe par défaut le lecteur (`celluloid`, interface GTK4/libadwaita au-dessus de mpv)
et conditionne les autres par audience : `enableTools` (ffmpeg, mlt, vlc,
video-trimmer, parabolic), `enableEditing` (kdenlive + shotcut depuis stable
nixpkgs), `enableCreator` (OBS Studio avec `obs-backgroundremoval`,
`obs-vkcapture`, etc.), `enableUnfree` (davinci-resolve depuis stable),
et `enableAlternative` (mpv).

:::caution[Pas GNOME Showtime]
Showtime 50 se bloque sur certains fichiers — `get_state(CLOCK_TIME_NONE)` sur le
thread principal, [GNOME/showtime#299](https://gitlab.gnome.org/GNOME/showtime/-/work_items/299).
Le processus bloqué conserve le nom D-Bus `org.gnome.Showtime`, donc chaque
lancement ultérieur est activé vers celui-ci et ne fait rien silencieusement :
ni fenêtre, ni log.
Non corrigé en amont à la version 50.0.
:::

* **enable** `bool` Module maison de création et d'outils vidéo
* **enableTools** `bool` Outils vidéo pour professionnels
* **enableEditing** `bool` Outils de montage vidéo (kdenlive…)
* **enableCreator** `bool` Outils de création vidéo (obs…)
* **enableUnfree** `bool` Applications vidéo non libres (davinci…)
* **enableAlternative** `bool` Applications vidéo alternatives (mpv…)

```nix
darkone.home.video = {
  enable = false;
  enableTools = false;
  enableEditing = false;
  enableCreator = false;
  enableUnfree = false;
  enableAlternative = false;
};
```
