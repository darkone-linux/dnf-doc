### &#x2699; darkone.system.core

Le module DNF principal.

:::danger[Module requis]
Ce module est activé par défaut (requis par la configuration DNF).
Il est nécessaire au bon fonctionnement de chaque ordinateur NixOS du réseau local.
:::

Met en place&nbsp;:
- systemd-boot et le noyau LTS (dernier mainline via `enableLatestKernel`);
- JetBrains Mono Nerd Font, avec `kmscon` pour le TTY;
- optimisation nightly du store, GC hebdomadaire avec rétention de 30 jours (keep-last-N via
  `gcKeepGenerations` sur les hôtes au disque contraint);
- le pare-feu et SSH à clé uniquement;
- le terminfo `xterm-ghostty` de Ghostty, pour que chaque hôte accepte le terminal;
- la politique de veille (`disableSuspend` pour les serveurs);
- les règles polkit laissant `wheel` arrêter/redémarrer;
- un groupe/utilisateur `common-files` partagé pour les dossiers médias inter-services.

:::note[Point d'entrée du mixin]
Active le mixin de profil de l'hôte (`darkone.host.${host.profile}.enable`)
et propage `enableSops` au module sops.
:::

:::caution[SSH est ouvert par interface]
Le port 22 n'est global que sur les hôtes sans jambe WAN. Une passerelle l'obtient sur le pont LAN
et le tailnet&nbsp;; un hôte en zone globale sur le tailnet seulement — un SSH public
là-bas se décide dans le profil d'hôte.
:::

:::danger[SSH est à clé uniquement]
Les mots de passe et l'interactif clavier sont désactivés sur toute la flotte, et seul
`/etc/ssh/authorized_keys.d/%u` est lu&nbsp;: un compte sans clé déclarée
n'a aucun accès SSH, et `ssh-copy-id` n'a plus de canal de bootstrap.
:::

* **enable** `bool` Système principal du framework Darkone (activé par défaut)
* **enableSystemdBoot** `bool` Activer le chargeur de démarrage par défaut
* **enableLatestKernel** `bool` Utiliser le dernier noyau mainline (linuxPackages_latest) au lieu du LTS
* **enableFstrim** `bool` Optimisation SSD avec fstrim
* **enableFirewall** `bool` Activer le pare-feu (true par défaut)
* **enableSops** `bool` Activer le module dnf sops (true par défaut)
* **enableFlatpak** `bool` Activer la configuration DNF flatpak (uniquement pour les environnements graphiques)
* **enableKmscon** `bool` Activer la nerd font pour le TTY
* **gcKeepGenerations** `int` Si &gt; 0, limiter le profil système aux N dernières générations avant
  chaque collecte de déchets, et collecter quotidiennement sans rétention
  basée sur l'âge. Pour les hôtes avec une partition racine étroite (passerelles).
* **enableBoost** `bool` Activer l'overclocking, corectl
* **enableAutoSuspend** `bool` Activer la veille automatique (pour les portables, ignoré si disableSuspend est true)
* **disableSuspend** `bool` Désactivation complète de la veille (pour les serveurs)
* **enableCommonFilesUser** `bool` Activer l'utilisateur common-files utilisé par plusieurs services

```nix
darkone.system.core = {
  enable = true;
  enableSystemdBoot = true;
  enableLatestKernel = false;
  enableFstrim = true;
  enableFirewall = true;
  enableSops = true;
  enableFlatpak = true;
  enableKmscon = true;
  gcKeepGenerations = 5;
  enableBoost = false;
  enableAutoSuspend = false;
  disableSuspend = false;
  enableCommonFilesUser = false;
};
```

### &#x2699; darkone.system.dnf-release

Estampille la version du framework sur l&#x27;hôte&nbsp;: `/etc/dnf-release` et l&#x27;étiquette d&#x27;amorçage.

Répond à la question «&nbsp;quelle version de DNF fait tourner cette machine&nbsp;?&nbsp;» sans journal de déploiement, sur une flotte où les hôtes sont mis à jour un par un et où une restauration peut laisser un nœud à plusieurs versions en arrière.

:::note[Inconditionnel]
Pas d&#x27;option `enable`&nbsp;: pur métadonnées, pas de service, aucun coût. `dnfVersion` provient de `lib/mk-configuration.nix`, qui lit `dnf/VERSION` et la révision du flake.
:::

:::tip[Le lire]
```sh
cat /etc/dnf-release      # DNF_RELEASE + DNF_REV
nixos-version             # release apparaît comme une étiquette `dnf-X.Y.Z`
```
:::

### &#x2699; darkone.system.hardware

Améliorations de la configuration matérielle.

Tous les firmwares sont chargés (`hardware.enableAllFirmware`), sauf sur une
machine virtuelle&nbsp;: `just detect-hw` la détecte (`systemd-detect-virt --vm`) et
définit `darkone.system.hardware.virtual` dans `hardware/detected-hardware.nix`.
Un invité permet aussi à Zed de tourner sur son GPU émulé (`ZED_ALLOW_EMULATED_GPU`).

* **enable** `bool` Activer les optimisations matérielles
* **enableIntel** `bool` Activer les mises à jour de microcode intel
* **enableAmd** `bool` Activer les mises à jour de microcode amd
* **virtual** `bool` Machine virtuelle, aucun firmware chargé. Défini par `just detect-hw`

```nix
darkone.system.hardware = {
  enable = false;
  enableIntel = false;
  enableAmd = false;
  virtual = false;
};
```

### &#x2699; darkone.system.i18n

Configuration de la localisation et de la langue.

:::note
Les valeurs par défaut suivent la zone de l'hôte (`etc/config.yaml`). La locale doit avoir la forme canonique `xx_YY.UTF-8` (p.&nbsp;ex. `fr_FR.UTF-8`)&nbsp;: le mappage de clavier en console, la disposition XKB et la région téléphonique Nextcloud en dérivent.
:::

:::tip[Clavier d'une locale]
`dnf/config/locales.json` indique le clavier utilisé pour chaque locale proposée par l'installateur (`en_GB.UTF-8`&nbsp;: `uk` en console, `gb` en XKB). Pour toute autre locale, le code pays est utilisé (`ru_RU.UTF-8`&nbsp;: `ru`).
:::

* **enable** `bool` Active l'internationalisation avec la configuration de la zone réseau par défaut
* **locale** `strMatching dnfLib.localeRegex` Locale réseau, doit respecter la forme `xx_YY.UTF-8`.
* **timeZone** `str` Fuseau horaire réseau
* **keyboard** `raw` Clavier de la locale&nbsp;: mappage `console`, disposition `xkb` et variante `xkbVariant`.

```nix
darkone.system.i18n = {
  enable = false;
  locale = "fr_FR.UTF-8";
  timeZone = "Europe/Paris";
  keyboard = if cfg.enable then
          dnfLib.keyboardFromLocale cfg.locale
        else
          {
            console = config.console.keyMap;
            xkb = config.console.keyMap;
            xkbVariant = "";
          };
};
```

### &#x2699; darkone.system.luks

Politique de phrases de passe LUKS et déverrouillage à distance : phrases de passe partagée et par hôte, SSH en initrd.

Complète `modules/system/yubikey.nix` (slots de clés FIDO2) avec le volet phrases de passe de la politique LUKS du parc. Chaque volume chiffré porte exactement deux phrases de passe gérées, plus un slot par YubiKey enrôlée :

| Slot de clés | Secret | Destinataire |
|---|---|---|
| partagée | sops `luks-passphrase` | l'administrateur du parc. **Autorise** aussi les opérations sur les slots de clés (`luksAddKey` / `luksKillSlot`) pour les unités ci-dessous, et c'est la clé avec laquelle disko formate le disque. |
| par hôte | sops `luks/<host>/passphrase` | l'utilisateur de cette seule machine, sans livrer le parc. |
| FIDO2 | registre `usr/secrets/yubikeys.json` | un slot par clé, sur chaque hôte chiffré. |

Deux phrases de passe gérées et non une, parce qu'elles servent des personnes différentes, et parce que la rotation de l'une reste autorisée par l'autre : l'unité de synchronisation n'est donc jamais sans autorisateur (elle ajoute le nouveau slot avant de tuer l'ancien).

Il n'y a pas de « phrase de passe d'installation » séparée : `just install` formate le volume via `nixos-anywhere --disk-encryption-keys` avec la phrase de passe partagée, donc le slot de format *est* le slot partagé. Sur le premier hôte (`darkone new`, `just install-here`), la phrase de passe saisie dans l'assistant le devient.

`just luks <host>` provisionne un hôte (idempotent, aussi appelé par `just configure`) ; sa phase `pre` s'exécute hors ligne et est appelée par `just install` avant le build. Il inscrit l'hôte dans le manifeste **public** `usr/secrets/luks.json` (versionné), stocke la phrase de passe par hôte et la clé d'hôte SSH de l'initrd dans sops, et garantit que la `luks-passphrase` partagée existe. `just luks <host> show` affiche le tableau des slots de clés et audite le déverrouillage à distance. Le module maintient ensuite tout convergé à chaque apply :

- **slots de clés** : un service oneshot synchronise les phrases de passe partagée et par hôte dans chaque en-tête LUKS2 déclaré par disko. Une valeur sops modifiée fait tourner le slot correspondant (ancien slot tué, nouveau ajouté). Les opérations sur les slots de clés sont autorisées par la phrase de passe gérée qui déverrouille encore le volume : l'une d'elles doit donc rester valide. Les slots hors de son registre (FIDO2, enrôlements manuels) ne sont jamais touchés.
- **déverrouillage à distance** : sshd en initrd sur un port dédié (2222), clé d'hôte persistante propre (`/var/lib/luks-initrd/`), connexion root avec la clé de déploiement `nix` (`usr/secrets/nix.pub`). `just unlock <host>` répond à l'invite de phrase de passe sans humain (via l'assistant `dnf-unlock` livré dans l'initrd), puis de façon interactive depuis un terminal quand aucune phrase de passe stockée ne fonctionne. Il se rabat sur l'IP WAN enregistrée dans le manifeste quand la route VPN est morte. Les hôtes ordinaires font du DHCP sur les interfaces filaires (un portable en Wi-Fi n'a pas de réseau en initrd et retombe sur le déverrouillage en console) ; les passerelles de zone répliquent plutôt leur disposition de production, IP LAN statique sur le bridge lan0 et DHCP côté WAN, puisqu'elles sont elles-mêmes le serveur DHCP que leur initrd attendrait sinon.

:::caution[Hôtes isolés]
Un hôte isolé (`darkone.system.sops.isolated`) ne détient jamais de secret du parc :
pas de slot partagé, disko formate avec sa propre phrase de passe, et
`luks/<host>/*` vit dans son propre `usr/secrets/hosts/<host>.yaml`. Pas d'unité
de synchronisation non plus : une phrase de passe seule ne peut pas autoriser sa
propre rotation, c'est `just luks <host> passwd` qui la fait tourner depuis l'hôte
d'administration. Le déverrouillage à distance reste.
:::

:::note[Zéro configuration]
Activé par défaut mais totalement inerte tant que l'hôte n'apparaît pas dans
`usr/secrets/luks.json` ET ne déclare pas de volume LUKS dans sa configuration disko.
Les hôtes chiffrés existants ne sont pas affectés tant que `just luks <host>` n'a pas été lancé.
:::

:::caution[La clé de l'initrd doit précéder le bootloader]
Les secrets de l'initrd sont ajoutés à l'installation du bootloader, *avant*
l'activation. Une installation neuve est couverte : `just install` place la clé sous
`/mnt` (`nixos-anywhere --extra-files`) pour que le tout premier démarrage écoute déjà
sur 2222. Sur un hôte déjà en marche, `just luks <host>` la met en place par
SSH ; n'ajoutez jamais un hôte à `luks.json` à la main, et n'appliquez jamais avant que la clé
n'existe sur la cible.
:::

:::danger[Budget de slots de clés]
Les en-têtes LUKS2 acceptent au plus 32 slots de clés. Chaque YubiKey enrôlée consomme un
slot sur chaque hôte chiffré (politique à l'échelle du parc), plus les phrases de passe
partagée et par hôte : le module avertit quand le total projeté approche de la limite.
:::

* **enable** `bool` Politique de phrases de passe LUKS du parc (inerte tant que `just luks &lt;host&gt;` n'a pas provisionné l'hôte)
* **sshPort** `port` Port du sshd de l'initrd ; distinct de 22 pour que la clé d'hôte de l'initrd n'entre jamais en conflit avec celle du système
* **volumes** `listOf str` Volumes LUKS déclarés par la disposition disko de l'hôte.

```nix
darkone.system.luks = {
  enable = true;
  sshPort = 2222;
  volumes = [ ];
};
```

### &#x2699; darkone.system.microvm

Invités MicroVM (microvm.nix, cloud-hypervisor) sur un hôte hyperviseur DNF.

Un invité est un hôte DNF ordinaire de l'inventaire, marqué de la
fonctionnalité `microvm-guest:<hypervisor>` dans `etc/config.yaml`. Il garde son IP
de zone, ses services et sa supervision&nbsp;; l'hyperviseur l'exécute et le déploie.

```yaml
- hostname: "space1"
  zone: "cp:1.40"              # fixed IP: tap + MAC are derived from it
  profile: "ai-space"
  features: ["microvm-guest:ms-a2", "monitoring-node"] # monitored like any host
```

- Côté invité (`microvm/guest.nix`)&nbsp;: partages virtiofs sous
  `<stateDir>/<guest>/{persist,var-lib,home}`, store de l'hôte en lecture seule, clé
  de l'hôte sur `/persist`, lien statique `/32` routé par l'hyperviseur.
- Côté hyperviseur (`microvm/host.nix`)&nbsp;: un tap routé par invité (pas de pont),
  tout l'hôte sur networkd avec la passerelle de zone comme résolveur statique, proxy
  ARP sur le LAN, isolation nftables (table `dnf-microvm`), `<stateDir>` fermé aux
  utilisateurs de l'hyperviseur (0770) et monté `nosuid,nodev` (fichiers setuid,
  nœuds de périphérique d'un invité inertes).
- Parole vers texte (`microvm/whisper.nix`)&nbsp;: un serveur whisper.cpp sur
  l'hyperviseur pour les invités avec
  `darkone.system.microvm.guest.whisper` (notes vocales OpenClaw), démarré et
  ouvert pour eux seuls&nbsp;; `whisper.model`, `whisper.threads` le règlent.

:::note[Déploiement]
Les invités ne sont pas des nœuds colmena&nbsp;: déployer l'hyperviseur construit et
redémarre les invités dont le système a changé.
:::

:::caution[Optimisation du store]
Désactivée sur un hyperviseur&nbsp;: son store est la couche inférieure de l'overlay
de store des invités, qui répond ESTALE dès que `nix-store --optimise` recrée un lien
vers un fichier qu'un invité en cours d'exécution a lu. Ne jamais la lancer à la main
là non plus.
:::

:::caution[Isolation]
Un invité atteint Internet et le DNS de la passerelle de zone, rien d'autre sur le
LAN&nbsp;; de l'hyperviseur, uniquement les services qu'il demande (whisper). Seule la
passerelle de zone (proxy inverse, supervision) atteint un invité.
:::

* **hypervisor** `nullOr str` Hyperviseur exécutant cet hôte comme invité microVM, null sur machine physique.
* **stateDir** `str` Répertoire de l'hyperviseur contenant un sous-répertoire de partages par invité.
* **guest.vcpu** `ints.positive` Processeurs virtuels de l'invité.
* **guest.mem** `ints.positive` RAM de l'invité, en MiB.
* **guest.whisper** `bool` Utiliser le serveur whisper.cpp de l'hyperviseur (parole vers texte)&nbsp;: démarré et ouvert à cet invité.
* **guestInputRules** `lines` Règles nftables de la chaîne d'entrée `dnf-microvm` de l'hyperviseur, avant le drop du trafic des invités.
* **whisper.model** `path` Modèle ggml whisper.cpp du serveur de l'hyperviseur, chargé une fois pour tous les invités.
* **whisper.threads** `ints.positive` Threads du serveur whisper.cpp de l'hyperviseur, une transcription à la fois.

```nix
darkone.system.microvm = {
  hypervisor = dnfLib.getMicrovmHypervisor hosts host;
  stateDir = "/var/lib/microvms";
  guest.vcpu = 2;
  guest.mem = 4096;
  guest.whisper = false;
  guestInputRules = "";
  whisper.model = pkgs.fetchurl {
        url = "https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3-turbo.bin";
        sha256 = "1fc70f774d38eb169993ac391eea357ef47c88757ef72ee5943879b7e8e2bc69";
      };
  whisper.threads = 8;
};
```

### &#x2699; darkone.system.security

Durcissement système ANSSI BP-028 v2.0 (GNU/Linux). (wip)

Module recommandé, activé dans certains profils d'hôte ou manuellement
selon les besoins. Applique progressivement les
recommandations ANSSI selon le niveau et la catégorie de machine choisis.
Chaque profil d'hôte définit son niveau et sa catégorie&nbsp;:

:::danger[Module en cours de développement]
- Affiner et tester les options, fonctionnalités, etc.
- Créer le « checkScript », outil d'introspection de la configuration de sécurité.
- Configuration locale simple pour les réglages propres au matériel et aux besoins.
:::

```nix
darkone.system.security = {
  level    = "intermediary"; # minimal | intermediary | reinforced | high
  category = "server";       # base | client | server
};
```

Les règles incompatibles avec l'environnement sont exclues par tag&nbsp;:

```nix
darkone.system.security.excludes = [ "needs-jit" "needs-hibernation" ];
```

Une règle précise peut être contournée avec une justification obligatoire&nbsp;:

```nix
darkone.system.security.exceptions = {
  R9.rationale = "Docker rootless required during development.";
};
```

:::note[Niveau de durcissement ANSSI]
- `minimal`      : base commune, tout système (par défaut).
- `intermediary` : recommandé pour presque tous les systèmes.
- `reinforced`   : systèmes sensibles ou multi-tenant.
- `high`         : compétences et budget dédiés ; implique une recompilation
                   du noyau (tag `kernel-recompile`) si non exclue.
:::

:::note[Catégorie de machine]
- `base`   : règles universelles, toujours appliquées (par défaut).
- `client` : poste de travail (GUI, USB, session, verrouillage).
- `server` : serveur (réseau durci, journalisation centralisée, services exposés).

Indépendante de `host.profile`, à définir explicitement dans chaque profil d'hôte.
:::

:::note[Tags d'exclusion]
- `kernel-recompile`             : ignore R15–R27, C1 (pas de noyau personnalisé).
- `disable-kernel-module-loading`: ignore R10 (peut casser des périphériques).
- `no-ipv6`                      : ignore R22 (options noyau IPv6). Abandonner
                                   IPv6 lui-même (R13) est l'option opt-in
                                   `darkone.security.kernel-params.disableIpv6`.
- `no-mac`                       : ignore R37, R45 (pas de MAC active).
- `no-sealing`                   : ignore R76, R77 (pas de HIDS/AIDE).
- `no-auditd`                    : ignore R73 (auditd non configurable).
- `embedded`                     : assouplit les contraintes /var, /home, etc.
- `needs-jit`                    : autorise un W^X assoupli (Java, .NET, V8, Wasm).
- `needs-kexec`                  : conserve kexec pour kdump.
- `needs-binfmt`                 : conserve binfmt_misc (Java, qemu-static).
- `needs-hibernation`            : conserve l'hibernation (portables).
- `needs-usb-hotplug`            : désactive USBGuard / deny_new_usb.
:::

:::note[Exceptions par règle]
Une règle avec exception est exclue de l'activation même si le niveau la couvre.
Justification obligatoire dans `rationale`. Les exceptions d'hôte s'ajoutent aux
exceptions structurelles SELinux (R46–R49), sans jamais les remplacer.
:::

:::caution[Effets de bord]
Certaines règles peuvent casser un usage courant : `noexec /tmp` (R28), SMT désactivé (R8 —
le conserver avec `darkone.security.kernel-params.disableSmt = false`), modules
non signés (R18), conteneurs rootless (R9), JIT (R63). Vérifier les commentaires
`sideEffects` dans chaque fichier thématique avant d'élever le niveau sur un système de production.
:::

* **enable** `bool` Active le module de durcissement ANSSI BP-028 v2.0.
* **level** `enum [ "minimal" "intermediary" "reinforced" "high" ]` Niveau de durcissement ANSSI visé.
* **category** `enum [ "base" "client" "server" ]` Catégorie de machine qui sélectionne les sous-ensembles de règles.
* **excludes** `listOf str` Tags qui désactivent des groupes entiers de règles.
* **exceptions** `attrs` Exceptions par règle avec justification obligatoire. Fusionnées avec les exceptions structurelles SELinux (R46–R49).
* **adminMailbox** `str` Adresse e-mail de l'administrateur (sudo R39, alias MTA R75).
* **useHardenedKernel** `bool` Utilise linuxPackages_hardened (R60, C1) au lieu du noyau par défaut.
* **allowedActiveUsers** `listOf str` Comptes humains autorisés à s'authentifier (R30). Par défaut, tous les utilisateurs
  déclarés dans config.yaml (host.users) plus le compte de déploiement
  du framework `nix`. Les comptes désactivés (aucun identifiant de mot de passe) et les comptes
  de service (pas des utilisateurs normaux) n'ont pas besoin d'être listés.

```nix
darkone.system.security = {
  enable = false;
  level = "minimal";
  category = "base";
  excludes = [ ];
  exceptions = { };
  adminMailbox = "admin@exemple.fr";
  useHardenedKernel = false;
  allowedActiveUsers = [ ];
};
```

### &#x2699; darkone.system.services

Registre des services DNF : chaque module de service s'y enregistre, et le registre
est résolu par rapport à la topologie réseau.

:::caution[Module interne spécial]
Le registre résolu (`darkone.system.services.resolved`) alimente les sections
de la page d'accueil et les sous-modules ci-dessous. Les entrées `persist.*` sont
les dossiers et fichiers à sauvegarder.
:::

Sous-modules (`services/`) :
- `caddy.nix` : vhosts du reverse proxy, TLS, pare-feu HTTP(S) ;
- `oauth2-proxy.nix` : SSO Kanidm des services protégés.

{/* t:p 40dca566541cc3e195ba3809298afd0f66f4a80d4602b7b17a7075fe96f84575 */}
#### Reverse proxy (`caddy.nix`)

Un vhost Caddy par service résolu, plus le pare-feu HTTP(S) des passerelles de zone
et du HCS.

:::note[Exposition]
- services de zone : sur la passerelle de zone, sous le domaine de zone ;
- services globaux : sur le HCS, sous le domaine du réseau ;
- `external-hosts` : services de zone dont le HCS fait face, proxyés vers leur passerelle.
:::

{/* t:p 6aa3e72674e7de020bffd26362d1bc5ea68242949e18f313817503d6826aeb28 */}
#### SSO (`oauth2-proxy.nix`)

oauth2-proxy devant les services protégés d'une zone, adossé au client
OAuth2 `internal-service` de Kanidm.

:::note[Flux]
Caddy `forward_auth` vérifie chaque requête contre `/oauth2/auth`. Le flux de
connexion est ancré sur le FQDN de la page d'accueil de la zone, qui héberge
les points d'entrée publics `/oauth2/*` d'oauth2-proxy&nbsp;; un cookie scopé au
domaine de la zone conserve la session entre ses services.
:::

* **enable** `bool` Activer le gestionnaire de services DNF pour enregistrer et exposer les services
* **service** `attrs` Configuration globale des services &lt;name&gt;
  * **enable** `bool` Activer le proxy du service
  * **defaultParams** `submodule` Ces options sont calculées par dnfLib.srv.extractServiceParams
    * **domain** `str` Nom de domaine du service
    * **title** `str` Nom affiché sur la page d'accueil
    * **description** `str` Description du service pour la page d'accueil
    * **icon** `str` [Nom de l'icône pour la page d'accueil](https://selfh.st/icons/)
    * **global** `bool` Le service global est accessible sur Internet
    * **noRobots** `bool` Empêcher les robots de scanner si global est vrai
    * **fqdn** `str` FQDN calculé du service avant le reverse proxy
    * **href** `str` URL calculée du service avant le reverse proxy
    * **ip** `str` IP calculée pour contacter le service
  * **displayOnHomepage** `bool` Afficher un lien sur la page d'accueil
  * **reverseProxy** `bool` Atteint via le reverse proxy de la passerelle de zone (le DNS pointe sur l'IP LAN de la passerelle)
  * **uniquePerZone** `bool` Au plus une instance autorisée par zone (validation du générateur)
  * **externalAccess** `bool` Service www-zone joignable depuis le LAN via une IP hôte fixe (ex. headscale, turn)
  * **persist.dirs** `listOf str` Répertoires persistants du service
  * **persist.files** `listOf str` Fichiers persistants du service
  * **persist.dbDirs** `listOf str` Répertoires persistants du service avec base(s) de données
  * **persist.dbFiles** `listOf str` Fichier(s) de base de données du service
  * **persist.varDirs** `listOf str` Fichiers secondaires variables (log, cache, etc.)
  * **persist.mediaDirs** `listOf str` Répertoires médias du service (images, vidéos, gros fichiers)
  * **proxy.enable** `bool` Créer la configuration virtualHost (false pour les services qui gèrent le leur)
  * **proxy.isProtected** `bool` Service protégé par Oauth2
  * **proxy.allowedGroups** `listOf str` Groupes Kanidm autorisés sur ce service protégé (vide = tout utilisateur authentifié)
  * **proxy.spaceMembersOnly** `bool` Restreindre aux membres de l'espace IA de l'hôte de l'instance (groupe Kanidm `space-&lt;host&gt;`)&#8239;; implique isProtected
  * **proxy.isInternal** `bool` Lier le service sur l'interface interne uniquement (pas accessible depuis Internet)
  * **proxy.hasReverseProxy** `bool` C'est un reverse proxy (ou une autre configuration virtualhost via extraConfig)
  * **proxy.defaultService** `bool` Est le service par défaut
  * **proxy.servicePort** `nullOr port` Port interne du service
  * **proxy.preExtraConfig** `lines` Configuration caddy virtualHost supplémentaire (préfixe)
  * **proxy.extraConfig** `lines` Configuration caddy virtualHost supplémentaire
  * **proxy.extraGlobalConfig** `lines` Configuration caddy supplémentaire
  * **proxy.scheme** `str` Schéma du service interne (http / https)
* **resolved** `raw` Registre des services résolus.

```nix
darkone.system.services = {
  enable = false;
  service.enable = false;
  service.defaultParams.domain = "";
  service.defaultParams.title = "";
  service.defaultParams.description = "";
  service.defaultParams.icon = "";
  service.defaultParams.global = false;
  service.defaultParams.noRobots = true;
  service.defaultParams.fqdn = "";
  service.defaultParams.href = "";
  service.defaultParams.ip = "";
  service.displayOnHomepage = true;
  service.reverseProxy = true;
  service.uniquePerZone = false;
  service.externalAccess = false;
  service.persist.dirs = [ ];
  service.persist.files = [ ];
  service.persist.dbDirs = [ ];
  service.persist.dbFiles = [ ];
  service.persist.varDirs = [ ];
  service.persist.mediaDirs = [ ];
  service.proxy.enable = true;
  service.proxy.isProtected = false;
  service.proxy.allowedGroups = [ ];
  service.proxy.spaceMembersOnly = false;
  service.proxy.isInternal = false;
  service.proxy.hasReverseProxy = true;
  service.proxy.defaultService = false;
  service.proxy.servicePort = null;
  service.proxy.preExtraConfig = "";
  service.proxy.extraConfig = "";
  service.proxy.extraGlobalConfig = "";
  service.proxy.scheme = "https";
  resolved = { inherit services hasProtectedServices authHost; };
};
```

### &#x2699; darkone.system.sops

Gestion des sops, des mots de passe et des secrets DNF.

:::danger[Module critique]
Ce module est activé par défaut dans le module core.
Il est recommandé de le garder activé et de le configurer (commandes `just passwd*`).
:::

Relie sops-nix à `usr/secrets/secrets.yaml` et le déverrouille avec la
clé SSH de l'hôte (`ssh_host_ed25519_key`) plus la clé age
d'infrastructure dédiée (`/etc/sops/age/infra.key`). Déclare un secret
`user/<login>/password-hash` par utilisateur de l'hôte, avec
`neededForUsers = true` pour que le hachage soit disponible avant la
création des comptes utilisateurs.

Les secrets ordinaires sont installés par `sops-install-secrets.service`
(`sops.useSystemdActivation`), avant `sysinit.target` ; un secret modifié
redémarre ses `restartUnits` dans le même switch. Les hachages de mots de
passe restent dans le script d'activation, avant les comptes utilisateurs.

Rien d'autre n'est matérialisé ici&nbsp;: un secret appartient aux hôtes qui
le consomment, déclaré par le module qui le lit.

:::caution[Hôtes isolés]
`isolated = true` (défaut du profil `ai-space`) pointe l'hôte vers
son propre `usr/secrets/hosts/<hostname>.yaml`, sans la clé infra&nbsp;: un hôte
qui exécute des agents non fiables ne détient jamais les secrets de la flotte,
et une clé laissée par une installation antérieure est supprimée. Pas de hachage
de mot de passe non plus, ses comptes sont uniquement par clé SSH. Déclarer une
valeur de flotte à cet endroit (`luks-passphrase`, un hachage de mot de passe,
un secret FIDO2 au sel de la flotte) fait échouer l'éval.
:::

* **enable** `bool` Active la configuration automatisée sops pour DNF
* **isolated** `bool` fichier de secrets propre, pas de clé infra, pas de hachages de mots de passe

```nix
darkone.system.sops = {
  enable = false;
  isolated = false;
};
```

### &#x2699; darkone.system.srv-dirs

Service de gestion des répertoires partagés.

:::caution[Auto-activation]
Ce service est automatiquement activé par les services qui utilisent NFS ou le stockage média partagé.
:::

* **enable** `bool` Activer les répertoires partagés, créer le répertoire racine (défaut /srv)
* **enableNfs** `bool` Activer les chemins du service NFS (nfs/common, nfs/homes)
* **enableMedias** `bool` Activer les chemins des services média (medias/[videos|music|incomming/...])
* **enableStk** `bool` Activer le chemin de partage des pistes SuperTuxKart (nfs/stk-tracks)
* **root** `str` Répertoire racine des données persistantes (/srv)
* **nfs** `str` Répertoire racine NFS (/srv/nfs)
* **homes** `str` Répertoire des domiciles partagés (/srv/nfs/homes)
* **common** `str` Répertoire commun partagé (/srv/nfs/common lié à ~/Public)
* **stkTracks** `str` Répertoire des pistes SuperTuxKart partagées (/srv/nfs/stk-tracks)
* **medias** `str` Répertoire racine des médias (/srv/medias)
* **music** `str` Répertoire des fichiers musicaux partagés (/srv/medias/music)
* **videos** `str` Répertoire des fichiers vidéo partagés (/srv/medias/videos)
* **incoming** `str` Répertoire des fichiers entrants partagés (/srv/medias/incoming accès en écriture)
* **incomingMusic** `str` Répertoire des fichiers entrants partagés (/srv/medias/incoming/music accès en écriture)
* **incomingVideos** `str` Répertoire des fichiers entrants partagés (/srv/medias/incoming/videos accès en écriture)

```nix
darkone.system.srv-dirs = {
  enable = cfg.enableNfs || cfg.enableMedias || cfg.enableStk;
  enableNfs = false;
  enableMedias = false;
  enableStk = false;
  root = "/srv";
  nfs = null;
  homes = null;
  common = null;
  stkTracks = null;
  medias = null;
  music = null;
  videos = null;
  incoming = null;
  incomingMusic = null;
  incomingVideos = null;
};
```

### &#x2699; darkone.system.testing

Mode test autonome pour le NixOS Test Driver.

Quand activé, neutralise les parties irréductiblement externes/exécution afin
qu'un nœud puisse être testé dans une VM&nbsp;: headscale/tailscale deviennent
des no-op et un certificat TLS fixe peut simuler ACME. Permet également à la
configuration propre à workDir (nix.pub, harmonia.pub) d'être ignorée par
core/nix-cache. sops reste RÉEL (haute fidélité).

:::caution[Tests uniquement]
Activé uniquement via `tests/lib/test-tuning.nix`. Ce module ne référence
jamais de chemin sous `tests/` — le chemin du certificat est passé comme
valeur d'option.
:::

* **standalone** `bool` Mode test autonome — ignore la configuration propre à workDir (nix.pub, harmonia.pub) et neutralise les services externes
* **tlsCert** `nullOr path` Certificat auto-signé (PEM) fourni par le harnais de test pour simuler ACME. Jamais un chemin tests/ intégré dans le framework.
* **tlsKey** `nullOr path` Clé privée (PEM) associée à tlsCert.

```nix
darkone.system.testing = {
  standalone = false;
  tlsCert = null;
  tlsKey = null;
};
```

### &#x2699; darkone.system.yubikey

Authentification forte par YubiKey : PAM U2F à l'échelle du parc et LUKS FIDO2 déclaratif.

Un enrôlement physique par (utilisateur, clé) sur l'hôte d'administration (`just yubikey
<user> [key] [action]`) alimente :

- un registre **public** `usr/secrets/yubikeys.json` dans l'espace de travail consommateur :
  identifiant pamu2fcfg, identifiant et sel de l'identifiant hmac-secret FIDO2
  (tout inutile sans la clé physique, donc versionnable) ;
- un secret sops `yubikey/<user>/<key>/luks-secret` (la phrase de passe LUKS
  dérivée du FIDO2) plus la `luks-passphrase` partagée (la phrase de passe saisie
  à l'installation disko, nécessaire pour autoriser de nouveaux slots de clés).

Le module propage ensuite tout de façon déclarative (`just apply`), sans
jamais brancher la clé sur les hôtes cibles :

- **connexion / sudo / greeter** : pam_u2f en *alternative* au mot de passe
  (`sufficient`) : toucher la clé connecte, le mot de passe sops reste le
  repli automatique. Un identifiant est valable à l'échelle du parc grâce à
  l'origine fixe (`pam://<network.domain>`).
- **hôtes chiffrés** : un service oneshot auto-enrôle chaque clé déclarée dans
  chaque en-tête LUKS2 déclaré par disko (slot de clés et jeton `systemd-fido2`,
  exactement le format qu'écrit `systemd-cryptenroll`) et élague les clés révoquées. La clé
  physique n'est nécessaire qu'au démarrage pour déverrouiller le disque.

:::caution[Hôtes isolés : sels propres]
Un hôte isolé (`darkone.system.sops.isolated`) ne voit jamais le sel du parc
ni sa valeur : `just yubikey` dérive une valeur par (clé, hôte chiffré isolé)
à partir d'un sel de cet hôte (`hostSalts` dans le registre, valeur dans le
fichier sops de l'hôte, une touche à chaque fois), autorisé là par la phrase de passe propre
à l'hôte. Une clé non capturée pour un hôte n'y est pas enrôlée.
:::

:::note[Zéro configuration]
Activé par défaut, mais totalement inerte tant que le fichier de registre n'existe pas.
La prise en charge LUKS s'appuie sur les volumes LUKS trouvés dans la configuration disko de l'hôte
(`usr/machines/<host>/install/disko.nix`, importée à l'exécution).
:::

:::caution[Aucun verrouillage par conception]
Le slot de clé de la phrase de passe d'installation et les mots de passe de session sops ne sont jamais
touchés : perdre une clé se rabat au pire sur la phrase de passe ou le mot de passe. Cela vaut
aussi au démarrage : la tentative FIDO2 s'exécute dans une unité à part autorisée à
échouer, si bien qu'une clé inutilisable, non touchée ou absente aboutit toujours à l'invite
de phrase de passe ; voir le commentaire sur le bloc initrd ci-dessous.
:::

:::caution[La touche au démarrage est inévitable]
Les YubiKey imposent la présence utilisateur pour l'extension `hmac-secret` : une assertion
demandant `up=false` est refusée avec `FIDO_ERR_UP_REQUIRED` avant même que
l'identifiant ne soit comparé. La touche est une règle matérielle, pas un réglage du jeton,
et aucun indicateur d'en-tête ne peut la lever. Le déverrouillage sans intervention (passerelles,
hôtes sans écran) relève du TPM2 (`systemd-cryptenroll --tpm2-device=auto`),
qui coexiste avec ces slots de clés FIDO2 dans le même en-tête LUKS.
:::

:::caution[Le trousseau GNOME reste verrouillé lors d'une connexion par clé]
`sufficient` termine la pile d'authentification avant `pam_gnome_keyring` : un trousseau de connexion
scellé demande une saisie au démarrage de session. Remède : `darkone.home.gnome.passwordlessKeyring`,
activé par défaut pour les utilisateurs non avancés d'un hôte LUKS.
:::

* **enable** `bool` Authentification par YubiKey (défaut : activée quand usr/secrets/yubikeys.json existe)
* **origin** `str` Origine/appid pam_u2f fixe : un enrôlement est valable à l'échelle du parc
* **luks.enable** `bool` Déverrouillage FIDO2 des volumes LUKS de l'hôte (inerte sans LUKS disko et clés enrôlées)

```nix
darkone.system.yubikey = {
  enable = hasRegistry;
  origin = "pam://${network.domain}";
  luks.enable = true;
};
```
