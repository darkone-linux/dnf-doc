Supervision : tableaux de bord Grafana et exporteur par nœud.

:::tip
Grafana affiche les métriques collectées par le service `prometheus` (requis sur le même hôte, imposé par le générateur). Pour chaque zone :

- Tous les nœuds avec le tag « monitoring-node » exécutent l'exporteur de nœud.
- Le nœud avec le service « monitoring » exécute Grafana (et requiert `prometheus`).
- Un seul hôte de supervision par zone est accepté.
- Un tag « monitoring-node:[zone] » rattache un nœud au Prometheus de cette zone.
:::

Surveillance en lecture seule (`monitoring/fs-readonly.nix`) : chaque nœud exporte `dnf_filesystem_forced_readonly`, ses montages `rw` que le noyau a passés en lecture seule, derrière `FilesystemReadOnly`. Les montages `ro` voulus et les bind mounts n'apparaissent jamais ; le fichier vit sur tmpfs, il survit donc au disque défaillant.

## Options

* **enable** `bool` Activer la supervision avec prometheus, grafana et l'exporteur de nœud
* **isNode** `bool` Est un nœud de supervision
* **kioskTarget** `str` Cible (relative, sans `/`) de la redirection automatique vers Grafana
  depuis la racine du domaine de supervision. Remplacée par le module Loki
  lorsqu'il est actif, pour pointer vers un tableau de bord d'accueil multi-sources.

```nix
darkone.service.monitoring = {
  enable = false;
  isNode = lib.hasAttrByPath [ "features" "monitoring-node" ] host;
  kioskTarget = "d/dnf-monitoring-home/home?kiosk";
};
```
