Un service Garage S3 local, entièrement configuré.

Fournit un backend de stockage objet compatible S3, interne, accessible uniquement sur 127.0.0.1:3900.

:::note[Création manuelle des buckets]
Les buckets ne sont PAS créés automatiquement par ce module.
Chaque service consommateur crée son propre bucket et sa clé d'accès via une unité systemd oneshot dédiée, ordonnée After= `garage-init.service`.
Les identifiants de chaque consommateur sont stockés dans sops sous `garage-<consumer>-key-id` et `garage-<consumer>-key-secret`, puis importés dans Garage au premier démarrage.
:::

:::tip[Migration vers un cluster multi-nœuds]
Mono-nœud, replication_factor = 1. Pour passer à un cluster multi-nœuds, augmenter `replication_factor`, exposer `rpc_public_addr` sur le mesh, et étendre `garage-init` pour piloter une disposition multi-nœuds.
:::

:::caution[Initialisation de la disposition du cluster]
En cas d'échec, attendre que le service garage soit entièrement opérationnel, puis le redémarrer.
:::

## Options

* **enable** `bool` Active le service Garage S3 local
* **srvPort** `port` Port de l'API S3 exposé sur l'IP interne
* **s3Region** `str` Nom de la région S3 (doit correspondre à la configuration du consommateur)
* **capacity** `str` Indication de capacité de stockage du nœud, transmise à `garage layout assign`.
  Utilisée uniquement au premier démarrage pour l'initialisation de la disposition ; ne constitue pas
  un quota strict sur le système de fichiers sous-jacent.
  Suffixes supportés : B, KB, MB, GB, TB, PB.

```nix
darkone.service.garage = {
  enable = false;
  srvPort = srvPort;
  s3Region = s3Region;
  capacity = "500GB";
};
```
