Un service headscale entièrement configuré pour HCS.

La politique ACL du tailnet est générée à partir de la topologie (zones, hôtes, utilisateurs) par `dnfLib.mkHeadscalePolicy`, validée par `headscale policy check` au build, puis rechargée à chaque changement (SIGHUP) sans redémarrer headscale.

- Les machines sont taguées : `tag:hcs`, `tag:gw-<zone>`, `tag:admin` (hôte dont `groups` contient `admin`).
- Les machines et les LAN des zones se joignent entre elles. Appareils personnels : DNS et HTTPS sur le HCS, HTTPS sur les passerelles de zone (toutes les zones pour les administrateurs, sinon leurs groupes `zone-*` et les zones de leurs espaces IA). SSH depuis les postes d'administration et `policy.adminDevices`.
- Chaque hôte de zone adressé est un alias de politique (`nas` -&gt; son IP LAN) : tout autre service s'ouvre via `policy.extraAcls` (`nas:445`).
- Les appareils personnels se connectent via Kanidm (OIDC), pour les membres du groupe Kanidm `tailnet` ; leurs clés expirent après `nodeExpiry`.

```nix
darkone.service.headscale.policy.adminDevices.phone-alice = "100.64.0.9";
```

:::caution[Mode ouvert]
`policy.enforce = false` conserve les identités mais autorise tout le trafic : pour une migration uniquement, le temps que les nœuds soient taggés.
:::

:::note[Panne de Kanidm]
headscale démarre quand même sans Kanidm et bascule sur l'enregistrement en CLI jusqu'à son prochain redémarrage. Les nœuds déjà enregistrés ne sont pas touchés.
:::

Sous-modules (`headscale/`) :
- `dns.nix` : unbound, le DNS pivot du tailnet, et sa vue `tailnet-machines` ;
- `audit.nix` : `headscale-audit`, nœuds en ligne face à la topologie déclarée ;
- `enroll.nix` : `dnf-tailnet-enroll`, derrière `just tailnet-enroll`.

## Pivot DNS (`dns.nix`)

unbound sur le HCS. Les noms internes y parviennent via le split DNS de headscale ; il transmet chaque domaine de zone à la passerelle de zone, le reste à Quad9 en TLS.

Vue `tailnet-machines` : les nœuds taggés (hors HCS) reçoivent l'adresse LAN de zone des services globaux servis par une zone (`git.<domain>` sur une passerelle), tous les autres l'adresse publique. `unbound-tailnet-view` liste leurs IP tailnet depuis headscale, déclarées nulle part.

## Audit (`audit.nix`)

`headscale-audit`, toutes les 15 min : nœuds en ligne face à la topologie déclarée. Métriques pour les alertes `dnf-headscale-<zone>`, détails dans son journal. Il ne tague ni ne supprime jamais.

## Enrôlement (`enroll.nix`)

`dnf-tailnet-enroll`, côté root de `just tailnet-enroll` : clés à usage unique taguées selon la topologie déclarée ; le nœud enrôlé reçoit son nom et ses tags déclarés.

## Options

* **enable** `bool` Activer le service headscale DNF
* **enableGRPC** `bool` Ouvrir le port TCP GRPC
* **nodeExpiry** `str` Expiration des clés des appareils personnels (`0` : jamais). Les machines taguées n'expirent jamais.
* **policy.enforce** `bool` ACL du tailnet en refus par défaut. `false` autorise tout le trafic, pour une migration uniquement.
* **policy.adminDevices** `attrs` Appareils personnels ayant le SSH sur toutes les machines et zones : nom -&gt; IPv4 du tailnet.
* **policy.exitNodeSources** `listOf str` Sources de politique autorisées à utiliser le HCS comme nœud de sortie.
* **policy.extraHosts** `attrs` Alias d'hôtes supplémentaires de la politique (nom -&gt; CIDR), à utiliser dans `extraAcls`. Les hôtes de zone déclarés en ont déjà un.
* **policy.extraAcls** `listOf (attrsOf anything)` Règles ACL ajoutées après les règles générées.
* **shared** `raw` Valeurs headscale partagées avec les sous-modules `headscale/`.

```nix
darkone.service.headscale = {
  enable = false;
  enableGRPC = false;
  nodeExpiry = "180d";
  policy.enforce = true;
  policy.adminDevices = { };
  policy.exitNodeSources = [ ];
  policy.extraHosts = { };
  policy.extraAcls = [ ];
  shared = {
        inherit
          policy
          auditSpec
          idmUrl
          hcsTailnetIpv4
          ;
      };
};
```
