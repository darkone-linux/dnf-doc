Le module `darkone.service.restic` sauvegarde les hôtes du parc avec
[restic](https://restic.net/) : chaque hôte (client) pousse ses données vers un
dépôt, local ou distant via un serveur REST de zone.

{/* t:p d3d4eda68bea9cd4e3a1fa409070615480d0f14964da44a8533315c9d01a6241 */}
## Principes

Deux rôles, un seul module :

- **Serveur REST** : un hôte qui déclare le service `restic` dans `config.yaml`.
  Il stocke les dépôts de tous les hôtes et écoute sur le réseau interne.
- **Client** : tout hôte avec `enable = true` qui déclare des `targets`
  (destinations de sauvegarde).

```d2

direction: down

  shape: person
}

passphrase: Passphrase de dépôt\nrestic-password-<zone> {
  shape: hexagon
}
cred: Credential REST\nrestic/<hôte>/rest-password {
  shape: hexagon
}

local: Disque local\n/mnt/backup {
  shape: cylinder
}

  shape: cylinder
}

client -> server: cible rest:// (authentifiée)

passphrase -> client: chiffre le contenu {
  style.stroke-dash: 4
}
cred -> server: contrôle l'accès {
  style.stroke-dash: 4
}
```

<Aside type="caution" title="Deux mots de passe à ne pas confondre">
- **Passphrase de dépôt** `restic-password-<zone>` : chiffre le *contenu* du
  dépôt. Sans elle, aucune restauration n'est possible.
- **Credential REST** `restic/<hôte>/rest-password` : *authentifie* l'hôte
  auprès du serveur REST. Un par hôte.

Les deux sont générés par `just configure-admin-host` (voir plus bas).
</Aside>

Disposition d'un dépôt : un dépôt par catégorie, nommé d'après elle.

```
<racine>/<hôte>/system  # catégorie "system" (/ moins les exclusions)
<racine>/<hôte>/nfs     # catégorie "nfs"    (/srv/nfs/<...>)
<racine>/<hôte>/medias  # catégorie "medias" (/srv/medias/<...>)
```

<Aside type="caution" title="Le chemin de dépôt fait exactement deux niveaux">
`rest-server` ne sert que les dépôts situés **deux composants** sous son
répertoire de données : `<hôte>/medias` répond, `<hôte>/srv/medias` renvoie
404 — et restic affiche alors le message trompeur `repository does not exist`
alors que les données sont intactes.

Le sous-chemin est donc le **nom de la catégorie**, jamais le répertoire
source. Cette disposition étant identique en local et en REST, un dépôt peut
passer de l'un à l'autre sans être renommé.
</Aside>

<Aside type="danger" title="Dépôts créés avant cette disposition">
Les dépôts écrits quand le sous-chemin recopiait le répertoire source se
trouvent sous `<hôte>/srv/nfs` ou `<hôte>/srv/medias`. Les renommer sur le
serveur **avant la prochaine exécution** : `initialize` valant `true`, restic
créerait sinon un dépôt vide au nouveau chemin et repartirait silencieusement
sur une sauvegarde complète — plusieurs To sur une liaison lente.

```sh
mv <données>/<hôte>/srv/medias <données>/<hôte>/medias
rmdir <données>/<hôte>/srv
```

Renommage au sein du même système de fichiers : instantané, aucune donnée
déplacée, historique et incrémentalité préservés.
</Aside>

## Monter un serveur de sauvegarde

<Steps>

1. Dans `etc/config.yaml`, ajouter le service `restic` à l'hôte serveur :

   ```yaml
   services:
     restic:
   ```

2. Brancher le disque de sauvegarde et le monter sur `/mnt/backup` dans la
   configuration de l'hôte (`usr/machines/<hôte>/`), avec l'option `nofail` :

   ```nix
   fileSystems."/mnt/backup" = {
     device = "/dev/disk/by-uuid/<uuid>";
     fsType = "ext4";
     options = [ "nofail" ];
   };

   # Le serveur REST ne démarre qu'une fois le disque monté.
   systemd.services.restic-rest-server = {
     requires = [ "mnt-backup.mount" ];
     after = [ "mnt-backup.mount" ];
   };
   ```

3. Le dépôt est stocké sous `serverDataDir` (défaut `/mnt/backup/restic`).
   Le pare-feu ouvre le port REST sur l'interface interne automatiquement.

4. Si des clients d'**autres zones** doivent y accéder par le tailnet, ajouter
   `listenAll` : le serveur n'écoute par défaut que sur l'adresse LAN de
   l'hôte, invisible depuis le VPN.

   ```nix
   darkone.service.restic = {
     enable = true;
     enableServer = true;
     listenAll = true;
   };
   ```

</Steps>

<Aside type="note" title="Serveur = client aussi">
Un serveur peut sauvegarder ses propres données en pointant un `target` vers son
disque local (`root = "/mnt/backup/restic"`).
</Aside>

<Aside type="caution" title="restic-rest-server.service inactive : c'est normal">
Le serveur REST est activé par socket. `restic-rest-server.service` reste donc
`inactive` tant qu'aucun client ne s'est connecté — après chaque démarrage, et
aussi longtemps qu'un disque en `x-systemd.automount` reste inutilisé (le
`requires` sur le montage fait alors arrêter le démon pour démonter). C'est
`restic-rest-server.socket`, toujours à l'écoute, qui porte la surveillance
`ServiceDown` ; un démon qui plante reste couvert par `SystemdUnitFailed`.
</Aside>

## Ajouter un client

Déclarer une ou plusieurs `targets` dans la configuration de l'hôte :

```nix
darkone.service.restic = {
  enable = true;
  targets = [
    {
      # Dépôt distant via le serveur REST de la zone.
      root = "rest:http://restic.home.example.net:8888";
      zone = "home";
      categories = [ "system" "nfs" ];
    }
  ];
};
```

Champs d'un `target` :

| Champ        | Rôle                                                       |
| ------------ | ---------------------------------------------------------- |
| `name`       | Identifiant (défaut `main`), suffixe des jobs/units.       |
| `root`       | Chemin local ou URL `rest://`.                             |
| `zone`       | Zone qui choisit la passphrase `restic-password-<zone>`.   |
| `categories` | Données sauvegardées : `system`, `nfs`, `medias`.          |

<Aside type="tip" title="Plusieurs destinations">
Ajouter un second `target` (autre `name`, autre `root`/`zone`) pour répliquer la
sauvegarde, par exemple vers le serveur REST d'une autre zone.
</Aside>

## Sauvegarder hors-site

Une seconde `target` vers le serveur REST d'une autre zone donne le « 1 » de la
règle 3-2-1. Deux précautions propres au hors-site.

**Adresser le serveur par son IP tailnet**, jamais par son nom de zone :

```nix
{
  name = "offsite";
  root = "rest:http://100.64.0.20:8888";
  zone = "home";
  categories = [ "system" ];
}
```

Un nom comme `restic.<zone-distante>.example.net` n'est résolu que par la
passerelle de cette zone. Si le site distant tombe, le résolveur tombe avec lui
et la panne se présente comme une **erreur de résolution de noms**, ce qui
égare le diagnostic. L'IP tailnet supprime cette indirection, ainsi que la
dépendance à la route de sous-réseau du site distant. Elle exige `listenAll`
côté serveur (voir plus haut).

<Aside type="note" title="Un serveur hors-site absent ne met pas l'unité en échec">
Chaque cible `rest:` porte une sonde de joignabilité (`ExecCondition`). Serveur
injoignable&nbsp;: l'unité est **sautée**, pas mise en échec — aucune alerte
`SystemdUnitFailed` nocturne, pas de quart d'heure de tentatives restic, et
aucune création de dépôt vide contre une adresse morte. La sauvegarde manquante
reste signalée par `ResticBackupStale` (36&nbsp;h) puis `ResticBackupCritical`
(7&nbsp;jours), qui surveillent la date du dernier succès. Le journal indique
alors `Skipped due to ExecCondition=`.
</Aside>

## Générer les mots de passe

La génération des [secrets internes](/fr/doc/admin-guide/operate/secrets/#secrets-internes-et-secrets-externes)
est idempotente&nbsp;: elle crée ce qui manque, jamais d'écrasement.

```bash
just configure-admin-host
```

Elle génère, dans `usr/secrets/secrets.yaml` :

- une passphrase `restic-password-<zone>` par zone ;
- un credential `restic/<hôte>/rest-password` par hôte du parc.

<Aside type="note" title="Nouvel hôte">
Relancer `just configure-admin-host` après l'ajout d'un hôte, puis redéployer
les serveurs pour qu'ils prennent en compte son nouveau compte REST.
</Aside>

## Lancer une sauvegarde manuellement

Le module crée un service systemd par couple cible × catégorie, nommé
`restic-backups-<catégorie>-<nom>` (le `<nom>` vient du champ `name` du target,
`main` par défaut). Exemples : `restic-backups-system-main`,
`restic-backups-nfs-main`.

<Steps>

1. Lister les services de sauvegarde présents sur l'hôte :

   ```bash
   systemctl list-units 'restic-backups-*'
   ```

2. Déclencher une sauvegarde immédiate, sans attendre le timer :

   ```bash
   sudo systemctl start restic-backups-system-main.service
   ```

3. Suivre son déroulement en direct :

   ```bash
   journalctl -fu restic-backups-system-main.service
   ```

</Steps>

<Aside type="tip" title="Simuler sans rien écrire">
Poser `darkone.service.restic.enableDryRun = true` ajoute `--dry-run` à tous les
jobs : la sauvegarde est jouée à blanc, aucun snapshot n'est créé.
</Aside>

## Isolation des dépôts

Le serveur REST tourne en dépôts privés (`privateRepos = true`) : chaque hôte
n'accède qu'au dépôt dont le chemin commence par son propre nom d'hôte. Le
module aligne automatiquement le compte REST (`<hôte>`) sur le préfixe du dépôt
 (`<racine>/<hôte>/...`), donc l'isolation est permanente → aucun réglage à
activer. Une tentative d'accès au dépôt d'un autre hôte renvoie une erreur
**403**.

## Restaurer

Sur l'hôte concerné, les secrets sont déjà en place. Lister puis restaurer :

```bash
# Adapter la zone du dépôt (et la catégorie : system, nfs, medias).
ZONE=home

# Variables d'accès REST (générées par sops) et passphrase de dépôt.
set -a; . /run/secrets/rendered/restic-rest-env; set +a
export RESTIC_PASSWORD_FILE=/run/secrets/restic-password-$ZONE
export RESTIC_REPOSITORY=rest:http://restic.$ZONE.example.net:8888/$(hostname)/system

restic snapshots
restic restore latest --target /restore
```

<Aside type="caution" title="Adapter zone et catégorie">
Renseigner `ZONE` avec la zone du dépôt et remplacer `system` dans
`RESTIC_REPOSITORY` par la catégorie (`nfs`, `medias`) à restaurer.
</Aside>

## Vérifier

<Steps>

1. Sur un serveur, un compte par hôte du parc dans le fichier htpasswd :

   ```bash
   sudo cut -d: -f1 /run/restic-rest/htpasswd
   ```

2. Sur un client, lancer une sauvegarde manuelle (voir plus haut) et vérifier
   qu'elle se termine sans erreur.

3. Isolation : depuis un client, l'accès au dépôt d'un autre hôte doit être
   **refusé** (erreur 401/403).

</Steps>
