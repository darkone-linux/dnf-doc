Un utilisateur a perdu l'accès à son compte. Avant d'agir, identifier **lequel**
des trois mots de passe est en cause (ils sont indépendants), et le
[parcours](/fr/doc/admin-guide/operate/onboarding/#choisir-un-parcours) suivi à
la création du compte.

{/* t:p ae90d566c2871e797c39bb6e33a3100a567665d05f8e1144aaa74b9e6fd0d00d */}
## Trois mots de passe distincts

| Mot de passe | Sert à | Où le réinitialiser |
|---|---|---|
| **Identité** (Kanidm) | Se connecter aux services (SSO) | [Lien Kanidm](#identité-kanidm) |
| **Coffre-fort** (Vaultwarden) | Déverrouiller le gestionnaire de mots de passe | [Récupération de compte](#coffre-fort) |
| **Session** (NixOS) | Ouvrir une session sur un poste | [`just passwd`](#mot-de-passe-de-session) |

{/* t:p 02ae423fa43bbfaa02c352b026830679ee246471f5bca95df285f80bfdeff87f */}
## Identité (Kanidm)

<Steps>

1. Créer un lien de réinitialisation sur le serveur de coordination&nbsp;:

   ```bash
   just enter hcs
   kanidm person credential create-reset-token <login> --name idm_admin
   ```

2. Selon le parcours&nbsp;:
   - **Non technique** : ouvrir le lien soi-même, redéfinir mot de passe et TOTP, mettre à jour l'élément de sa collection.
   - **Technique** : transmettre le lien ou le QR-code à l'utilisateur.

</Steps>

## Coffre-fort

Le mot de passe principal chiffre le coffre&nbsp;: aucun serveur ne le connaît.

| Situation | Remède |
|---|---|
| **Mot de passe oublié**, parcours non technique | Organisation → *Membres* → *Récupérer le compte* |
| **Mot de passe oublié**, sinon | *Delete User* dans `/admin`, puis nouvelle invitation |
| **2FA perdue** | *Remove all 2FA* dans `/admin` |

:::note[Après une récupération de compte]
L'administrateur fixe un nouveau mot de passe principal et le transmet.
Vaultwarden n'impose pas de le changer&nbsp;: le conseiller à l'utilisateur.
:::

:::danger[Supprimer un compte détruit son coffre personnel]
Seuls les éléments des collections partagées survivent. Une nouvelle
invitation n'est pas une réinitialisation&nbsp;: *Resend invite* ne fonctionne
que tant que l'invitation n'a pas été acceptée.
:::

## Mot de passe de session

Le mot de passe d'ouverture de session sur un poste est géré dans les
[secrets](/fr/doc/admin-guide/operate/secrets/), pas dans Kanidm :

<Steps>

1. **Définir l'empreinte**

   ```bash
   just passwd <login>
   ```

   Parcours technique&nbsp;: l'utilisateur saisit lui-même le mot de passe, ou
   envoie son empreinte (voir [le parcours](/fr/doc/admin-guide/operate/onboarding/#parcours-technique)).

2. **Valider et déployer**

   ```bash
   just commit "user(passwd): <login>"
   just apply @user-<login>
   ```

</Steps>

:::note[Mot de passe par défaut]
`just passwd-default` enregistre le mot de passe de référence du parc, sans
configurer aucun compte : un compte neuf n'ouvre de session qu'après
`just passwd <login>`. Voir [Utilisateurs](/fr/doc/admin-guide/operate/users/).
:::

:::tip[YubiKey]
Une YubiKey enrôlée (`just yubikey <login>`) permet d'ouvrir la session sans
mot de passe, pratique en attendant la réinitialisation. Voir
[Authentification forte](/fr/doc/admin-guide/operate/yubikey/).
:::
