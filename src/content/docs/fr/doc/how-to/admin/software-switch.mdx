Un hôte peut prêter ses ports réseau libres à sa zone. Une machine branchée
dessus est dans la zone comme derrière un switch matériel&nbsp;: DHCP et DNS de
la passerelle, aucune configuration de son côté.

{/* t:p 4eb8f46896fbd24a7bd1826175fadbfb63ff5fa3f386f84db9f537a6130a3c5c */}
## Principe

```d2
style.fill: transparent
direction: right

gw: Passerelle
host: Hôte switch {
  br0: Pont br0
}
a: Machine A
b: Machine B

gw -> host.br0: uplink
host.br0 -> a: downlink
host.br0 -> b: downlink
```

- **Pont `br0`** : regroupe l'uplink (vers la zone) et les downlinks (ports libres).
- **Adresse de l'hôte** : portée par `br0`, en DHCP, avec la MAC de l'uplink.
- **Niveau 2 pur** : pas de STP, pas de filtrage par le pare-feu de l'hôte.
- **Dès l'initrd** : l'aval garde le réseau pendant l'attente du [déverrouillage LUKS](/fr/doc/admin-guide/operate/luks/).

L'hôte passe sur systemd-networkd. Une passerelle de zone ou un hôte sous
NetworkManager ne peut pas être switch&nbsp;: l'évaluation le refuse.

{/* t:p 3ca659a2a5a256b6c856da4019741347cece615d69158d1c14c67a40eb37a5c0 */}
## Mise en place

<Steps>

1. **Une seule MAC**

   Dans `etc/config.yaml`, `mac` ne garde que l'adresse de l'uplink&nbsp;: le
   pont la reprend, la réservation DHCP suit le pont.

   ```yaml
   # etc/config.yaml
   - hostname: "srv"
     zone: "maison:1.2"
     mac: "02:00:00:00:00:01"
   ```

   Puis `just generate`.

2. **Déclarer le switch**

   ```nix
   # usr/machines/srv/configuration.nix
   darkone.system.network.switch = {
     enable = true;
     uplink = "enp1s0f1";
     downlinks = [
       "enp1s0f0" # 10 GbE
       "enp2s0"
     ];
   };
   ```

3. **Appliquer au redémarrage**

   `just apply srv boot`, puis redémarrer. Un `switch` ferait entrer l'uplink
   dans le pont en pleine activation, et couperait la session SSH.

4. **Vérifier**

   `ip -br addr` montre l'adresse sur `br0`, `bridge link` les ports du pont.

</Steps>

## FAQ

{/* t:p 0e43bfa3bdd6722d9ca9d71f4880814ea21ac1855e58917c9c4964d40609c71f */}
### Les machines en aval perdent-elles le réseau ?

Oui, pendant que l'hôte redémarre (firmware, noyau). Le pont revient dès
l'initrd, avant le déverrouillage du disque.

{/* t:p 8725957d95179bd1b370895c83b6abc94328e60eb305f86637682e9389a4a0b4 */}
### Pourquoi une seule MAC ?

Le pont doit reprendre l'adresse de l'uplink, et l'évaluation ne peut pas
deviner laquelle des MAC c'est. Plusieurs MAC ou aucune → l'évaluation échoue.

{/* t:p 19f623d3332feeff6c8089631698a18f8aa294c1daf6733358cbc8e773e9c14c */}
### Peut-on relier deux ports au même switch ?

Non&nbsp;: sans STP, deux ports sur le même segment forment une boucle.

{/* t:p 626b006e14f6957976bfb0197d335669818c956ff621e634147430be82397bb1 */}
### Quel débit attendre ?

Le trafic ponté traverse le processeur de l'hôte, et l'uplink est partagé avec
ses propres échanges. Mesurer de bout en bout avec `iperf3`.
