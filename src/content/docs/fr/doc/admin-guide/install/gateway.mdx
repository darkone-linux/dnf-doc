Une [zone](/fr/doc/admin-guide/understand/concepts/) est un sous-réseau, qui
comporte une **passerelle**, derrière laquelle on branche autant de machines
qu'on veut. La première passerelle s'installe **depuis le poste
d'administration, posé à côté d'elle**, sans serveur de coordination.

`darkone add gateway` fait tout depuis le poste d'administration&nbsp;:
appairage de la machine, déclaration dans `etc/config.yaml`, installation,
recâblage, contrôles. La [variante manuelle](#variante-manuelle) reste
possible.

## Le matériel

La passerelle est idéalement installée sur un mini-ordinateur toujours allumé,
avec **au moins deux interfaces réseau** : une vers la box (WAN), les autres
vers le réseau local (LAN, ethernet ou wifi).

:::note[Quel matériel ?]
Par exemple, boîtier [Protectli](https://eu.protectli.com/) ou équivalent&nbsp;:

- Disque NVMe ≥ 256 Go
- BIOS coreboot de préférence
- Carte wifi en option
:::

## Câblage

Le WAN de la passerelle va sur la box&nbsp;; tout le réseau local passe
derrière elle.

```d2
style.fill: transparent
direction: right

internet: Internet { shape: cloud }
box: Box
wifi: "Wi-Fi de la box\n(hors zone)" { shape: oval }

zone: "Zone" {
  gw: Passerelle
  switch: Commutateur
  pcs: "Postes\n(dont le poste d'administration)"
  ap: "Point d'accès\nWi-Fi"
  gw -> switch: LAN
  switch -> pcs
  switch -> ap
}

internet -> box
box -> zone.gw: WAN
box -> wifi { style.stroke-dash: 3 }
```

- Le Wi-Fi de la box reste **hors de la zone** : ses appareils ne reçoivent pas
  d'adresse de la passerelle.
- Un point d'accès Wi-Fi se branche **derrière** la passerelle, sans DHCP.
- Le commutateur est facultatif&nbsp;: un poste peut se brancher sur un port LAN.

## Installer avec l'assistant

`darkone add gateway` se lance sur le poste d'administration, dans le projet
(`/etc/nixos`). Il ne demande que l'adresse de la machine et son code.

:::caution[Version du générateur]
`darkone add` arrive avec une release du générateur postérieure à la v0.4.0.
Avec une version plus ancienne, la commande n'existe pas&nbsp;:
[variante manuelle](#variante-manuelle).
:::

<Steps>

1. **Brancher**

   Le WAN de la passerelle sur la box. Le poste d'administration **reste sur
   la box** (câble ou Wi-Fi).

2. **Démarrer**

   Sur l'ISO générique, [gravée sur une clé USB](/fr/doc/admin-guide/install/first-network-installation/#préparer-la-clé),
   entrée *2) Add this machine to an existing network* du menu (ou
   `dnf-pair`). L'écran donne l'adresse et le code d'appairage&nbsp;:

   ```text
   - IP: 192.168.1.50

   Pairing code: 123456-7890  (10 min, a new one after)
   ```

3. **Lancer**

   ```sh
   cd /etc/nixos
   darkone add gateway
   ```

   L'assistant demande l'adresse, puis le code. Il sonde la machine et propose
   le nom (`gw`), le WAN (la carte qui porte la route vers la box), le LAN (les
   autres cartes filaires) et le disque (une question s'il y en a plusieurs).

4. **Confirmer**

   Le récapitulatif nomme le disque effacé et les choix définitifs. Vient
   ensuite le diff de `etc/config.yaml`, avec une seconde confirmation&nbsp;:
   rien n'est écrit avant.

5. **Recâbler**

   À l'invite *Now unplug this machine from the box and plug it into a LAN
   port of gw*, brancher le poste d'administration sur un port LAN de la
   passerelle. L'assistant reprend seul, applique ce poste (`just apply-local`)
   et contrôle le réseau.

</Steps>

Le message final, *Step 2 of 4 done*, annonce l'étape 3.

:::caution[À valider]
L'enchaînement complet est testé de bout en bout en machines virtuelles (box
simulée, passerelle à deux cartes), pas encore sur du matériel.
:::

### Le code d'appairage

Le code `PPPPPP-FFFF` prouve que l'adresse tapée est la bonne machine avant
l'envoi de la moindre clé.

| Partie | Rôle |
|---|---|
| `PPPPPP` | mot de passe `nixos`, à usage unique, valable 10 min |
| `FFFF` | empreinte de la clé d'hôte, vérifiée par le poste |

Le poste calcule `FFFF` depuis la clé qu'il lit sur le réseau&nbsp;: si elle
diffère, rien n'est envoyé. Sinon il pousse sa clé de déploiement
(`usr/secrets/nix.pub`) et verrouille le mot de passe&nbsp;; l'écran affiche
*Paired*. La clé d'hôte vérifiée est ensuite tenue jusqu'à la fin de
l'installation. Une machine déjà appairée ne redemande pas de code.

### Plan à blanc, réponses

`--dry-run` appaire et sonde la machine, puis affiche le plan, le diff de
`etc/config.yaml` et les commandes d'une vraie exécution. Rien n'est écrit dans
le projet&nbsp;; la machine, elle, reste appairée.

Un fichier de réponses remplace les questions. Le code d'appairage n'y entre
jamais&nbsp;: il se tape sur le terminal.

```yaml
# reponses.yaml
version: 1
address: "192.168.1.50"           # adresse affichée par la machine
host:
  hostname: "gw"                  # facultatif
nics:
  wan: "enp1s0"                   # facultatif : la carte qui porte la route
  lan: ["enp2s0"]                 # toujours à donner
disk:
  device: "/dev/disk/by-id/nvme-Example_SSD_256GB_S4EXAMPLE0001"  # facultatif : un seul disque ≥ 20 Go
confirm: true                     # exigé avec --non-interactive
```

```sh
darkone add gateway --answers reponses.yaml --dry-run
darkone add gateway --answers reponses.yaml --non-interactive
```

- `confirm: true` saute les deux confirmations (le diff reste affiché)&nbsp;;
  sans lui, `--non-interactive` refuse de commencer.
- Une clé inconnue est refusée&nbsp;; toutes les erreurs sont listées d'un coup.

### Refus

L'assistant refuse **avant d'écrire** quand&nbsp;:

| Cas | À faire |
|---|---|
| Dépôt non propre | commiter ou remiser |
| Passerelle déjà là, ou plusieurs zones | déclarer à la main |
| Réseau de la box dans la zone | changer le réseau de la box |
| Moins de deux cartes filaires | prendre une machine à deux cartes |
| Machine en BIOS | passer le firmware en UEFI |

Le préfixe de la zone est définitif&nbsp;: si la box le recouvre, c'est elle qui
bouge. La disposition `server-1-disk` exige l'UEFI. Les disques de moins de
20&nbsp;Go (clé USB) ne sont pas proposés.

### Écrit dans le projet

Après confirmation, l'assistant écrit dans `etc/config.yaml` le bloc `gateway`
de la zone et l'hôte `gw` (`<zone>:1.1`). Le poste d'administration reçoit son
adresse fixe (`<zone>:2.1`) et sa `mac` si elles manquent. Puis `just clean`
et le commit `chore(gateway): add gw`.

### Reprise après échec

Le message d'échec liste les commandes restantes, dans l'ordre.

| Échec | État | Reprise |
|---|---|---|
| Avant l'écriture | rien de changé | relancer |
| `just clean`, commit | fichier écrit, rien de commité | suite à la main, ou `git stash --include-untracked` puis relancer |
| `just full-install` | déclaration commitée | `just full-install gw nixos <ip>`, puis `just apply-local` |
| `just apply-local` | passerelle installée | `just apply-local` |
| Contrôles | passerelle installée | le remède suit chaque contrôle |

Une fois la déclaration commitée, `darkone add gateway` refuse de rejouer (la
zone a sa passerelle)&nbsp;: la reprise est à la main, et repose la question de
formatage. Les contrôles vérifient la route par défaut (la passerelle), la
résolution de `gw` et l'accès à Internet.

## Variante manuelle

Sans l'assistant, la même installation se fait recette par recette&nbsp;: la
déclaration dans `etc/config.yaml` précède `just full-install`.

### Préparer la passerelle

<Steps>

1. **Brancher**

   Le WAN de la passerelle sur la box. Le poste d'administration **reste sur
   la box** (câble ou Wi-Fi).

2. **Démarrer**

   Sur l'ISO, [gravée sur une clé USB](/fr/doc/admin-guide/install/first-network-installation/#préparer-la-clé).
   L'écran donne ce qu'il faut déclarer&nbsp;:

   ```text
   - IP: 192.168.1.50
   - MAC: aa:bb:cc:dd:ee:01

   Network cards (wan.interface, lan.interfaces):
     NAME    MAC                LINK  IPV4             NOTE
     enp1s0  aa:bb:cc:dd:ee:01  up    192.168.1.50/24  default route (WAN)
     enp2s0  aa:bb:cc:dd:ee:02  down  -

   Disks (disko.devices), installation medium left out:
     /dev/disk/by-id/nvme-Example_SSD_256GB_S4EXAMPLE0001
         239G  Example SSD 256GB  [nvme0n1]
   ```

   | Ligne | Sert à |
   |---|---|
   | `- IP:` | `just full-install` |
   | *Network cards* | `wan.interface`, `lan.interfaces` |
   | *Disks* | `disko.devices` (chemin à copier) |

   La carte marquée *default route (WAN)* porte la route vers la box&nbsp;:
   c'est le WAN, les autres câblées sont le LAN. `dnf-netinfo` réaffiche
   l'écran. Avec l'ISO générique, l'entrée du menu *2) Add this machine to an
   existing network* affiche les mêmes tableaux.

   L'écran affiche aussi le code d'appairage (`Pairing code: PPPPPP-FFFF`)&nbsp;:
   `just full-install` le demande à l'étape 4, rien à autoriser avant. L'image
   `just build-iso` porte déjà la clé&nbsp;: pas de code.

</Steps>

### Déclarer la zone

Tout se déclare **avant** l'installation&nbsp;: la passerelle naît avec la
réservation du poste d'administration, qui reçoit son adresse fixe dès le
recâblage.

<Steps>

3. **Déclarer**

   Dans `etc/config.yaml`&nbsp;: le bloc `gateway` de la zone, l'hôte `gw`, et
   une adresse fixe pour le poste d'administration.

   ```yaml
   # etc/config.yaml
   zones:
     main:
       description: "Main network"
       ipPrefix: "10.0"             # zone en 10.0.0.0/16
       gateway:
         wan:
           interface: "enp1s0"      # carte vers la box
         lan:
           interfaces: ["enp2s0"]   # cartes vers le réseau local

   hosts:
     - hostname: "gw"
       name: "Passerelle"
       zone: "main:1.1"             # IP fixe 10.0.1.1
       profile: "gateway"
       disko:
         profile: "server-1-disk"
         devices:
           main: "/dev/disk/by-id/nvme-Example_SSD_256GB_S4EXAMPLE0001"

     - hostname: "admin"            # le poste d'administration
       zone: "main:2.1"             # était "main" : IP fixe 10.0.2.1
       mac: "aa:bb:cc:dd:ee:ff"     # inchangée
       # … le reste est inchangé
   ```

   Pas de `mac` pour la passerelle&nbsp;: son adresse LAN est fixe (`1.1`) et
   son adresse WAN vient de la box.

   ```sh
   just clean
   git add . && git commit -m "host(gw): passerelle"
   ```

</Steps>

:::tip[Services et liaisons de secours]
Le profil `gateway` câble le routeur, le pare-feu, le DNS/DHCP (`dnsmasq`) et le
client VPN (voir [Réseau](/fr/doc/admin-guide/understand/network/)). Les
services (adguardhome, homepage…) se déclarent sous `services:`. Un port libre
ou une carte wifi peut servir de
[liaison de secours](/fr/doc/how-to/admin/gateway-backup-links/).
:::

### Installer la passerelle

<Steps>

4. **Installer**

   ```sh
   just full-install gw nixos 192.168.1.50
   ```

   - `gw` : nom d'hôte déclaré.
   - `nixos` : utilisateur de l'ISO.
   - `192.168.1.50` : la ligne `- IP:` de l'écran.

   Avant la question de formatage, la recette annonce le recâblage&nbsp;:
   *get the cable ready now*. Le disque est ensuite formaté, le système
   installé, puis la passerelle redémarre.

   Si le réseau de la box chevauche celui de la zone (la box dans
   `10.0.0.0/16`), la recette refuse **avant tout formatage**&nbsp;: WAN et LAN
   seraient sur le même réseau.

   ```text
   Cannot install gw on 10.0.0.50: the box network (10.0.0.0/24 on enp1s0) overlaps
   zone 'main' (10.0.0.0/16), so its WAN and LAN would share one network.
   ```

   Le préfixe de la zone est définitif&nbsp;: changer le réseau de la box
   (sous-réseau ou plage DHCP), redémarrer l'ISO, recommencer.

5. **Recâbler**

   À l'invite *Now unplug this machine from the box and plug it into a LAN
   port of gw*, débrancher le poste d'administration de la box et le brancher
   sur un port LAN de la passerelle (ou du commutateur). Rien à presser&nbsp;:
   la recette attend jusqu'à 30 minutes que `10.0.1.1` réponde, puis enchaîne
   `configure`, `apply` et un dernier redémarrage.

   Sans réponse après 30 minutes&nbsp;:

   ```sh
   just configure gw 10.0.1.1
   just apply gw
   ```

   Cette pause n'a lieu que si la passerelle garde son SSH fermé côté box
   (coordination inactive, ou `gateway.vpn.ipv4` déjà déclaré)&nbsp;: voir
   [Accès SSH selon le
   rôle](/fr/doc/admin-guide/understand/network/#accès-ssh-selon-le-rôle).

6. **Finir**

   ```sh
   just apply-local
   ```

   Le poste d'administration prend son adresse fixe (`10.0.2.1`).

</Steps>

:::caution[À valider]
Essayée en machines virtuelles, poste câblé&nbsp;: le poste prend un bail de la
passerelle dès le recâblage, et `gw` se résout. Reste à confirmer sur une vraie
installation&nbsp;: poste sur le Wi-Fi de la box **et** câblé au LAN,
`10.0.1.1` répond sans rien débrancher.
:::

## Chiffrement du disque

Pour une première passerelle, **préférer un disque en clair** (`server-1-disk`)&nbsp;:
elle redémarre seule après une coupure de courant, sans quoi le réseau reste
coupé tant que personne ne tape la passphrase. Le chiffrement et le
déverrouillage à distance sont décrits dans
[Chiffrement des disques (LUKS)](/fr/doc/admin-guide/operate/luks/).

:::caution[À valider : passerelle chiffrée]
Le déverrouillage se ferait côté box avant le recâblage, puis côté LAN au
dernier redémarrage. En câble direct, le poste peut perdre son adresse pendant
l'initrd (pas de DHCP)&nbsp;: sinon, passphrase à la console.
:::

## Installer depuis une autre zone

Une passerelle se prépare souvent ailleurs que chez son destinataire. Branchez
son interface **WAN** au réseau local de la zone d'accueil&nbsp;: elle y reçoit
l'adresse de passage que cette zone lui réserve sur sa MAC. Ici, la clé `mac`
de la passerelle (ligne `- MAC:` de l'écran de l'ISO) reste utile.

Trois conditions&nbsp;:

- la clé `mac` de la passerelle est déclarée dans `etc/config.yaml`&nbsp;;
- la passerelle de la zone d'accueil a été redéployée depuis cette déclaration ;
- la machine d'administration aussi, pour que SSH lise la redirection posée
  pendant l'installation.

Ensuite, `just full-install gw` se passe d'adresse&nbsp;: l'outillage calcule la
cible et la suit d'un bout à l'autre. Le principe est décrit dans [Machines hors
de leur zone](/fr/doc/admin-guide/understand/network/#machines-hors-de-leur-zone).

:::note[Une fois la passerelle livrée]
Sur place, elle reprend l'adresse fixe de sa zone (`.1.1`). La redirection SSH
posée pour l'installation ne sert plus&nbsp;: `just roaming-clear gw`.
:::

## Installer à distance

Une personne sur place branche la passerelle à la box et la démarre sur l'image
`just build-iso` (elle porte la clé de déploiement)&nbsp;; l'administrateur
installe par SSH. Cette voie suppose la **coordination (HCS) active** et
`gateway.vpn.ipv4` non déclaré&nbsp;: sinon le SSH reste fermé côté box une fois
la passerelle installée.

<Steps>

1. **Rediriger** le port 22 de la box vers la passerelle.
2. **Installer** avec l'adresse IP publique de la box&nbsp;:
   `just full-install gw nixos <ip-publique>`.
3. **Retirer la redirection** après avoir déclaré `gateway.vpn.ipv4` et
   appliqué&nbsp;: la passerelle ne répond plus depuis Internet, l'accès passe
   par le VPN (`just enter gw`).

</Steps>

## Enregistrer la passerelle sur le VPN

Une passerelle est un **client Tailscale** : elle publie le sous-réseau de sa
zone dans le [tailnet](/fr/doc/admin-guide/understand/tailnet/). Tant qu'elle n'y
est pas enrôlée, les autres zones ne la voient pas. `just full-install` l'enrôle au
passage&nbsp;; sinon, ou pour vérifier&nbsp;:

```sh
just tailnet-enroll gw
```

Reste à déclarer son adresse tailnet : voir [Enregistrer une
passerelle](/fr/doc/admin-guide/operate/vpn/#enregistrer-une-passerelle).

## Remplacer le matériel

Changer l'ordinateur d'une passerelle en service relève d'une procédure
distincte&nbsp;: la machine est neuve, mais son état ne l'est pas. Voir [Migrer
le matériel d'une
passerelle](/fr/doc/admin-guide/install/gateway-hardware-migration/).

## FAQ

### Une faute de frappe sur le code ?

Un code faux coûte **10 secondes d'attente** (délai PAM), et l'assistant
accepte trois essais. Un code faux et un code expiré donnent le même refus&nbsp;:
relire l'écran. Après six codes de 10 minutes, l'appairage se ferme&nbsp;; la
commande `dnf-pair` de la machine en tire un nouveau.

### « not the machine whose screen shows this code » ?

L'empreinte `FFFF` du code ne correspond pas à la machine qui répond à cette
adresse&nbsp;: autre appareil du réseau, adresse mal relevée. Rien n'a été
envoyé&nbsp;; vérifier l'adresse sur l'écran.
