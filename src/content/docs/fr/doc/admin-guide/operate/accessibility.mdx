Les profils 🌳 `umi` (*Unified Multimodal Input*, saisie multimodale unifiée)
génèrent un poste de travail utilisable **sans clavier ni souris**. Il se
pilote par plusieurs moyens de saisie coordonnés entre eux&nbsp;: toucher, voix,
regard… L'objectif est l'accessibilité, notamment pour les personnes en
situation de handicap moteur.

Ils se composent de deux parties&nbsp;: un
[profil d'hôte](/fr/doc/admin-guide/understand/host-profiles/) `umi` qui
déclare le matériel et la session, et un
[profil d'utilisateur](/fr/doc/admin-guide/understand/user-profiles/) `umi`
qui fixe l'environnement de l'utilisateur.

## Le principe

Aucun moyen de saisie ne remplace seul le clavier et la souris&nbsp;: chacun a
ses limites (précision du regard, fatigue de la voix, amplitude du geste). Le
poste UMI les combine pour qu'ils se complètent, et se règle selon les capacités
de l'utilisateur.

| Moyen de saisie | Outil | Usage |
|---|---|---|
| Toucher | Écran tactile, clavier visuel Onboard | Désigner, cliquer, saisir du texte |
| Voix | Talon | Commandes vocales |
| Regard | Tobii Eye Tracker 5, piloté par Talon | Déplacer le pointeur |

Exemple de coordination&nbsp;: le regard place le pointeur, la voix ou le clic
par temporisation valide, le clavier visuel saisit le texte.

```d2
style.fill: transparent
direction: down

user: Utilisateur { shape: person }
touch: Écran tactile
mic: Micro
tracker: Tobii Eye Tracker 5
onboard: Clavier visuel Onboard

session: Session Cinnamon (X11)

user -> touch: Toucher
user -> mic: Voix
user -> tracker: Regard
touch -> onboard
touch -> session
mic -> talon
tracker -> talon
talon -> uinput
uinput -> session
onboard -> session
```

## Le matériel

Chaque périphérique sert un moyen de saisie&nbsp;: n'équiper le poste que de
ceux adaptés à l'utilisateur.

| Élément | Exigence |
|---|---|
| Traqueur oculaire | Tobii Eye Tracker 5 (USB, identifiant fabricant `2104`) |
| Architecture | `x86_64-linux` uniquement (Talon ne fournit pas d'autre binaire) |
| Micro | Nécessaire pour les commandes vocales |
| Haut-parleurs | Retour sonore des frappes du clavier visuel |
| Écran | Un bon écran tactile pour le contrôle du bureau et des applications |

:::caution[Premier démarrage sous Windows]
Le micrologiciel du Tobii 5 doit être initialisé **une fois** sur une machine
Windows, avec l'application Tobii Experience. Sans cette étape, le traqueur
reste muet sous Linux.
:::

## Mettre en place un poste

<Steps>

1. **Déclarer l'hôte et son utilisateur** dans `etc/config.yaml`, tous deux avec
   le profil `umi`&nbsp;:

   ```yaml
   # etc/config.yaml
   users:
     alice:
       uid: 1010
       name: "Alice"
       profile: "umi"
       groups: ["global"]

   hosts:
     - hostname: "umi-desktop"
       name: "Poste accessible"
       zone: "maison:2.3"
       profile: "umi"
       users: ["alice"]
   ```

   Sur l'hôte `umi`, le profil d'utilisateur ajoute le compte aux groupes
   `input` et `uinput`, sans lesquels Talon ne peut pas injecter d'événements.

2. **Activer l'ouverture de session automatique** dans la configuration de la
   machine, si l'utilisateur ne peut pas utiliser de clavier pour s'identifier&nbsp;:

   ```nix
   # usr/machines/umi-desktop/configuration.nix
   darkone.host.umi.autoLoginUser = "alice";
   ```

3. **Générer et déployer**&nbsp;:

   ```sh
   just generate
   just apply umi-desktop
   ```

4. **Tester et configurer**

   :::caution[Eye tracker : calibrer au premier lancement]
   Débrancher puis rebrancher le traqueur (les règles udev ne s'appliquent qu'au
   branchement), relancer Talon, puis lancer la calibration depuis son menu.
   :::

</Steps>

:::tip[Plusieurs utilisateurs sur la même machine]
Seul le compte listé dans `autoLoginUser` ouvre sa session tout seul. Tout
compte de l'hôte au profil `umi` ouvre la session Cinnamon, imposée à chaque
démarrage. Les comptes ordinaires gardent leur session GNOME Wayland habituelle.
:::

## Configurer l'hôte

Options de `darkone.host.umi`, à poser dans `usr/machines/<hôte>/configuration.nix`.

| Option | Défaut | Rôle |
|---|---|---|
| `enable` | activé par le profil | Active le profil d'hôte |
| `autoLoginUser` | `null` | Compte `umi` ouvert au démarrage |
| `package` | `pkgs.talon` | Paquet Talon, ou `null` pour l'installer à la main |

:::note[Talon absent ou non souhaité]
Avec `package = null`, tout le reste est configuré (udev, uinput,
accessibilité) et Talon peut être lancé manuellement depuis l'archive amont,
ce qui préserve sa mise à jour automatique.
:::

## Paramétrer l'utilisateur

Options de `darkone.home.umi`, à poser dans `usr/users/<login>/default.nix`.

| Option | Défaut | Rôle |
|---|---|---|
| `enable` | activé par le profil | Active le profil d'utilisateur |
| `enableTalonAutostart` | `true` | Lance Talon à l'ouverture de session |
| `communityScripts` | `null` | Arbre `talonhub/community` déployé dans `~/.talon/user/community` |
| `enableDwell` | `false` | Clic par temporisation permanent |
| `enableTrackerAuto` | `true` | Regard et clic suivent le traqueur |
| `gazeFilterSpeed` | `2.0` | Réactivité du regard (Talon&nbsp;: `1.0`) |
| `cursorFilterSpeed` | `4.0` | Réactivité du pointeur (Talon&nbsp;: `2.0`) |
| `enableHeadControl` | `false` | La tête déplace aussi le pointeur |
| `dwellTime` | `1.2` | Délai du clic par temporisation, en secondes |
| `panelHeight` | `64` | Hauteur du panneau Cinnamon, en pixels |
| `textScaling` | `1.4` | Facteur d'agrandissement du texte (Cinnamon) |
| `enablePanel` | `true` | Panneau imposé, réécrit à chaque déploiement |
| `panelLaunchers` | Fichiers, Firefox | Lanceurs du panneau (fichiers `.desktop`) |

:::caution[Le clic par temporisation suit le traqueur]
Sous Cinnamon, `enableTrackerAuto` active le pilotage du pointeur par le regard
et le clic par temporisation au branchement du traqueur, et coupe ce clic au
débranchement&nbsp;: **à la souris, il clique sur tout ce que le pointeur
survole**. `enableDwell` ne sert alors que sous GNOME.
:::

:::tip[Apports communautaires]
Les scripts communautaires `talonhub/community` apportent le zoom mouse et le
clic par claquement de langue. Ils se déclarent de façon reproductible&nbsp;:

```nix
# usr/users/alice/default.nix
{ pkgs, ... }:
{
  darkone.home.umi.communityScripts = pkgs.fetchFromGitHub {
    owner = "talonhub";
    repo = "community";
    rev = "…";
    hash = "…";
  };
}
```
:::

## Ce que le profil change

Le poste est volontairement dépouillé de tout ce qui suppose un clavier ou une
souris.

| Changement | Raison |
|---|---|
| Session Cinnamon en X11 | Talon ne fonctionne (malheureusement) pas sous Wayland |
| Ouverture de session automatique | Aucun mot de passe saisissable |
| Verrouillage et veille désactivés | Un écran verrouillé est un cul-de-sac |
| Trousseau de clés sans mot de passe | Évite une invite impossible à satisfaire (ouverture automatique, hôte non chiffré) |
| Accessibilité active dès l'ouverture | Aucune invite d'activation (Onboard) |
| Curseur, texte, panneau et icônes agrandis | Précision limitée du regard (quelques dizaines de pixels) et du doigt |
| Ouverture par simple clic (Nemo) | Un double clic par temporisation exige de changer de mode |
| Clavier visuel ancré en bas | Grandes cibles, prédiction de mots |
| Clavier visuel masqué au démarrage | Écran dégagé, affiché par son bouton |

:::danger[Le poste n'est pas protégé au démarrage]
Ouverture de session automatique, aucun verrouillage d'écran&nbsp;: quiconque
allume la machine est dans la session. Le seul rempart utile est le
[chiffrement du disque](/fr/doc/admin-guide/operate/luks/), à prévoir dès
l'installation si le poste est mobile.

L'ouverture de session par reconnaissance faciale est dans la liste TODO.
:::

:::note[Le trousseau suit le chiffrement du disque]
Seul le compte ouvert automatiquement est concerné&nbsp;: une connexion par mot de
passe déverrouille son trousseau comme d'habitude. Pour ce compte, tout dépend de
l'hôte&nbsp;:

- **poste non chiffré** : le trousseau est créé sans mot de passe, sinon la
  session s'ouvrirait sur une invite que personne ne peut satisfaire ;
- **poste chiffré (LUKS)** : la passphrase saisie au démarrage est transmise au
  trousseau par la pile PAM de l'ouverture de session automatique. Le trousseau
  reste protégé, et rien n'est demandé.

Conséquence sur un poste chiffré&nbsp;: changer la passphrase LUKS sans changer
celle du trousseau provoque le message « le mot de passe de connexion ne
correspond plus à celui de votre trousseau ». Supprimer alors
`~/.local/share/keyrings/login.keyring` et rouvrir la session.
:::

## Le panneau

Sous Cinnamon, `enablePanel` organise le panneau du bas pour le regard.

| Emplacement | Contenu |
|---|---|
| Gauche | Menu, lanceurs, fenêtres ouvertes |
| Droite | Types de clic, zone pause, regard |
| Puis | Accessibilité, clavier visuel |
| Enfin | Icônes d'état (Nextcloud…), horloge |

Les types de clic (simple, double, glisser, secondaire) et la zone pause
n'apparaissent que si le clic par temporisation est actif. La zone pause laisse
le regard explorer l'écran sans rien déclencher&nbsp;; les types de clic se
masquent pendant la pause.

| Action sur la zone pause | Effet |
|---|---|
| Clic, clics actifs | Suspend le clic par temporisation |
| Pointeur posé 1,5 s, en pause | Réactive les clics (barre verte) |
| Clic souris, en pause | Réactive les clics |

Le bouton regard (œil) coupe le pilotage du pointeur par le regard&nbsp;: les
yeux ne déplacent plus rien. Le rallumer à la souris, au toucher ou par
l'action Talon `user.umi_gaze`. Il est rallumé à chaque démarrage.

## Les autres comptes de l'hôte

Un compte ordinaire garde sa session GNOME Wayland, avec quelques différences
héritées de l'hôte&nbsp;:

- **Démarrage** : la machine ouvre la session du compte UMI. Fermer celle-ci ou
  changer d'utilisateur pour ouvrir la sienne.
- **Seahorse** : absent, car inutilisable sans clavier.
- **`su`** : ne transmet pas l'accès à l'écran, une invite (trousseau…) y
  bloquerait le compte UMI. Administrer par SSH ou depuis sa propre session.
- **Extinction** : chaque service a 5 secondes pour s'arrêter.

## Diagnostic

| Symptôme | Piste |
|---|---|
| Talon ne voit pas le traqueur | Rebrancher le traqueur, puis relancer Talon (règle udev appliquée au branchement) |
| Micrologiciel non initialisé | Repasser une fois par Tobii Experience sous Windows |
| Session ouverte sous GNOME | Vérifier le profil `umi` du compte et sa présence dans les `users` de l'hôte, puis redémarrer |
| Le pointeur clique tout seul | `enableDwell` activé sans traqueur, le désactiver |
| Le pointeur s'arrête avant le point regardé | Augmenter `gazeFilterSpeed` et `cursorFilterSpeed` |
| Le pointeur dépasse ou tremble | Les diminuer |
| Le pointeur suit les mouvements de tête | `enableHeadControl` à `false` |

:::note[Messages du noyau attendus]
Le traqueur expose deux interfaces vidéo que `uvcvideo` ne sait pas gérer, d'où
des messages `Unknown video format`, `No supported video formats found` et
`probe with driver uvcvideo failed with error -22`. Ils sont **normaux et
souhaitables**&nbsp;: aucun pilote noyau ne réclame les interfaces, ce qui les
laisse libres pour Talon.
:::

## FAQ

{/* t:p 49a3e63f83ac4ab8d59d9fec17b634755193ab5c7f83c6e469656b3b31c22450 */}
### Un compte UMI peut-il choisir GNOME ?

Non sur un hôte `umi`&nbsp;: la session Cinnamon est réimposée à chaque
démarrage, car Talon exige X11.

{/* t:p ac6c80b95349c7cebae6b778636b28afcda1c1826a5b6d551c7c87e914420339 */}
### Et sur un poste ordinaire ?

Le compte ouvre la session GNOME Wayland de l'hôte, avec le clavier visuel de
GNOME, le curseur et le texte agrandis. Talon et Onboard, qui exigent X11,
restent inactifs.
