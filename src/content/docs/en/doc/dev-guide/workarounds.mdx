The framework tracks nixpkgs unstable: a package breaks, a PR is slow. Every
workaround added while waiting for the upstream fix is registered in
`dnf/config/workarounds.nix`, and removed along with its entry.

{/* t:p 8acd71af1f3d102117c5d525ec3610b3c93b26f01949c30af1b5ee9f4bfe5c25 */}
## Registered workarounds

| `kind` | Workaround |
|---|---|
| `overlay` | Fix in `dnf/lib/overlays/` |
| `backport` | Module copied to `dnf/backports/nixos/` |
| `pin` | Package taken from another nixpkgs |
| `inline` | Workaround in a module |
| `insecure` | `permittedInsecurePackages` entry |

:::caution[Mandatory registration]
A unit test rejects an overlay, a backport or a `nixpkgs-*` input that is not registered, as well as an entry whose file or input has disappeared. It also rejects an overlay missing from the `dnf/lib/overlays/default.nix` list and a backport that `dnf/lib/flake/mk-configuration.nix` does not import: they would be registered but have no effect.
:::

{/* t:p ee513526ee5fd421756e8c2f07b65a54e6f053418e67359ddbe9ae658aa4594c */}
## An entry

```nix
# dnf/config/workarounds.nix
posthog = {
  kind = "overlay";
  files = [ "lib/overlays/posthog.nix" ];
  reason = "posthog marked broken since mcp 2: aider-chat refuses to evaluate";
  upstream = "NixOS/nixpkgs#578265"; # PR ou issue attendue
  package = "python3Packages.posthog"; # sondé sur unstable
  dropWhen = "nixpkgs#578265 in the locked nixpkgs";
  since = "2026-10-27";
};
```

`upstream`, `package` and `inputs` (flake inputs to remove along with it) are
optional. Omit `package` when a green build does not prove the fix
(a runtime crash, for example).

## Tracking upstream status

In `dnf/` or at the root of a co-development project:

```sh
just workarounds
```

- **upstream**: status of the PR or issue, via `gh`. A merged nixpkgs PR
  is compared with the locked revision.
- **unstable**: is the package, evaluated against the locked nixpkgs, built
  by [Hydra](https://hydra.nixos.org)? For a `pin`, the stable version is
  shown alongside.

```
gimp · overlay · since 2026-06-17  [drop?]
  why       gimp build breaks under `__structuredAttrs`
  unstable  gimp 3.2.6: built by Hydra
  drop      when Hydra builds unstable gimp
  files     lib/overlays/gimp.nix
```

`[drop?]` flags a lead, not a verdict: `dropWhen` decides.

## Remove a workaround

<Steps>

1. **Check** the `dropWhen` condition, rebuilding an affected host if needed.

2. **Delete** the workaround: files in `files`, wiring (overlay in `dnf/lib/overlays/default.nix`, backport in `dnf/lib/flake/mk-configuration.nix`), `inputs` of `dnf/flake.nix`.

3. **Unregister**: remove the entry from the registry.

4. **Validate**: `just clean`, `just unit-tests`, then commit.

</Steps>

## FAQ

### Overlay or suspension?

A broken service or library: overlay. A non-critical leaf application (game, office, education) already fixed upstream: commented line in its module, `inline` entry. No local build in the meantime.

```nix
#(lib.mkIf g3d veloren) # Minecraft like -> TMP: cargo system libs, back with nixpkgs#585129
```

{/* t:p 1ce1b8e169774b101122d8e3627c2c476945e409b1e7bc0655835f4fe95959a9 */}
### A permanent overlay?

An overlay that exposes a third-party flake's package (`talon`, `claude-code`)
is not a fix: add it to `permanentOverlays`, in
`dnf/tests/unit/config/workarounds_test.nix`.

{/* t:p b146fff9bc1618b8e590a524dfa28795e5011b4346fb5befc9d6336d490ed54d */}
### Without `gh`?

Upstream statuses are skipped, the rest of the report is displayed. `gh auth login`
restores them.
