This page summarizes **which ANSSI rules are activated**, according to the **level** and
**category** of a host. It is the reference to consult before hardening a machine.

:::tip[Understand first]
The concepts used here (levels, categories, labels, MAC, egress…) are
explained in [Security
notions](/en/doc/admin-guide/understand/security-notions/).
:::

{/* t:p 68a4c9db7877ba6e627b323b0aa6db0c52e20c58f59a2d03d52b9919e0d2d590 */}
## Reminder: level and category

```nix
darkone.system.security = {
  enable   = true;
  level    = "intermediary";   # minimal | intermediary | reinforced | high
  category = "server";         # base | client | server
};
```

Levels are **cumulative**: `intermediary` adds its rules to those of
`minimal`, and so on. The category adds the rules specific to a workstation
(`client`) or a server (`server`).

## Recommended category per profile

| Profile | Recommended category | Why |
|---|---|---|
| `minimal`, `portable` | `base` | Universal base |
| `desktop`, `laptop` | `client` | Screen, USB, interactive session |
| `server`, `gateway`, `hcs`, `vm` | `server` | Exposed services, network |

:::caution[Today: `base` everywhere]
Automatic profile → category mapping is not yet active. All hosts are
set to `minimal` / `base` by default. To apply a category, set
`category` manually on the relevant host.
:::

verify their actual state.

:::note[`R9`: user namespaces remain allowed]
The legacy key `kernel.unprivileged_userns_clone` comes from a Debian patch and is absent from a mainline kernel: setting it causes `systemd-sysctl` to fail. The mainline equivalent `user.max_user_namespaces = 0` breaks Flatpak, bubblewrap, and rootless Podman. It is therefore **optional**:
`darkone.security.kernel-params.restrictUserns = true`, to be reserved for servers without application sandboxing.

| Code | Rule | Min | Inter | Reinforced | Elevated |
|---|---|:-:|:-:|:-:|:-:|
| `R30` | Unused accounts disabled | ✅ | ✅ | ✅ | ✅ |
| `R31` | Strong passwords | ✅ | ✅ | ✅ | ✅ |
| `R68` | Password storage in `yescrypt` | ✅ | ✅ | ✅ | ✅ |
| `R32` | Idle session lockout | ❌ | ✅ | ✅ | ✅ |
| `R33` | Admin action audit trail | ❌ | ✅ | ✅ | ✅ |
| `R34` | Service accounts without shell | ❌ | ✅ | ✅ | ✅ |
| `R35` | Unique service accounts | ❌ | ✅ | ✅ | ✅ |
| `R67` | Secure remote PAM | ❌ | ⚠️ | ⚠️ | ⚠️ |
| `R69` | User databases over TLS | ❌ | ⚠️ | ⚠️ | ⚠️ |
| `R70` | System accounts ≠ directory | ❌ | ⚠️ | ⚠️ | ⚠️ |
| `C10` | Session limits (`nproc`, `nofile`) | ❌ | ✅ | ✅ | ✅ |

:::note[`R69`, `R70`: remote directory deferred]
These rules only concern a **remote directory** (SSSD/nslcd), not used by DNF today; their TLS component is deferred (future `checkScript`).
:::

:::note[`R32`: idle session logout]
`TMOUT=600` closes any console or SSH session that has been idle for ten minutes, on **both bash and zsh** — DNF makes zsh the default login shell, and the variable was previously only set for bash. A `tmux` or `screen` left in the foreground is terminated with the session.

The variable is set as `readonly`: it cannot be disabled in a session. A machine that keeps long-running terminals (compilation farms, agent tools) sets `darkone.security.users.idleTimeout = 0`, which removes the TTY delay without affecting GNOME lock.

:::

:::danger[`R67`: `pam_faillock` truly locks accounts]
Three incorrect passwords lock the account for 15 minutes on `login`, `su`, `sudo`, and through the `login` stack, the GNOME lock screen. The stack is complete: `preauth` rejects, `authfail` counts, the `account` rule blocks an already locked account. The two `auth` rules bracket the `pam_unix` **for each service**; their rank is calculated as it differs from one stack to another (11700 on `su`/`sudo`, 13100 on `login`).

`sshd` is intentionally excluded: DNF prohibits password authentication, so `faillock` would never count anything there. Its `account` rule could only reject a backup key session for a lock acquired at the console. Maintenance access therefore remains open under all circumstances, and `nix` (without password credentials) cannot be locked.

Keep a **root session open** during the initial deployment and know the recovery command: `faillock --user <login> --reset`. Settings: `darkone.security.pam.faillock.deny` and `.unlockTime`. `root` is never locked.
:::

### Files and Permissions

| Code | Rule | Min | Inter | Reinforced | Elevated |
|---|---|:-:|:-:|:-:|:-:|
| `R53` | Detection of unowned files | ✅ | ✅ | ✅ | ✅ |
| `R54` | Sticky bit on `/tmp` and `/var/tmp` | ✅ | ✅ | ✅ | ✅ |
| `R56` | Detection of `setuid` outside allowlist | ✅ | ✅ | ✅ | ✅ |
| `R14` | Filesystem sysctls | ❌ | ✅ | ✅ | ✅ |
| `R28` | Partitioning and mount options | ❌ | ✅ | ✅ | ✅ |
| `R50` | Sensitive file restrictions | ❌ | ✅ | ✅ | ✅ |
| `R52` | Socket and named pipe permissions | ❌ | ⚠️ | ⚠️ | ⚠️ |
| `R55` | Per-user temporary directories | ❌ | ⚠️ | ⚠️ | ⚠️ |
| `R36` | `UMASK` 0077 | ❌ | ❌ | ✅ | ✅ |
| `R57` | Minimal root `setuid` (capabilities) | ❌ | ❌ | ✅ | ✅ |

:::note[`R14`: `binfmt_misc` kept on emulating hosts]
Disabling `binfmt_misc` breaks cross-compilation (aarch64 images for Raspberry Pi). The restriction is automatically lifted when `boot.binfmt.emulatedSystems` is not empty; the `needs-binfmt` label remains useful for other cases (Java, `qemu-static`).
:::

:::caution[`R28`: `/tmp` non-executable]
`/tmp` is a tmpfs with `nosuid,nodev,noexec`, sized via `boot.tmp.tmpfsSize` (25% of RAM by default). R28 **owns the mount**: `boot.tmp.useTmpfs` is forced to `false`, otherwise the `tmp.mount` unit it generates — without `noexec` — would silently override `/etc/fstab`.

`noexec` forbids direct execution **and** `dlopen`. It therefore breaks any tool that executes what it just decompressed (pip, cargo, gcc) and any runtime that extracts its native libraries into `/tmp` (Bun, Electron, agent tools). Nix builds are covered, the daemon switching to `/var/tmp`, but an interactive tool may require `export TMPDIR=$XDG_RUNTIME_DIR`.

Two fallback options per host:

| Option | Effect |
|---|---|
| `darkone.security.filesystem.tmpNoexec = false` | keeps the tmpfs with `nosuid,nodev`, removes `noexec` |
| `darkone.security.filesystem.tmpfs = false` | leaves `/tmp` on its original filesystem (persistent data, no RAM consumed) |
:::

:::note[`R28`, `R52`, `R55`: designated services and partitions]
`R28` also hardens `/proc` (`hidepid=2`) and `/dev/shm`. The `proc` group, which grants the right to see other users' processes, is populated with `wheel` members; otherwise `ps`, `htop`, and the GNOME monitor would display nothing for administrators themselves. Mount options on `/var/log`, `/srv`, `/opt`, `/home` are added via `darkone.security.filesystem.extraMountHardening` (separate partitions required). `R52` (directory mode `0750`) and `R55` (per-service private `/tmp`) apply to units listed in `darkone.security.services.hardenedUnits` — empty by default. See `R63`.
:::

| `C5` | OpenSSH hardening | ❌ | ✅ | ✅ | ✅ |

| `C8` | Secure DNS resolver (DNSSEC, DoT) | ❌ | ✅ | ✅ | ✅ |

| `R78` | Network service isolation **(server)** | ❌ | ❌ | ✅ | ✅ |

:::note[`C4` partial at the first two levels]
At the `minimal` and `intermediary` levels, `C4` covers **inbound**
filtering (default-deny). **Outbound** (egress) filtering is added from
`reinforced` onwards.
:::

:::caution[`C5`: no tunnel, no agent, no `ssh -J`]
TCP tunnels, agent forwarding and X11 are disabled. ProxyJump falls with them:
`ssh -J` opens a `direct-tcpip` channel, which is exactly what
`AllowTcpForwarding` refuses. Administrative access happens **directly on the
tailnet**, never through a jump.
:::

:::note[On the tailnet, SSH follows the workstation]
The tailnet access policy only opens port 22 to administration workstations
and to devices declared in `adminDevices`&nbsp;: an administrator account is not
enough. See [Access policy](/en/doc/admin-guide/understand/tailnet/#access-policy-acl).
:::

:::caution[`R13`: disabling IPv6 is an explicit request]
An exclusion label only knows how to **remove** a rule. `no-ipv6` therefore made
R13 active by default and cut IPv6 across the whole fleet. Disabling now goes
through `darkone.security.kernel-params.disableIpv6` (`false` by
default); ANSSI prefers hardening IPv6 over removing it anyway.
:::

:::note[`R12`: reverse-path filtering matched to the role]
Strict mode (`rp_filter = 1`) drops any asymmetric reply. A tailscale
subnet router advertises its routes without SNAT
(`--snat-subnet-routes=false`): this is exactly that case. `isGateway`
or `isExitNode` hosts switch to loose mode (`2`), the others stay strict.
:::

:::caution[`R79`: every exposed service must have its filter]
fail2ban runs on the `systemd` backend: a jail requires a `filter.d`
definition **and** a `journalmatch`, otherwise the daemon refuses to start —
and takes the `sshd` jail down with it. `exposedServices` is therefore checked
at evaluation against `darkone.security.network.filters`. Provided today:
`sshd` (shipped with fail2ban) and `vaultwarden`. Caddy, Matrix and Kanidm need
patterns written from real journal logs.
:::

## Adjusting Without Breaking Everything

Three levers allow fine-tuning a specific protection without lowering the global level.

- **Tags** (`excludes`): disable a **group** of incompatible rules (e.g. `needs-jit`, `needs-binfmt`).
- **Exceptions** (`exceptions`): bypass a **single** rule, with mandatory justification.
- **Activation options**: enable a rule too destructive to be active by default (`disableIpv6`, `restrictUserns`).

:::note[A tag can only remove]
`excludes` and `exceptions` **subtract** rules; neither can add one. A dangerous rule that is enabled by default is therefore controlled via a dedicated option, never by the absence of a tag.
:::

The details of these levers are in [Security
Concepts](/en/doc/admin-guide/understand/security-notions/#exclusion-labels).

:::danger[Module under stabilization]
Raise the level **gradually** and test each host before production.
:::
