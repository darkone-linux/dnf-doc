The `umi` profile turns a workstation into a machine usable **without a
keyboard or mouse**, driven by eye gaze and voice. It is intended for people
with severe motor disabilities.

It consists of two inseparable halves: an `umi`
[host profile](/en/doc/admin-guide/understand/host-profiles/) that prepares the
hardware and the session, and an `umi`
[user profile](/en/doc/admin-guide/understand/user-profiles/) that sets up the
account environment.

{/* t:p 9e285175a5b07f1b355ffd3379de8d9009e6f5a78cc5fd39ff6c99abdae0169e */}
## The principle

The gaze replaces the mouse, the voice replaces the keyboard, and the on-screen keyboard takes over for everything typed character by character.

```d2
style.fill: transparent
direction: down

user: User { shape: person }
tracker: Tobii Eye Tracker 5
talon: Talon
uinput: /dev/uinput
session: Cinnamon Session (X11)
onboard: Onboard Virtual Keyboard

user -> tracker: Gaze
user -> talon: Voice
tracker -> talon
talon -> uinput
uinput -> session
onboard -> session
```

## Hardware

| Element | Requirement |
|---|---|
| Eye tracker | Tobii Eye Tracker 5 (USB, manufacturer ID `2104`) |
| Architecture | `x86_64-linux` only (Talon provides no other binary) |
| Microphone | Required for voice commands |
| Speakers | Audio feedback for on-screen keyboard keystrokes |

:::caution[First boot under Windows]
The Tobii 5 firmware must be initialized **once** on a Windows machine, using
the Tobii Experience application. Without this step, the tracker stays silent
under Linux.
:::

## Setting up a workstation

<Steps>

1. **Declare the host and its user** in `etc/config.yaml`, both with the `umi`
   profile:

   ```yaml
   # etc/config.yaml
   users:
     alice:
       uid: 1010
       name: "Alice"
       profile: "umi"
       groups: ["global"]

   hosts:
     - hostname: "poste-regard"
       name: "Poste piloté au regard"
       zone: "maison:2.3"
       profile: "umi"
       users: ["alice"]
   ```

   The user profile adds the account to the `input` and `uinput` groups,
   without which Talon cannot inject events.

2. **Enable automatic login** in the machine configuration. A password prompt
   is a dead end without a keyboard:

   ```nix
   # usr/machines/poste-regard/default.nix
   darkone.host.umi.autoLoginUser = "alice";
   ```

3. **Generate and deploy**:

   ```sh
   just generate
   just apply poste-regard
   ```

4. **Calibrate on first launch**. Unplug then replug the tracker (the udev
   rules only apply on connection), relaunch Talon, then run the calibration
   from its menu.

</Steps>

:::tip[Multiple users on the same machine]
Only the account listed in `autoLoginUser` opens its session on its own. The
other eye-controlled accounts declare themselves in `gazeUsers` to inherit the
Cinnamon session; ordinary accounts keep their usual GNOME Wayland session.
:::

## Configuring the host

`darkone.host.umi` options, to be set in `usr/machines/<host>/default.nix`.

| Option | Default | Role |
|---|---|---|
| `enable` | enabled by the profile | Enables the host profile |
| `autoLoginUser` | `null` | Account opened automatically at boot |
| `gazeUsers` | `[ ]` | Other accounts whose GDM session is Cinnamon/X11 |
| `package` | `pkgs.talon` | Talon package, or `null` to install it manually |

:::note[Talon absent or not wanted]
With `package = null`, everything else is configured (udev, uinput,
accessibility) and Talon can be launched manually from the upstream archive,
which preserves its automatic updates.
:::

## Configuring the user

`darkone.home.umi` options, to be set in `usr/users/<login>/default.nix`.

| Option | Default | Role |
|---|---|---|
| `enable` | enabled by the profile | Enables the user profile |
| `enableTalonAutostart` | `true` | Launches Talon at login |
| `communityScripts` | `null` | `talonhub/community` tree deployed in `~/.talon/user/community` |
| `enableDwell` | `false` | Click by pointer dwell |
| `dwellTime` | `1.2` | Dwell click delay, in seconds |

:::caution[Dwell click remains optional]
`enableDwell` triggers a click as soon as the pointer stays still. It is
essential for eye gaze, but **unusable with a mouse**: the pointer left on the
accessibility menu or on the on-screen keyboard clicks on its own. Only enable
it on a machine actually equipped with a tracker.
:::

:::tip[Full mouse control with eye gaze]
The `talonhub/community` community scripts provide the mouse zoom and click by
tongue clucking. They are declared reproducibly:

```nix
# usr/users/alice/default.nix
{ pkgs, ... }:
{
  darkone.home.umi.communityScripts = pkgs.fetchFromGitHub {
    owner = "talonhub";
    repo = "community";
    rev = "…";
    hash = "…";
  };
}
```
:::

## What the profile changes

The workstation is deliberately stripped of anything that requires a keyboard
or a mouse.

| Change | Reason |
|---|---|
| Cinnamon session on X11 | Talon does not work under Wayland |
| Automatic login | No password can be entered |
| Locking and sleep disabled | A locked screen is a dead end |
| Passwordless keyring | Avoids an impossible-to-fill prompt |
| Cursor and text enlarged | Gaze accuracy limited to a few dozen pixels |
| On-screen keyboard docked at the bottom | Always available, large targets, word prediction |
| Configuration panels hidden | Cinnamon extensions and actions, keyring manager |

:::danger[The workstation is not protected at boot]
Automatic login, no screen lock, plaintext keyring: anyone who turns on the
machine is in the session. The only useful safeguard is
[disk encryption](/en/doc/admin-guide/operate/luks/), to plan from installation
if the workstation is portable.
:::

## Diagnostics

| Symptom | Lead |
|---|---|
| Talon does not see the tracker | Replug the tracker, then relaunch Talon (udev rule applied on connection) |
| Firmware not initialized | Run through Tobii Experience under Windows once |
| Session opened under GNOME | Check that the account is in `gazeUsers` or in `autoLoginUser` |
| The pointer clicks on its own | `enableDwell` enabled without a tracker, disable it |

:::note[Expected kernel messages]
The tracker exposes two video interfaces that `uvcvideo` cannot handle, hence
the `Unknown video format`, `No supported video formats found` and
`probe with driver uvcvideo failed with error -22` messages. They are
**normal and desirable**: no kernel driver claims the interfaces, which leaves
them free for Talon.
:::
