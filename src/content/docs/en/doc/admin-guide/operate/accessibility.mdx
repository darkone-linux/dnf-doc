The 🌳 `umi` profiles (*Unified Multimodal Input*, unified multimodal input)
generate a workstation usable **without keyboard or mouse**. It is
controlled by several input methods coordinated with each other: touch, voice,
gaze… The goal is accessibility, especially for people with
motor disabilities.

They consist of two parts: a
[host profile](/en/doc/admin-guide/understand/host-profiles/) `umi` which
declares the hardware and session, and a
[user profile](/en/doc/admin-guide/understand/user-profiles/) `umi`
which sets the user's environment.

{/* t:p 1a9132b4a595976f48374c14f19cc1630a5dd0142d8f1dd51cef73439b7cc3c9 */}
## The principle

No single input method replaces keyboard and mouse on its own: each has its
limits (gaze precision, voice fatigue, gesture range). The UMI workstation
combines them so they complement each other, and adjusts to the user's
abilities.

| Input method | Tool | Usage |
|---|---|---|
| Touch | Touchscreen, Onboard on-screen keyboard | Point, click, enter text |
| Voice | Talon | Voice commands |
| Gaze | Tobii Eye Tracker 5, driven by Talon | Move the pointer |

Coordination example: gaze places the pointer, voice or dwell-click confirms,
on-screen keyboard enters text.

## Hardware

Each device serves one input method&nbsp;: only equip the workstation with
those suited to the user.

| Item | Requirement |
|---|---|
| Eye tracker | Tobii Eye Tracker 5 (USB, manufacturer ID `2104`) |
| Architecture | `x86_64-linux` only (Talon provides no other binary) |
| Microphone | Needed for voice commands |
| Speakers | Audio feedback for visual keyboard keystrokes |
| Screen | A good touchscreen for controlling the desktop and applications |

:::caution[First boot under Windows]
The Tobii 5 firmware must be initialized **once** on a Windows
machine, using the Tobii Experience app. Without this step, the tracker
stays silent under Linux.
:::

## Set up a workstation

<Steps>

1. **Declare the host and its user** in `etc/config.yaml`, both with the `umi`
   profile:

   ```yaml
   # etc/config.yaml
   users:
     alice:
       uid: 1010
       name: "Alice"
       profile: "umi"
       groups: ["global"]

   hosts:
     - hostname: "umi-desktop"
       name: "Accessible workstation"
       zone: "maison:2.3"
       profile: "umi"
       users: ["alice"]
   ```

   On the `umi` host, the user profile adds the account to the `input` and
   `uinput` groups, without which Talon cannot inject events.

2. **Enable automatic login** in the machine configuration, if the user cannot
   use a keyboard to sign in:

   ```nix
   # usr/machines/umi-desktop/configuration.nix
   darkone.host.umi.autoLoginUser = "alice";
   ```

3. **Generate and deploy**:

   ```sh
   just generate
   just apply umi-desktop
   ```

4. **Test and configure**

   :::caution[Eye tracker: calibrate on first launch]
   Unplug and replug the tracker (udev rules only apply on plug-in), restart
   Talon, then run the calibration from its menu.
   :::

</Steps>

:::tip[Several users on the same machine]
Only the account listed in `autoLoginUser` signs in on its own. Every host
account with the `umi` profile starts the Cinnamon session, imposed at each
boot. Ordinary accounts keep their usual GNOME Wayland session.
:::

## Configure the host

Options of `darkone.host.umi`, to set in `usr/machines/<host>/configuration.nix`.

| Option | Default | Role |
|---|---|---|
| `enable` | enabled by the profile | Activates the host profile |
| `autoLoginUser` | `null` | `umi` account started at boot |
| `package` | `pkgs.talon` | Talon package, or `null` to install it manually |

:::note[Talon absent or unwanted]
With `package = null`, everything else is configured (udev, uinput,
accessibility) and Talon can be launched manually from the upstream archive,
which preserves its automatic update.
:::

## Configuring the user

`darkone.home.umi` options, to set in `usr/users/<login>/default.nix`.

| Option | Default | Role |
|---|---|---|
| `enable` | enabled by the profile | Enables the user profile |
| `enableTalonAutostart` | `true` | Launches Talon at session start |
| `communityScripts` | `null` | `talonhub/community` tree deployed in `~/.talon/user/community` |
| `enableDwell` | `false` | Click by pointer dwell |
| `dwellTime` | `1.2` | Dwell click delay, in seconds |

:::caution[Dwell click remains optional]
`enableDwell` triggers a click as soon as the pointer stays still. It is
essential for gaze, but **unsettling for the mouse**: a pointer
left on the accessibility menu or on the visual keyboard clicks on its own.
Only enable it on a workstation equipped with a tracker.
:::

:::tip[Community contributions]
The `talonhub/community` community scripts bring mouse zoom and
click by tongue click. They are declared reproducibly:

```nix
# usr/users/alice/default.nix
{ pkgs, ... }:
{
  darkone.home.umi.communityScripts = pkgs.fetchFromGitHub {
    owner = "talonhub";
    repo = "community";
    rev = "…";
    hash = "…";
  };
}
```
:::

## What the profile changes

The workstation is deliberately stripped of everything that requires a keyboard
or a mouse.

| Change | Reason |
|---|---|
| Cinnamon session on X11 | Talon (unfortunately) does not work under Wayland |
| Automatic login | No password to type |
| Locking and sleep disabled | A locked screen is a dead end |
| Passwordless keyring | Avoids an impossible prompt (automatic login, unencrypted host) |
| Enlarged cursor and text | Limited precision of the gaze (a few dozen pixels) and of the finger |
| On-screen keyboard docked at the bottom | Always available, large targets, word prediction |

:::danger[The workstation is not protected at boot]
Automatic login, no screen lock: whoever turns the machine on is in the
session. The only effective safeguard is [disk encryption](/en/doc/admin-guide/operate/luks/),
to be planned from installation if the workstation is mobile.

Face recognition login is on the TODO list.
:::

:::note[The keyring follows disk encryption]
Only the automatically signed-in account is concerned: a password login unlocks
its keyring as usual. For this account, everything depends on the host:

- **unencrypted workstation**: the keyring is created without a password, or the
  session would open on a prompt nobody can satisfy;
- **encrypted workstation (LUKS)**: the passphrase entered at boot is passed to
  the keyring by the automatic login PAM stack. The keyring stays protected,
  and nothing is asked.

Consequence on an encrypted workstation: changing the LUKS passphrase without
changing the keyring one triggers the "your login password no longer matches
the one used for your keyring" message. Then delete
`~/.local/share/keyrings/login.keyring` and log in again.
:::

## The host's other accounts

An ordinary account keeps its GNOME Wayland session, with a few differences
inherited from the host:

- **Boot**: the machine logs into the UMI account. Log out of it, or switch
  user to open your own.
- **Seahorse**: absent, because it is unusable without a keyboard.
- **Shutdown**: each service gets 5 seconds to stop.

## Troubleshooting

| Symptom | Lead |
|---|---|
| Talon does not see the tracker | Replug the tracker, then restart Talon (udev rule applied on plug-in) |
| Firmware not initialised | Go once through Tobii Experience under Windows |
| Session opened under GNOME | Check the `umi` profile of the account and its presence in the host's `users`, then reboot |
| The pointer clicks on its own | `enableDwell` enabled without a tracker, disable it |

:::note[Expected kernel messages]
The tracker exposes two video interfaces that `uvcvideo` cannot handle, hence
the `Unknown video format`, `No supported video formats found` and
`probe with driver uvcvideo failed with error -22` messages. They are
**normal and desirable**: no kernel driver claims the interfaces, which leaves
them free for Talon.
:::

## FAQ

{/* t:p 49a3e63f83ac4ab8d59d9fec17b634755193ab5c7f83c6e469656b3b31c22450 */}
### Can a UMI account choose GNOME?

Not on a `umi` host: the Cinnamon session is re-imposed at every boot, because
Talon requires X11.

{/* t:p ac6c80b95349c7cebae6b778636b28afcda1c1826a5b6d551c7c87e914420339 */}
### And on an ordinary workstation?

The account opens the host's GNOME Wayland session, with the GNOME on-screen
keyboard, the enlarged cursor and text. Talon and Onboard, which require X11,
stay inactive.
