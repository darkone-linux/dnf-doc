The `umi` profiles (*Unified Multimodal Input*, unified multimodal input)
produce a workstation usable **without keyboard or mouse**. It is
driven through several input methods coordinated with each other&nbsp;: touch, voice,
gaze… The goal is accessibility, especially for people
with motor disabilities.

They consist of two parts&nbsp;: a
[host profile](/en/doc/admin-guide/understand/host-profiles/) `umi` that
declares the hardware and the session, and a
[user profile](/en/doc/admin-guide/understand/user-profiles/) `umi`
that sets the user's environment.

{/* t:p 1a9132b4a595976f48374c14f19cc1630a5dd0142d8f1dd51cef73439b7cc3c9 */}
## The principle

No single input method replaces keyboard and mouse on its own: each has its
limits (gaze precision, voice fatigue, gesture range). The UMI workstation
combines them so they complement each other, and adjusts to the user's
abilities.

| Input method | Tool | Usage |
|---|---|---|
| Touch | Touchscreen, Onboard on-screen keyboard | Point, click, enter text |
| Voice | Talon | Voice commands |
| Gaze | Tobii Eye Tracker 5, driven by Talon | Move the pointer |

Coordination example: gaze places the pointer, voice or dwell-click confirms,
on-screen keyboard enters text.

```d2

```

## Hardware

Each device serves one input method&nbsp;: only equip the workstation with
those suited to the user.

| Item | Requirement |
|---|---|
| Eye tracker | Tobii Eye Tracker 5 (USB, manufacturer ID `2104`) |
| Architecture | `x86_64-linux` only (Talon provides no other binary) |
| Microphone | Needed for voice commands |
| Speakers | Audio feedback for visual keyboard keystrokes |
| Screen | A good touchscreen for controlling the desktop and applications |

:::caution[First boot under Windows]
The Tobii 5 firmware must be initialized **once** on a Windows
machine, using the Tobii Experience app. Without this step, the tracker
stays silent under Linux.
:::

## Setting up a workstation

<Steps>

1. **Declare the host and its user** in `etc/config.yaml`, both with
   the `umi` profile&nbsp;:

   ```yaml
   # etc/config.yaml
   users:
     alice:
       uid: 1010
       name: "Alice"
       profile: "umi"
       groups: ["global"]

   hosts:
     - hostname: "umi-desktop"
       name: "Poste accessible"
       zone: "maison:2.3"
       profile: "umi"
       users: ["alice"]
   ```

   The user profile adds the account to the `input` and `uinput` groups,
   without which Talon cannot inject events.

2. **Enable automatic login** in the machine's
   configuration, if the user cannot use a keyboard to sign in&nbsp;:

   ```nix
   # usr/machines/umi-desktop/default.nix
   darkone.host.umi.autoLoginUser = "alice";
   ```

3. **Generate and deploy**&nbsp;:

   ```sh
   just generate
   just apply umi-desktop
   ```

4. **Test and configure**

   :::caution[Eye tracker: calibrate on first launch]
   Unplug then replug the tracker (the udev rules only apply at
   plug-in), restart Talon, then run calibration from its menu.
   :::

</Steps>

:::tip[Multiple users on the same machine]
Only the account listed in `autoLoginUser` opens its session by itself. The
other UMI accounts are declared in `gazeUsers` to inherit
the Cinnamon session. Regular accounts keep their usual GNOME
Wayland session.
:::

## Configuring the host

`darkone.host.umi` options, to set in `usr/machines/<host>/default.nix`.

| Option | Default | Role |
|---|---|---|
| `enable` | enabled by the profile | Enables the host profile |
| `autoLoginUser` | `null` | Account opened automatically at startup |
| `gazeUsers` | `[ ]` | Other accounts whose GDM session is Cinnamon/X11 |
| `package` | `pkgs.talon` | Talon package, or `null` to install it manually |

:::note[Talon absent or not wanted]
With `package = null`, everything else is configured (udev, uinput,
accessibility) and Talon can be launched manually from the upstream archive,
which preserves its automatic update.
:::

## Configuring the user

`darkone.home.umi` options, to set in `usr/users/<login>/default.nix`.

| Option | Default | Role |
|---|---|---|
| `enable` | enabled by the profile | Enables the user profile |
| `enableTalonAutostart` | `true` | Launches Talon at session start |
| `communityScripts` | `null` | `talonhub/community` tree deployed in `~/.talon/user/community` |
| `enableDwell` | `false` | Click by pointer dwell |
| `dwellTime` | `1.2` | Dwell click delay, in seconds |

:::caution[Dwell click remains optional]
`enableDwell` triggers a click as soon as the pointer stays still. It is
essential for gaze, but **unsettling for the mouse**: a pointer
left on the accessibility menu or on the visual keyboard clicks on its own.
Only enable it on a workstation equipped with a tracker.
:::

:::tip[Community contributions]
The `talonhub/community` community scripts bring mouse zoom and
click by tongue click. They are declared reproducibly:

```nix
# usr/users/alice/default.nix
{ pkgs, ... }:
{
  darkone.home.umi.communityScripts = pkgs.fetchFromGitHub {
    owner = "talonhub";
    repo = "community";
    rev = "…";
    hash = "…";
  };
}
```
:::

## What the profile changes

The workstation is deliberately stripped of anything that assumes a keyboard or
a mouse.

| Change | Reason |
|---|---|
| Cinnamon session on X11 | Talon (unfortunately) does not work under Wayland |
| Automatic login | No password can be entered |
| Locking and sleep disabled | A locked screen is a dead end |
| Passwordless keyring | Avoids an impossible-to-fill prompt (unencrypted host only) |
| Enlarged cursor and text | Limited accuracy of gaze (a few dozen pixels) and of the finger |
| Visual keyboard anchored at bottom | Always available, large targets, word prediction |

:::danger[The workstation is not protected at startup]
Automatic login, no screen locking&nbsp;: anyone who
turns on the machine is in the session. The only useful barrier is
[disk encryption](/en/doc/admin-guide/operate/luks/), to plan for from
installation if the workstation is mobile.

Login through facial recognition is on the TODO list.
:::

:::note[The keyring follows disk encryption]
Session keyring handling depends on the host&nbsp;:

- **unencrypted workstation** : the keyring is created without a password,
  otherwise the session would open on a prompt that nobody can fill in ;
- **encrypted workstation (LUKS)** : the passphrase entered at boot is passed to
  the keyring through the PAM stack of automatic login. The keyring
  stays protected, and nothing is asked.

Consequence on an encrypted workstation&nbsp;: changing the LUKS passphrase
without changing the one in the keyring triggers the message "the login
password no longer matches the one in your keyring". Then delete
`~/.local/share/keyrings/login.keyring` and reopen the session.
:::

## Diagnostics

| Symptom | Lead |
|---|---|
| Talon does not see the tracker | Replug the tracker, then relaunch Talon (udev rule applied on connection) |
| Firmware not initialized | Run through Tobii Experience under Windows once |
| Session opened under GNOME | Check that the account is in `gazeUsers` or in `autoLoginUser` |
| The pointer clicks on its own | `enableDwell` enabled without a tracker, disable it |

:::note[Expected kernel messages]
The tracker exposes two video interfaces that `uvcvideo` cannot handle, hence
the `Unknown video format`, `No supported video formats found` and
`probe with driver uvcvideo failed with error -22` messages. They are
**normal and desirable**: no kernel driver claims the interfaces, which leaves
them free for Talon.
:::
