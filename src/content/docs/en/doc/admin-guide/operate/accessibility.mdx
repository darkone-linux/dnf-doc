The 🌳 `umi` profiles (*Unified Multimodal Input*, unified multimodal input)
generate a workstation usable **without keyboard or mouse**. It is
controlled by several input methods coordinated with each other: touch, voice,
gaze… The goal is accessibility, especially for people with
motor disabilities.

They consist of two parts: a
[host profile](/en/doc/admin-guide/understand/host-profiles/) `umi` which
declares the hardware and session, and a
[user profile](/en/doc/admin-guide/understand/user-profiles/) `umi`
which sets the user's environment.

{/* t:p 1a9132b4a595976f48374c14f19cc1630a5dd0142d8f1dd51cef73439b7cc3c9 */}
## The principle

No single input method replaces keyboard and mouse on its own: each has its
limits (gaze precision, voice fatigue, gesture range). The UMI workstation
combines them so they complement each other, and adjusts to the user's
abilities.

| Input method | Tool | Usage |
|---|---|---|
| Touch | Touchscreen, Onboard on-screen keyboard | Point, click, enter text |
| Voice | Talon | Voice commands |
| Gaze | Tobii Eye Tracker 5, driven by Talon | Move the pointer |

Coordination example: gaze places the pointer, voice or dwell-click confirms,
on-screen keyboard enters text.

```d2
style.fill: transparent
direction: down

user: User { shape: person }
touch: Touchscreen
mic: Microphone
tracker: Tobii Eye Tracker 5
onboard: Onboard on-screen keyboard
talon: Talon
uinput: /dev/uinput
session: Cinnamon Session (X11)

user -> touch: Touch
user -> mic: Voice
user -> tracker: Gaze
touch -> onboard
touch -> session
mic -> talon
tracker -> talon
talon -> uinput
uinput -> session
onboard -> session
```

## Hardware

Each device serves one input method&nbsp;: only equip the workstation with
those suited to the user.

| Item | Requirement |
|---|---|
| Eye tracker | Tobii Eye Tracker 5 (USB, manufacturer ID `2104`) |
| Architecture | `x86_64-linux` only (Talon provides no other binary) |
| Microphone | Needed for voice commands |
| Speakers | Audio feedback for visual keyboard keystrokes |
| Screen | A good touchscreen for controlling the desktop and applications |

:::caution[First boot under Windows]
The Tobii 5 firmware must be initialized **once** on a Windows
machine, using the Tobii Experience app. Without this step, the tracker
stays silent under Linux.
:::

## Configure the host

Options of `darkone.host.umi`, to set in `usr/machines/<host>/configuration.nix`.

| Option | Default | Role |
|---|---|---|
| `enable` | enabled by the profile | Activates the host profile |
| `autoLoginUser` | `null` | `umi` account started at boot |
| `package` | `pkgs.talon` | Talon package, or `null` to install it manually |

:::note[Talon absent or unwanted]
With `package = null`, everything else is configured (udev, uinput,
accessibility) and Talon can be launched manually from the upstream archive,
which preserves its automatic update.
:::

## Configure the user

Options of `darkone.home.umi`, set in `usr/users/<login>/default.nix`.

| Option | Default | Role |
|---|---|---|
| `enable` | enabled by the profile | Enables the user profile |
| `enableTalonAutostart` | `true` | Starts Talon at login |
| `communityScripts` | `null` | `talonhub/community` tree deployed to `~/.talon/user/community` |
| `enableDwell` | `false` | Permanent dwell click |
| `enableTrackerAuto` | `true` | Gaze and click follow the tracker |
| `gazeFilterSpeed` | `2.0` | Gaze responsiveness (Talon: `1.0`) |
| `cursorFilterSpeed` | `4.0` | Pointer responsiveness (Talon: `2.0`) |
| `enableGazeControl` | `true` | Pointer follows the gaze |
| `enableHeadControl` | `false` | Head also moves the pointer |
| `headSpeed` | `null` | Head sensitivity (Talon: `1`) |
| `enableHeadJump` | `false` | A head movement brings the pointer back to the gaze |
| `enableMouseJump` | `false` | Moving a mouse toward the gaze brings the pointer there |
| `enableGazeFocus` | `false` | The gazed window takes focus (experimental) |
| `dwellTime` | `1.2` | Dwell click delay, in seconds |
| `panelHeight` | `64` | Height of the Cinnamon panel, in pixels |
| `textScaling` | `1.5` | Text magnification factor (Cinnamon) |
| `enablePanel` | `true` | Panel imposed, rewritten at every deployment |
| `panelLaunchers` | Files, Firefox | Panel launchers (`.desktop` files) |
| `menuFavorites` | Calculator, Calculator, Calendar, Settings | Menu favorites, rewritten at deployment |
| `enableRofiMenu` | `true` | Full-screen application grid |
| `rofiGridResolution` | `{ columns = 6; rows = 4; }` | Tiles per grid page |
| `hiddenApps` | Terminals, duplicates, NixOS manual | Hidden from the grid and the menu |

:::caution[Dwell click follows the tracker]
Under Cinnamon, `enableTrackerAuto` enables pointer control by gaze and dwell
click when the tracker is plugged in, and turns that click off when it is
unplugged: **with the mouse, it clicks on everything the pointer hovers over**.
`enableDwell` is then only useful under GNOME.
:::

:::note[Eye Tracking menu modes]
`enableGazeControl`, `enableHeadControl`, `enableHeadJump`, `enableMouseJump`
and `enableGazeFocus` are re-imposed at every Talon start. A change made from
the menu lasts until the next start.
:::

:::tip[Community contributions]
The community scripts `talonhub/community` bring mouse zoom and
tongue-click. They are declared reproducibly:

```nix
# usr/users/alice/default.nix
{ pkgs, ... }:
{
  darkone.home.umi.communityScripts = pkgs.fetchFromGitHub {
    owner = "talonhub";
    repo = "community";
    rev = "…";
    hash = "…";
  };
}
```
:::

## What the profile changes

The workstation is intentionally stripped of anything that assumes a keyboard or mouse.

| Change | Reason |
|---|---|
| Cinnamon session in X11 | Talon does not work (unfortunately) under Wayland |
| Automatic login | No password can be entered |
| Locking and sleep disabled | A locked screen is a dead end |
| Keyring without password | Avoids an impossible prompt (automatic login, unencrypted host) |
| Accessibility enabled at login | No activation prompt (Onboard) |
| Larger cursor, text, panel and icons | Limited precision of gaze (a few dozen pixels) and touch |
| Single-click opening (Nemo) | Dwell double-click requires changing mode |
| On-screen keyboard anchored to the bottom | Large targets, word prediction |
| On-screen keyboard hidden at startup | Clear screen, shown via its button |

:::danger[The workstation is not protected at startup]
Automatic login, no screen lock&nbsp;: anyone who turns on the machine is in the session. The only useful safeguard is [disk encryption](/en/doc/admin-guide/operate/luks/), which should be planned at installation if the workstation is mobile.

Facial recognition login is on the TODO list.
:::

:::note[The keyring follows disk encryption]
Only the automatically logged-in account is affected&nbsp;: logging in with a password unlocks its keyring as usual. For this account, it depends on the host&nbsp;:

- **Unencrypted workstation**: the keyring is created without a password, otherwise the session would open with a prompt that cannot be satisfied.
- **Encrypted workstation (LUKS)**: the passphrase entered at boot is passed to the keyring via the PAM stack of automatic login. The keyring remains protected, and no prompt is shown.

Consequence for an encrypted workstation&nbsp;: changing the LUKS passphrase without changing the keyring passphrase will cause the message "The login password does not match your keyring password." In that case, delete `~/.local/share/keyrings/login.keyring` and reopen the session.
:::

## The panel

Under Cinnamon, `enablePanel` organizes the bottom panel for the gaze.

| Position | Content |
|---|---|
| Left | Menu, grid, launchers, open windows |
| Right | Click types, pause zone, gaze |
| Then | Accessibility, on-screen keyboard |
| Finally | Status icons (Nextcloud…), clock |

The click types (single, double, drag, secondary) and the pause zone appear
only when dwell click is active. The pause zone lets the gaze explore the
screen without triggering anything; the click types are hidden during the
pause.

| Action on the pause zone | Effect |
|---|---|
| Click, clicks active | Suspends dwell click |
| Pointer resting 1.5 s, in pause | Re-enables clicks (green bar) |
| Mouse click, in pause | Re-enables clicks |

The gaze button (eye) turns off pointer control by gaze: the eyes no longer
move anything, and dwell click pauses to hand over to the mouse. Turning it
back on with the mouse, touch, or the Talon action `user.umi_gaze` also
re-enables clicks. It is turned back on at every start.

## The application grid

With `enableRofiMenu`, the first launcher on the panel opens all applications
full screen, in pages of large tiles, with no scrollbar.

| Target | Effect |
|---|---|
| Hovered tile | Highlighted |
| Click a tile | Launches the application, closes the grid |
| ◀ ▶ (screen edges) | Previous, next page |
| *Close* | Closes the grid |

Settings panels stay in the Cinnamon menu. `hiddenApps` hides other
applications (`.desktop` files) from both the grid and the menu.
`rofiGridResolution` sets the number of tiles per page.

:::caution[To validate with the tracker]
Dwell click in the grid not yet tested with the Tobii. The grid captures the
mouse: the pause zone, click types and on-screen keyboard stop responding while
it is open.
:::

## Calibrate gaze

The *Calibrate gaze* favorite, at the top of the Cinnamon menu, starts Talon's
calibration without going through its menu in the notification area. It appears
with `enableTrackerAuto`.

Recalibrate after changing screen, tracker or user position, or lighting.

## Tune the pointer live

With `enableHeadControl`, the gaze brings the pointer into the target zone and
the head refines it. `headSpeed` below `1` softens overly large head
movements. These settings can be tried without redeploying, from Talon's
console (REPL), and are lost when Talon restarts.

<Steps>

1. **Open the console** of the user's Talon, from an admin account on the host:

   ```sh
   sudo -u alice env HOME=/home/alice /home/alice/.talon/.venv/bin/repl
   ```

2. **Read the applied settings**:

   ```python
   print(actions.user.umi_tuning())
   ```

3. **Try values**, user at the workstation:

   | Command | Effect |
   |---|---|
   | `actions.tracking.control_head_toggle(True)` | Enables head control |
   | `actions.user.umi_head_speed(0.3)` | Head 3 times less sensitive |
   | `actions.user.umi_head_speed(1)` | Talon's original sensitivity |
   | `actions.user.umi_filter_speed(2, 4)` | Gaze and pointer responsiveness |

4. **Record the retained values** in `usr/users/<login>/default.nix`
   (`enableHeadControl`, `headSpeed`, `gazeFilterSpeed`, `cursorFilterSpeed`),
   then deploy.

</Steps>

:::caution[To validate]
`headSpeed` acts on the head acceleration curve, an internal Talon setting.
Its effect still needs measuring on a Tobii 5.
:::

## Other accounts on the host

A regular account keeps its GNOME Wayland session, with a few differences inherited from the host&nbsp;:

- **Startup**: the machine opens the session for the UMI account. Close that session or switch users to open your own.
- **Seahorse**: not present, as it is unusable without a keyboard.
- **`su`**: does not transmit screen access, and a prompt (keyring…) would block the UMI account. Administer via SSH or from your own session.
- **Shutdown**: each service has 5 seconds to stop.

## Troubleshooting

| Symptom | Lead |
|---|---|
| Talon does not see the tracker | Replug the tracker, then restart Talon (udev rule applied at plug-in) |
| Firmware not initialized | Run Tobii Experience once under Windows |
| Session opened under GNOME | Check the account's `umi` profile and its presence in the host's `users`, then reboot |
| The pointer clicks by itself | `enableDwell` enabled without a tracker, disable it |
| "Hover Click" window, clicks always single, scroll wheel unresponsive | A `mousetweaks` daemon is running in the session, started before the update: log out and back in |
| The pointer always aims beside the gaze | [Recalibrate](#calibrate-gaze) |
| The pointer stops short of the gazed point | Increase `gazeFilterSpeed` and `cursorFilterSpeed` |
| The pointer overshoots or jitters | Decrease them |
| The head moves the pointer too much | Lower `headSpeed`, or set `enableHeadControl` to `false` |

:::note[Expected kernel messages]
The tracker exposes two video interfaces that `uvcvideo` cannot handle, hence
the messages `Unknown video format`, `No supported video formats found` and
`probe with driver uvcvideo failed with error -22`. They are **normal and
desirable**: no kernel driver claims the interfaces, leaving them free for
Talon.
:::

## FAQ

### Can a UMI account choose GNOME?

Not on a `umi` host: the Cinnamon session is re-imposed at every boot, because
Talon requires X11.

{/* t:p ac6c80b95349c7cebae6b778636b28afcda1c1826a5b6d551c7c87e914420339 */}
### And on an ordinary workstation?

The account opens the host's GNOME Wayland session, with the GNOME on-screen
keyboard, the enlarged cursor and text. Talon and Onboard, which require X11,
stay inactive.
