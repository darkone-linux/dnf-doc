A **microVM guest** is an ordinary DNF host (zone IP, services,
monitoring) running in a lightweight virtual machine, on another host of the
fleet: the **hypervisor**. DNF relies on
[microvm.nix](https://github.com/microvm-nix/microvm.nix) and cloud-hypervisor.
Typical use: a closed AI workspace per person or per team.

## Declare a guest

<Steps>

1. **Declare the host**

   The `microvm-guest` feature names the hypervisor, from the same zone. The
   static IP is mandatory: the interface and MAC address derive from it.

   ```yaml
   # etc/config.yaml
   hosts:
     - hostname: "espace1"
       zone: "maison:1.40"
       profile: "ai-space"
       features: ["microvm-guest:serveur"]
   ```

2. **Size it**

   Optional, 2 vCPU and 4096 Mio by default.

   ```nix
   # usr/machines/espace1/configuration.nix
   {
     darkone.system.microvm.guest = {
       vcpu = 4;
       mem = 6144; # Mio
     };
   }
   ```

3. **Pin the state version**

   A guest never goes through `just install`: create the file by hand, with the
   NixOS version of the first deployment.

   ```nix
   # usr/machines/espace1/install/state.nix
   { system.stateVersion = "26.05"; }
   ```

4. **Initialize its secrets**

   The guest only reads its own secrets: see
   [isolated hosts](/en/doc/admin-guide/operate/secrets/#isolated-hosts).

   ```sh
   just space-init espace1
   ```

5. **Deploy the hypervisor**

   ```sh
   just generate
   just apply serveur
   ```

</Steps>

## Deploy and update

A guest is not a deployment target: `just apply <hypervisor>` builds the
guests, starts the new ones and restarts the changed ones. Guests start with
the hypervisor.

| Item | Location |
|---|---|
| Persistent data | `/var/lib/microvms/<guest>/` on the hypervisor |
| `/persist`, `/var/lib`, `/home` | virtiofs shares of that folder |
| Root `/` | In memory, wiped at every boot |
| Nix store | The hypervisor's, read-only, plus an in-memory layer for what the guest installs (`nix shell`, Home Manager), wiped at every boot |

## Network isolation

Each guest has its own `vm-X-Y` interface, routed in `/32` by the hypervisor,
which answers for it on the LAN (proxy ARP). The hypervisor's link to the LAN
is unchanged, there is no bridge.

| Flow | Allowed |
|---|---|
| Guest → Internet | Yes |
| Guest → gateway DNS | Yes |
| Guest → LAN, tailnet, other guests | No |
| Guest → hypervisor | No |
| Gateway → guest | Yes (proxy, monitoring) |
| Other host → guest | Ping and SSH only |

## FAQ

### How to connect to a guest?

Like any host, from an administration workstation: `just enter <guest>`. Its
name is published by the gateways' DNS, which must therefore be redeployed
after adding the guest.

{/* t:p 5edf6712e8f1a6fb19617f07ba341ad1037ebe941aea82d9a3a530eabbd8ca37 */}
### How to wipe a guest?

Remove it from `etc/config.yaml`, deploy the hypervisor, then delete
`/var/lib/microvms/<guest>/` on the hypervisor.
