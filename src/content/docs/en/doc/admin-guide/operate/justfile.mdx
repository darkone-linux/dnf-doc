The commands below are all executed with [`just`](https://just.systems/man/).

```sh title=Usage
just <command> <arguments>
```

Each command is prefixed with an icon indicating its usage context:

- 💠 **Common**: available in all contexts.
- 🔆 **Framework**: specific to the upstream DNF framework (`dnf/`).
- ✳️ **Project**: specific to the consuming project (my network).
- 🔗 **Co-development**: consuming project that contains a clone of the framework.

:::caution[Privilege elevation]
Most commands run with the user who administers the project, but
some of them elevate privileges to the `nix` user (`sudo -u nix ...`).
:::

:::tip[Key commands]
Commands marked with a ⭐ are the most useful on a daily basis.
:::

## Available commands

The recipes live in `dnf/just/`. The project `Justfile` imports **one** bootstrap file, which determines the available commands depending on the context.

| Context | `Justfile` line | Commands |
|---|---|---|
| Framework | `import 'just/dnf.just'` | 💠 🔆 |
| Consumer project | `import? 'dnf/just/project.just'` | 💠 ✳️ |
| Co-development | `import 'dnf/just/codev.just'` | 💠 ✳️ 🔗 |

In a consumer project, `dnf/` is the symlink to the Nix store created by `nix run .#init`. The `?` in `import?` lets `just` start as long as this symlink does not exist.

Co-development replaces this link with a git clone of the framework. The recipes 🔆 `unit-tests`, `check-recipes`, `simulate`, `simulate-debug`, `fixtures` and `pkg-update` can also be run there from the root. Project templates include the `codev.just` line, commented out.

:::note[Context adaptation]
A project is recognized by its `etc/config.yaml`, a framework clone by `dnf/.git`. A `dnf/` symlinked to the store is read-only&nbsp;: `generate`, `format` and `check` leave it aside.
:::

## Installation commands

Installing a new host follows a precise sequence.

{/* t:p 26ad8f4341e8d4b7a67a0c437f484feb81b4b1cba7bc9705cd22c18186860e3e */}
### ✳️ `install <host> [user] [ip]`

Formats disks via **disko** and installs NixOS via **nixos-anywhere**.

:::danger[Destructive]
All data on the target host is erased. A confirmation is requested before executing.
:::

:::note[Configuration required]
The host must have a disko configuration in `etc/config.yaml`, a `usr/machines/<host>/default.nix` directory, a `mac` key, and a fixed address (`zone: "<zone>:<x.y>"`). The last two are checked before any formatting: without them, the machine changes address on the reboot following installation. See [Initial
installation](/en/doc/admin-guide/install/first-network-installation/#install-a-machine).
:::

The `ip` argument defaults to `auto`: the address is calculated as for `full-install`, no need to look it up.

:::caution[The address must be the one the machine keeps]
`nixos-anywhere` freezes its target address for the entire run and cannot follow a renumbering. But the installer renews DHCP: if the machine was running on a dynamic lease older than its reservation (the typical case of an installation **over another system**), it switches to its reserved address mid-installation and the run talks to thin air.

The recipe therefore refuses to start on an address the host does not keep, and displays the ones it accepts. Before installing over an existing OS, reboot the machine so it takes its reserved address.
:::

The recipe also drops on the target, **before** system installation, the age key `/etc/sops/age/infra.key` and, on an encrypted host, its initrd SSH host key: sops works from the first activation and the very first boot already listens on port 2222. The volume is formatted with the fleet's shared passphrase, so there is nothing to enter.

```sh
just install myserver
just install myserver nixos 10.0.0.5     # custom IP
just install myserver nix auto test      # test VM only
```

:::caution[LUKS and `do=test`]
`nixos-anywhere` rejects `--vm-test` along with options that drop files and the formatting key: test mode therefore cannot format an encrypted volume. The recipe flags this.
:::

{/* t:p 332f678ae6aba4cf91ff9de59d833c42c4410666cb70c507792612466a979694 */}
### ✳️ `full-install <host> [user] [ip]` ⭐

Full chain: `install` + wait for reboot + `unlock` + `configure` + `apply` + `gc` + reboot.

The starting address is calculated automatically: host name in its own zone, reserved pass-through address if plugged in elsewhere. See [Machines outside
their zone](/en/doc/admin-guide/understand/network/#machines-outside-their-zone).

After reboot, the machine may not have returned to the same place: the recipe probes **all** its known addresses, on ports 22 and 2222, and continues on whichever responds. An encrypted host is unlocked along the way by `just unlock`.

The final reboot is not cosmetic: `apply` activates user space but not the kernel or initrd, and this reboot is the only automatic proof that the machine restarts **on its own**. On an encrypted host, it also proves that remote unlock works, while you are still in front of it rather than at the first power outage. `unlock` is therefore called again right after.

```sh
just full-install myserver
just full-install myserver nixos 10.0.3.42   # forced address
```

{/* t:p 865f0750feeb2e5de985ac71cf4c03c9686ede99e3c74b45939a00ab19a05b91 */}
### ✳️ `configure <host> [ip]`

Chains `copy-id` → `copy-hw` → `push-key` → `luks` (the last one does nothing on a non-encrypted host).

The address is resolved once and passed to the whole chain. If the host is plugged outside its zone, the SSH redirection is set up in the process, so that the following `apply` reaches it: `just roaming-clear <host>` once the machine is back home.

:::caution[Only for a host genuinely elsewhere]
The redirection disables host key verification, **and it stays that way until it is removed**. It is therefore only set if the used address is neither the host name nor the fixed address of its zone. `just install` removes, along the way, any one an interrupted installation might have left.
:::

```sh
just configure myserver
```

{/* t:p dd3f2f07c7d5a8f393df3542fbf46928a844826687c9ed08f13e5e7a370a02a7 */}
### ✳️ `copy-id <hôte>`

Checks that the `nix` deployment key can open the target host, and pushes the
shared **private** key to gateways (TLS certificate synchronization from the HCS).

:::caution[No more key drops]
SSH is key-only and `~/.ssh/authorized_keys` is no longer read:
`ssh-copy-id` has no bootstrap channel. The deployment key is
declarative (`usr/secrets/nix.pub`). If the recipe fails, fix the
configuration then apply from an still-open channel (console, sshd
initrd LUKS on port 2222).
:::

```sh
just copy-id myserver
```

Displays the MAC address of a machine's first active interface, to declare it

```sh

```

{/* t:p ee689c0e9bae99379c06bca18a6ce3f940095f7d52c6a39480ebfd7c131bd167 */}
### ✳️ `luks <hôte> [action] [ip]`

Provisions a host's encryption&nbsp;: shared and per-host passphrases in sops,
initrd SSH key in sops then on the target, `usr/secrets/luks.json` manifest,
gateways' WAN IP. See
[Disk encryption (LUKS)](/en/doc/admin-guide/operate/luks/).

| Action | Effect |
|---|---|
| (default) | Prepares the secrets, then converges the machine |
| `pre` | Offline half only, without touching the machine |
| `passwd` | Rotates the per-host passphrase, then converges |
| `show` | Read-only audit&nbsp;: keyslots and remote unlocking |

:::tip[Idempotent]
`pre` is called by `just install` before the build, the default version by
`just configure`. Without a LUKS volume in the host's disko, it is a logged
no-op.
:::

```sh
just luks myserver
just luks myserver show
just luks myserver passwd
```

{/* t:p 40874d9bfd781dfb02423530d635f069985c211874beaaa18c75567a4056b453 */}
### ✳️ `roaming [host] [ip]`

Redirects SSH to a host connected outside its zone, for the duration of the installation. Colmena addresses a node by its name, which refers to its original address; this redirect points it to where the machine actually is.

Set up by `just configure` when needed, removed by `full-install` at the end of the run. Without arguments, displays the current redirects.

```sh
just roaming             # display
just roaming myserver    # redirect (computed address)
```

### ✳️ `roaming-clear [host]`

Removes a host's redirect, or all of them if none is given.

```sh
just roaming-clear myserver
just roaming-clear
```

{/* t:p 85e0cb7cb36935cd94477dd21a189ba0f4396f16ff26983db66404d5bbe49858 */}
### ✳️ `configure-admin-host` ⭐

Configure the administration machine: SSH keys, age SOPS keys,
`.sops.yaml`, default secrets, Harmonia signing key, and **all
internal secrets** required by declared services (OAuth2
clients, backups, service tokens, etc.).

:::tip[Idempotent]
Can be safely re-run: each step checks whether it has already been completed, and
no existing secret is overwritten. Re-run after enabling a service,
adding a host or a zone. See
[Secrets](/en/doc/admin-guide/operate/secrets/#manage-passwords).
:::

```sh
just configure-admin-host
```

### ✳️ `apply <target> [action]` / `a` ⭐

Deploys the configuration on one or more targets.

| Parameter | Description |
|---|---|
| `target` | Hostname, glob (`'*'`), list (`a,b`), colmena tag (`@server`) |
| `action` | `switch` (default), `boot`, `test`, `build` |

:::note[Centralized build]
The machine running `just` builds each system once, then harmonia shares it with the fleet. To build on targets (architecture the machine cannot build): `just buildOnTarget=1 apply <target>`.
:::

```sh
just apply @all                 # all hosts
just apply myserver             # switch (default)
just apply myserver boot        # boot
just apply 'db-*'               # all hosts starting with db-
```

## Administration commands

These commands interact with fleet hosts: maintenance,
reboot, cleanup, and boot repair.

{/* t:p 9d330bebbc10ed7f0f1d8f494deb95df3363124b85db188c57f5347b25b011f0 */}
### ✳️ `enter <host>` / `e` ⭐

Opens an interactive SSH session as `nix@<host>`. If the host is waiting for its LUKS passphrase at boot (port 22 closed), it switches to its initrd sshd (port 2222, falling back to the manifest's WAN IP for a gateway) and presents the passphrase prompt. See [Disk encryption (LUKS)](/en/doc/admin-guide/operate/luks/).

```sh
just enter myserver
```

{/* t:p 9f400b7be7d3bc1a8e6bc34f3cdb28a586672c31447cf4e5309adcab3094c35e */}
### ✳️ `unlock <hôte> [ip] [délai]`

Answers the LUKS prompt of a host stuck in its initrd, **with no human**&nbsp;:
the passphrase is read from sops and pushed via the sshd on port 2222. Waits
for the host to appear (one dot per attempt), which allows chaining it right
after a reboot. Called automatically by `just full-install`.

On a host without a LUKS volume, it is a logged no-op.

```sh
just unlock myserver
```

{/* t:p 02fa3ced2db0dd6fdcdf8d51363f67974b3c73d0ae89e57b14dcf6bd883d56c4 */}
### ✳️ `remote-desktop <host> [ro|rw|login]` / `rd` ⭐

Opens the remote desktop of a host. `ro` (default) watches the **already open** graphical session, `rw` takes control of it; both fail if nobody is logged in. `login` opens **your own session** behind a GDM login screen instead. No port is opened on the host: the stream goes through an SSH tunnel set up by `nix`. See
[Remote desktop](/en/doc/admin-guide/operate/remote-desktop/).

```sh
just rd mypc                # observation
just rd mypc rw             # take control
just rd mypc login          # own session, via GDM
```

### ✳️ `gc <host> [keep]` ⭐

Removes old generations, cleans the store, then regenerates the boot entries
(`switch-to-configuration boot`). `keep` sets what is retained:

| `keep` | Generations retained |
|---|---|
| (empty) | Current only, all profiles (`nix-collect-garbage -d`) |
| `N` (1 to 99) | Last `N` system generations, current included |
| `Nd` (1 to 99) | Those less than `N` days old, plus the active one on that date |

```sh
# Clean hosts whose name starts with "server-"
```

### ✳️ `yubikey <user> [key] [action]`

Enrolls a YubiKey (`main` by default, or `backup`) for a user: PAM
(session/sudo), LUKS and Kanidm enrollment link, in a single pass on the
admin machine. `action=revoke` revokes the key across all machines at next
deployment. See [Strong authentication](/en/doc/admin-guide/operate/yubikey/).

```sh
just yubikey darkone            # enrolls the primary key
just yubikey darkone backup     # enrolls the backup key
just yubikey darkone main revoke
```

{/* t:p c721a639832b45fbdbb521264d00054fd9c54ef53c41e0d1c85d79114186406b */}
### ✳️ `rotate init|push-keys|finalize`

Rotation of the age key `/etc/sops/age/infra.key` in 3 steps with integrity
checks.

| Step | Action |
|---|---|
| `init` | Generates a new key, keeps the old one, re-encrypts secrets |
| `push-keys` | Pushes the combined key (new + old) to all hosts |
| `finalize` | Verifies all hosts have the new key, removes the old one |

:::danger[Unfinished rotation]
Do not interrupt a rotation. Sidecars `.cur` / `.old` mark an ongoing rotation.
:::

```sh
just rotate init
just rotate push-keys
just rotate finalize
```

## Co-development commands

At the root of a co-development project. Git commands operate on **all
repositories** of the project (default: `src/*/`, `dnf`, `doc`, and the
root). The short alias for `git` is `g`.

{/* t:p cbdefe32a6a73a2abcf623b8ad6b1f49de48dd5cd3c568090291f76d7773aef0 */}
### 🔗 `git <cmd> [project]`

Runs any git command on one or all projects.

:::tip[Iterated projects]
Listed by `just git-show-repos` (all by default).
:::

```sh
just git "log --oneline -5"       # latest commits of all projects
just git "status" dnf             # git status on dnf/ only
just git "remote -v"              # remotes of all projects
```

{/* t:p efacc1b9c33481552ed92afa9e004ec4b3bf35f16486327796bc46b3929d5a85 */}
### 🔗 `commit <message> [project]` ⭐

`add -A` + `commit -m` on one or all projects. If the message is
identical to the latest commit, the recipe **amends** instead of creating a new
commit.

On all projects, the root is processed last, after `update-dnf`: its
commit pins the revision of `dnf/` that was just committed.

```sh
just commit "fix(net): update dns config"
just commit "fix(net): update dns config" dnf    # dnf/ only
```

{/* t:p ab853d57f5e98d6ae271a34a4836d96825a38f00ba12437a1421ff545d80f18a */}
### 🔗 `amend [project]` ⭐

(`--no-edit`). On all projects, the root lock is then realigned to `dnf/`.

