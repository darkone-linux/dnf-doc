The commands below are all executed with [`just`](https://just.systems/man/).

```sh title=Usage
just <command> <arguments>
```

Each command is prefixed with an icon indicating its usage context:

- 💠 **Common**: available in all contexts.
- 🔆 **Framework**: specific to the upstream DNF framework (`dnf/`).
- ✳️ **Project**: specific to the consuming project (my network).
- 🔗 **Co-development**: consuming project that contains a clone of the framework.

:::caution[Privilege elevation]
Most commands run with the user who administers the project, but
some of them elevate privileges to the `nix` user (`sudo -u nix ...`).
:::

:::tip[Key commands]
Commands marked with a ⭐ are the most useful on a daily basis.
:::

## Available commands

The recipes live in `dnf/just/`. The project `Justfile` imports **one** bootstrap file, which determines the available commands depending on the context.

| Context | `Justfile` line | Commands |
|---|---|---|
| Framework | `import 'just/dnf.just'` | 💠 🔆 |
| Consumer project | `import? 'dnf/just/project.just'` | 💠 ✳️ |
| Co-development | `import 'dnf/just/codev.just'` | 💠 ✳️ 🔗 |

In a consumer project, `dnf/` is the symlink to the Nix store created by `nix run .#init`. The `?` in `import?` lets `just` start as long as this symlink does not exist.

Co-development replaces this link with a git clone of the framework. The recipes 🔆 `unit-tests`, `check-recipes`, `simulate`, `simulate-debug`, `fixtures` and `pkg-update` can also be run there from the root. Project templates include the `codev.just` line, commented out.

:::note[Context adaptation]
A project is recognized by its `etc/config.yaml`, a framework clone by `dnf/.git`. A `dnf/` symlinked to the store is read-only&nbsp;: `generate`, `format` and `check` leave it aside.
:::

## Development commands

Common to all contexts, these commands help maintain the code and
generate declarative files.

### 💠 `develop` / `d`

Runs `nix develop -c zsh` to get a shell with the project tools.

```sh
just develop
```

### 💠 `clean` / `c` ⭐

Runs the full chain: `statix fix` → `check-code` → `generate` → `format` → `_fix_fs_permissions`.

:::tip[Before committing]
`just clean` is the recommended entry point before each commit.
:::

```sh
just clean
```

{/* t:p b749b4f5b8a1ff6c59273ae71c210d208399fdbda62e9133ef2edaa62b33eb46 */}
### 💠 `format`

Runs `treefmt` on all files using the shared framework config. In
co-development, also formats `dnf/`.

```sh
just format
```

{/* t:p ae4e7f74d160a10119a0d16e2995a9313034e42c0b8e712b12ce0d85b2486211 */}
### 💠 `generate`

Regenerates the `default.nix` files of module folders and, in a project, the
`var/generated/*.nix` files from `etc/config.yaml`. It also seeds
`usr/machines/<host>/` for each host with a `disko` block (see [Machine
folder](/en/doc/how-to/admin/machines-layout/)).

:::note[Two modes]
- **Generator sources present** (`src/generator/`): `cargo run`.
- **Otherwise**: `dnf-generator` binary provided by the devShell (`just develop`).
:::

```sh
just generate
```


## Installation commands

Installing a new host follows a precise sequence.

{/* t:p 8f333d6c834ca17fab76b1d064a7937c1cf1bd05b63ef3b608258cd040d84214 */}
### ✳️ `install <host> [user] [ip]`

Formats the disks via **disko** and installs NixOS via **nixos-anywhere**.

:::danger[Destructive]
All data on the target host is erased. A confirmation is
requested before running.
:::

:::note[Required configuration]
The host must have a complete `disko` block in `etc/config.yaml` (profile and
`devices`, giving `usr/machines/<host>/install/disko.nix`), a `mac` key and a
fixed address (`zone: "<zone>:<x.y>"`). The last two points are checked before any
formatting&nbsp;: without them, the machine changes address on the reboot that follows
installation. See [Initial
installation](/en/doc/admin-guide/install/first-network-installation/#installing-a-workstation).
:::

The `ip` argument defaults to `auto`&nbsp;: the address is computed as for
`full-install`, no need to look it up.

:::caution[The address must be the one the machine keeps]
`nixos-anywhere` freezes its target address for the whole run and cannot
follow a renumbering. Yet the installer performs another DHCP&nbsp;: if the
machine had been running until then on a dynamic lease older than its reservation
(the typical case of an installation **on top of another system**), it
switches to its reserved address mid-installation and the run talks into the
void.

The recipe therefore refuses to start on an address the host does not keep, and
displays the ones it accepts. Before installing over an existing OS,
reboot the machine so that it takes its reserved address.
:::

Before formatting, the recipe reports what would make the rest fail, then
asks for confirmation&nbsp;:

| Alert | What to do |
|---|---|
| Host name unknown to the workstation | `just apply <local gateway>` |
| HCS not up to date for the host | `just apply hcs` |
| Encrypted host outside any zone | Also redirect port 2222 |

Before the very first question, it also lists the uncommitted changes outside
the host&nbsp;: they will go into its commits.

The recipe also places on the target, **before** installing the system, the
age key `/etc/sops/age/infra.key` (except on an
[isolated host](/en/doc/admin-guide/operate/secrets/#isolated-hosts)) and, on an encrypted host,
the SSH host key of its initrd&nbsp;: sops works from the first
activation and the very first boot already listens on port 2222. The volume
is formatted with the fleet's shared passphrase, so there is nothing to type.

On an isolated host, it first seals its `usr/secrets/hosts/<host>.yaml` file
for the installer's host key, which the installed system takes over&nbsp;: the
build finds it, without going through `just space-init`.

```sh
just install myserver
just install myserver nixos 10.0.0.5     # IP personnalisée
just install myserver nix auto test      # VM test uniquement
```

`nixos-anywhere` and `disko` are the ones locked by the framework, tested with
it&nbsp;: `nix run .#nixos-anywhere` and `nix run .#disko` from the project.

:::note[Installation seals the host]
Just before formatting, `install` writes `usr/machines/<host>/install/state.nix`
(`stateVersion` of the current nixpkgs release)&nbsp;: the disk layout and the
`stateVersion` are now frozen, even in case of reinstall. The hardware survey
(`hardware/`) is committed as soon as `nixos-anywhere` finishes. See [Machine
folder](/en/doc/how-to/admin/machines-layout/).
:::

:::caution[LUKS and `do=test`]
`nixos-anywhere` refuses `--vm-test` together with the options that place
files and the formatting key&nbsp;: test mode therefore cannot
format an encrypted volume. The recipe reports it.
:::

### ✳️ `full-install <host> [user] [ip]` ⭐

Full chain: `install` + wait for reboot + `unlock` + `configure` + `apply` + `gc` + reboot.

The starting address is calculated automatically: host name in its own zone, reserved pass-through address if plugged in elsewhere. See [Machines outside
their zone](/en/doc/admin-guide/understand/network/#machines-outside-their-zone).

After reboot, the machine may not have returned to the same place: the recipe probes **all** its known addresses, on ports 22 and 2222, and continues on whichever responds. An encrypted host is unlocked along the way by `just unlock`.

The final reboot is not cosmetic: `apply` activates user space but not the kernel or initrd, and this reboot is the only automatic proof that the machine restarts **on its own**. On an encrypted host, it also proves that remote unlock works, while you are still in front of it rather than at the first power outage. `unlock` is therefore called again right after.

```sh
just full-install myserver
just full-install myserver nixos 10.0.3.42   # forced address
```


### ✳️ `install-here <hôte> <login> [empreinte] [yes] [passphrase] [cache] [clé]`

Installs the machine it runs on, booted from the generic DNF ISO, as the project's administration workstation: disk o erases its disk, the keys are born on the target (`bootstrap-keys`), then `nixos-install`. The project joins the new system's `/etc/nixos`, owned by `login`. An encrypted disk requires the file for its passphrase, which becomes the fleet's shared passphrase; the initrd SSH key is placed on the target.

`cache` and `clé`: an additional package cache and its public key, for this installation only (passed by `darkone new`).

:::danger[Erases the disk of the current machine]
Refuses to run outside the generic ISO (witness file `/etc/dnf-installer`).
:::

```sh
just install-here poste alice '<empreinte>'
```

{/* t:p d4ad0660a7291391eec287e97146085ed32d91bd73a567d49cc213c7d183bf55 */}
### ✳️ `backup-admin <périphérique> [passphrase] [racine]`

Writes to a USB key, without formatting it, an age-encrypted backup of what nothing else replaces: the `nix` deployment key (which gives the admin age key), the infra age key and the project (`git bundle`). File `dnf-backup-<domaine>.tar.age`, with a plain `README.txt`; a previous backup of the same network is kept, renamed with its date.

- `périphérique`: a partition of the key, `/dev/disk/by-label/SECOURS` for example;
- `passphrase`: a file containing it; otherwise, age asks for it;
- `racine`: the system holding the keys, `/mnt` from the installer.

`darkone new` runs it after installation.

```sh
just backup-admin /dev/disk/by-label/SECOURS
```

### ✳️ `configure <host> [ip]`

Chains `copy-id` → `copy-hw` → `push-key` → `luks` (the last one does nothing on a non-encrypted host).

The address is resolved once and passed to the whole chain. If the host is plugged outside its zone, the SSH redirection is set up in the process, so that the following `apply` reaches it: `just roaming-clear <host>` once the machine is back home.

:::caution[Only for a host genuinely elsewhere]
The redirection disables host key verification, **and it stays that way until it is removed**. It is therefore only set if the used address is neither the host name nor the fixed address of its zone. `just install` removes, along the way, any one an interrupted installation might have left.
:::

```sh
just configure myserver
```

{/* t:p dd3f2f07c7d5a8f393df3542fbf46928a844826687c9ed08f13e5e7a370a02a7 */}
### ✳️ `copy-id <hôte>`

Checks that the `nix` deployment key can open the target host, and pushes the
shared **private** key to gateways (TLS certificate synchronization from the HCS).

:::caution[No more key drops]
SSH is key-only and `~/.ssh/authorized_keys` is no longer read:
`ssh-copy-id` has no bootstrap channel. The deployment key is
declarative (`usr/secrets/nix.pub`). If the recipe fails, fix the
configuration then apply from an still-open channel (console, sshd
initrd LUKS on port 2222).
:::

```sh
just copy-id myserver
```

### ✳️ `copy-hw <host>`

Runs `nixos-generate-config --show-hardware-config` remotely and saves the
result in `usr/machines/<host>/hardware/hardware-configuration.nix`,
then chains `detect-hw`.

```sh
just copy-hw myserver
```

{/* t:p d17dc0994db7f9c7685e2bb8be16ad6c5cb7a4453e754525f9cb8b0476fba3b0 */}
### ✳️ `detect-hw <hôte> [ip] [user]`

Collects on the machine the kernel modules of its wired network cards and writes them to `usr/machines/<hôte>/hardware/detected-hardware.nix` (generated file, imported automatically). They join the initrd only if it has network, for [remote LUKS unlocking](/en/doc/admin-guide/operate/luks/). Also detects a virtual machine (`systemd-detect-virt`): no firmware is loaded on it (`darkone.system.hardware.virtual`). Called by `install` (`nixos` user of the ISO) and by `copy-hw`.

```sh
just detect-hw myserver
```

### ✳️ `luks <host> [action] [ip]`

Provisions an encrypted host&nbsp;: shared and per-host passphrases
in sops, initrd SSH key in sops then on the target, `usr/secrets/luks.json`
manifest, WAN IP of the gateways. See
[Disk encryption (LUKS)](/en/doc/admin-guide/operate/luks/).

| Action | Effect |
|---|---|
| (default) | Prepares the secrets, then converges the machine |
| `pre` | Offline half only, without touching the machine |
| `passwd` | Rotates the per-host passphrase, then converges (immediately for an isolated host) |
| `show` | Read-only audit&nbsp;: keyslots and remote unlocking |

:::tip[Idempotent]
`pre` is called by `just install` before building, the default version by
`just configure`. Without a LUKS volume in the host's disko, it is a
logged no-op.
:::

```sh
just luks myserver
just luks myserver show
just luks myserver passwd
```

### ✳️ `roaming [host] [ip]`

Redirects SSH to a host connected outside its zone, for the duration of the installation. Colmena addresses a node by its name, which refers to its original address; this redirect points it to where the machine actually is.

Set up by `just configure` when needed, removed by `full-install` at the end of the run. Without arguments, displays the current redirects.

```sh
just roaming             # display
just roaming myserver    # redirect (computed address)
```

### ✳️ `roaming-clear [host]`

Removes a host's redirect, or all of them if none is given.

```sh
just roaming-clear myserver
just roaming-clear
```

### ✳️ `configure-admin-host` ⭐

Configures the administration machine: SSH keys, SOPS age keys,
`.sops.yaml`, Harmonia signing key, and **all internal secrets** required by
the declared services (OAuth2 clients, backup, service tokens…).

:::tip[Idempotent]
Can be safely re-run: each step checks whether it is already done, and no
existing secret is overwritten. Re-run after enabling a service, adding a
host or a zone. See
[Secrets](/en/doc/admin-guide/operate/secrets/#internal-secrets-and-external-secrets).
:::

```sh
just configure-admin-host
```

### ✳️ `bootstrap-keys [racine] [login] [empreinte]`

Creates the keys and the sops skeleton of a machine that has no `nix` account yet, under the given root (`/`, or `/mnt` from the installer). `configure-admin-host` relies on the same mechanism. The fingerprint of an account (`mkpasswd`, in single quotes) is optional.

```sh
just bootstrap-keys /mnt alice '<empreinte>'
```

## Deployment commands

The `apply*` commands rely on [colmena](https://github.com/zhaofengli/colmena)
and first refresh the DNF lock via `update-dnf`. `fleet-update` drives a full
update using native Nix commands.

{/* t:p ece18c6d5eea966020a1665a58fb2d9a5f883a5877b62e92e5884a772cb90e58 */}
### ✳️ `apply <target> [action]` / `a` ⭐

Deploys the configuration on one or more targets.

| Parameter | Description |
|---|---|
| `target` | Hostname, glob (`'*'`), list (`a,b`), colmena tag (`@server`) |
| `action` | `switch` (default), `boot`, `test`, `build` |

:::note[Centralized build]
The machine running `just` builds each system once, then harmonia shares it with the fleet. To build on targets (architecture the machine cannot build): `just buildOnTarget=1 apply <target>`.
:::

```sh
just apply @all                 # all hosts
just apply myserver             # switch (default)
just apply myserver boot        # boot
```

## Administration commands

These commands interact with fleet hosts: maintenance,
reboot, cleanup, and boot repair.

{/* t:p 87cfe4223c0fab5e4381d0cc7692d28386bf04e9e7395dfe897943bf8e4ca508 */}
### ✳️ `enter <hôte>` / `e` ⭐

Opens an interactive SSH session as `nix@<hôte>`, on port 22 only. A host outside its zone is located by `dnf-locate` (see
[Joining a host while travelling](/en/doc/admin-guide/understand/network/#joining-a-roaming-host)).
A host waiting for its LUKS passphrase falls under `just unlock`.

```sh
just enter myserver
```

{/* t:p f49fb84d7bab14e69ba295979c2f53803d3a7e38c4205ab8c15ec42571e9b3af */}
### ✳️ `unlock <host> [ip] [delay]`

Answers the LUKS prompt of a host left in its initrd, **without a human**&nbsp;:
the passphrase is read from sops and pushed by the sshd on port 2222. Waits for
the host to appear (one dot per attempt), which allows chaining it right
after a reboot. Called automatically by `just full-install`. No stored
passphrase accepted&nbsp;: from a terminal, the prompt is presented.

Nothing is sent to an initrd whose host key is not the one from sops. See
[LUKS encryption](/en/doc/admin-guide/operate/luks/#unlocking-at-boot).

On a host without a LUKS volume, it is a logged no-op.

```sh
just unlock myserver
```

{/* t:p 2715e281177819a120618eb9ca91e938906c3b2bd80d0857e4387c1c4abec02b */}
### ✳️ `remote-desktop <host> [ro|rw|login|stop]` / `rd` ⭐

Opens the remote desktop of a host. `ro` (default) observes the **already open**
 graphical session, `rw` takes control of it; both fail if no one is logged in.
`login` instead opens **your own session** behind a GDM login screen.
`stop` disarms a session left open. No port is opened on the host: the stream
goes through an SSH tunnel mounted by `nix`. See
[Remote desktop](/en/doc/admin-guide/operate/remote-desktop/).

```sh
just rd mypc                # observation
just rd mypc rw             # prise en main
just rd mypc login          # session à soi, via GDM
just rd mypc stop           # désarmer une session restée ouverte
```

### ✳️ `gc <host> [keep]` ⭐

Removes old generations, cleans the store, then regenerates the boot entries
(`switch-to-configuration boot`). `keep` sets what is retained:

| `keep` | Generations retained |
|---|---|
| (empty) | Current only, all profiles (`nix-collect-garbage -d`) |
| `N` (1 to 99) | Last `N` system generations, current included |
| `Nd` (1 to 99) | Those less than `N` days old, plus the active one on that date |

```sh
# Clean hosts whose name starts with "server-"
just gc "server-*"    # Keep only the current generation
just gc "server-*" 3  # Keep the last 3 generations, current included
just gc "server-*" 3d # Remove generations older than 3 days
```

### ✳️ `yubikey <user> [key] [action]`

Enrolls a YubiKey (`main` by default, or `backup`) for a user: PAM
(session/sudo), LUKS and Kanidm enrollment link, in a single pass on the admin
workstation. Adds one press per encrypted isolated host, with that host's salt&nbsp;:
rerun with an already enrolled key, it only computes what it is missing.
`action=revoke` revokes the key across the fleet on the next deployment. See
[Strong authentication](/en/doc/admin-guide/operate/yubikey/).

```sh

```

### ✳️ `rotate init|push-keys|finalize`

Rotation of the age key `/etc/sops/age/infra.key` in 3 steps with
integrity checks.

| Step | Action |
|---|---|
| `init` | Generates a new key, keeps the old one, re-encrypts the secrets |
| `push-keys` | Pushes the combined key (new + old) to all hosts |
| `finalize` | Verifies that all hosts have the new key, removes the old one |

Isolated hosts are ignored&nbsp;: they do not read this key.

:::danger[Rotation not finished]
Do not interrupt a rotation. The `.cur` / `.old` sidecars mark a rotation in progress.
:::

```sh
just rotate init
just rotate push-keys
just rotate finalize
```

## Co-development commands

At the root of a co-development project. Git commands operate on **all
repositories** of the project (default: `src/*/`, `dnf`, `doc`, and the
root). The short alias for `git` is `g`.

{/* t:p cbdefe32a6a73a2abcf623b8ad6b1f49de48dd5cd3c568090291f76d7773aef0 */}
### 🔗 `git <cmd> [project]`

Runs any git command on one or all projects.

:::tip[Iterated projects]
Listed by `just git-show-repos` (all by default).
:::

```sh
just git "log --oneline -5"       # latest commits of all projects
just git "status" dnf             # git status on dnf/ only
just git "remote -v"              # remotes of all projects
```

{/* t:p efacc1b9c33481552ed92afa9e004ec4b3bf35f16486327796bc46b3929d5a85 */}
### 🔗 `commit <message> [project]` ⭐

`add -A` + `commit -m` on one or all projects. If the message is
identical to the latest commit, the recipe **amends** instead of creating a new

commit pins the revision of `dnf/` that was just committed.

```sh
just commit "fix(net): update dns config"
just commit "fix(net): update dns config" dnf    # dnf/ only
```
