An **AI space** is a DNF host with the `ai-space` profile, usually a
[microVM guest](/en/doc/admin-guide/operate/microvm/). It runs an
[OpenClaw](https://openclaw.ai) assistant reserved for its members, with its own
secrets and its own data.

:::caution[In progress]
Web access, SSO, Matrix channel, Claude Code, Codex, OpenCode, MCP and skills in
place.
Hermes comes in a future release.
:::

## Create a space

<Steps>

1. **Declare the host and its members**

   The host's `users` are its members&nbsp;: DNF creates for them the Kanidm
   group `space-<hôte>`.

   ```yaml
   # etc/config.yaml
   - hostname: "ia-pro"
     zone: "lan:1.40"
     profile: "ai-space"
     features: ["microvm-guest:hyperviseur", "monitoring-node"]
     users: ["alice", "bob"]
     services:
       openclaw: {}
   ```

   `monitoring-node` places the space under the zone's supervision&nbsp;: without
   it, neither a space failure nor the assistant stopping triggers an alert.

   The **owner** is the member whose subscription runs the assistant&nbsp;: they
   receive approval requests and spontaneous messages (reminders, scheduled
   tasks). As the only member, they are implicit.
   With several members, the owner is declared in
   `usr/machines/ia-pro/configuration.nix` (the order of `users` is not
   preserved)&nbsp;:

   ```nix
   { darkone.service.openclaw.owner = "alice"; }
   ```

2. **Initialize the space**

   `just space-init ia-pro`&nbsp;: host key, secrets (see
   [Isolated hosts](/en/doc/admin-guide/operate/secrets/)) and, if the network
   has Matrix, the `@ia-pro:<domaine>` bot. Then commit `usr/secrets/` and
   `var/generated/spaces/`.

3. **Deploy**

   The hypervisor, the zone gateway (vhost, DNS) and the HCS (Kanidm
   group)&nbsp;: `just apply hyperviseur,gw,hcs`.

4. **Connect the AI provider**

   Once per space, from the host (`just enter ia-pro`), for each owner
   subscription used by the space's models (see
   [Models and subscriptions](#models-and-subscriptions))&nbsp;:

   | Subscription | Models | Sign-in |
   |---|---|---|
   | Claude Pro/Max, via the `claude` CLI | `anthropic/*` (default&nbsp;: `anthropic/claude-sonnet-5-5`) | `sudo -u openclaw -H claude auth login` |
   | ChatGPT Plus/Pro, via the `codex` plugin | `openai/*` | `openclaw models auth login --provider openai` |

   The host's `openclaw` command automatically switches to the service user.
   `openclaw models status` checks the connection, which stays in
   `/var/lib/openclaw`, persistent.

</Steps>

:::note[Why an `openclaw` user]
The assistant reads untrusted content (web, messages, documents)&nbsp;: a
dedicated system user keeps it away from member accounts, their keys and their
sign-ins. Members have no `sudo` (reserved for the `wheel` group)&nbsp;:
administration goes through the `nix` account.
:::

:::caution[Update]
A space created before the assistant's local password must go through
`just space-init <hôte>` again before deployment&nbsp;: it generates the
`openclaw-gateway-password` secret, through which the host's `openclaw` command
reaches the service.
:::

## Models and subscriptions

A model goes through the owner's subscription when its provider appears in
`subscriptions`, otherwise through an API key.

```nix
# usr/machines/ia-pro/configuration.nix
{
  darkone.service.openclaw = {
    model = "anthropic/claude-sonnet-5-5";
    extraModels = [ "openai/gpt-6-astra" "openrouter/moonshotai/kimi-k3" ];
    subscriptions = [ "anthropic" "openai" ]; # défaut
    apiKeys = [ "OPENROUTER_API_KEY" ];
  };
}
```

| Option | Role |
|---|---|
| `model` | Main model, `<fournisseur>/<modèle>` |
| `extraModels` | Other models, chosen in the conversation with `/model` |
| `subscriptions` | Owner subscriptions&nbsp;: `anthropic`, `openai` |
| `apiKeys` | API keys, by variable name |
| `providers` | Providers not in OpenClaw, OpenAI-compatible |

Each key (`apiKeys`, `providers.<nom>.apiKey`) is stored before deployment in
the space's secrets, under `openclaw/<VARIABLE>`
(`just space-sops <hôte>`).

:::caution[Anthropic key and Claude subscription]
The `claude` CLI prefers `ANTHROPIC_API_KEY` over its sign-in&nbsp;: alongside
the `anthropic` subscription, DNF does not pass this key. To pay for Claude per
use, remove `anthropic` from `subscriptions`.
:::

### OpenAI-compatible provider

A provider not in OpenClaw, such as Nous Portal, is declared with its address,
key and models&nbsp;:

```nix
# usr/machines/ia-pro/configuration.nix
{
  darkone.service.openclaw = {
    providers.nous = {
      baseUrl = "https://inference-api.nousresearch.com/v1";
      apiKey = "NOUS_API_KEY";
      models = [ "Hermes-4-405B" ];
    };
    model = "nous/Hermes-4-405B";
  };
}
```

### Shared subscriptions

| Use | Account |
|---|---|
| Assistant (web, Matrix, scheduled tasks) | The owner's, quota shared by members |
| A member's Claude Code, Codex, OpenCode | Their own |

A personal subscription (ChatGPT, Claude) shared by several members falls
outside the terms of use&nbsp;: a team space takes a team plan or API keys
(`subscriptions = [ ]`).

## Matrix

Members write to the bot `@<hôte>:<domaine>` in direct message, end-to-end
encrypted. The channel only exists if the network declares the `matrix`
service: without it, the space runs on its web interface alone.

| Element | Rule |
|---|---|
| Who is listened to | The space's members (`@<login>:<domaine>`), DM only; other accounts are ignored |
| Rooms | Ignored: non-members would read the replies there |
| Sessions | One per member when there are several, otherwise a single one for all channels |
| Command validation | None by default (see [Security](#security)); any request goes to the owner, via DM |
| Unsolicited messages | Sent to the owner, via DM |
| Encryption keys | In `/var/lib/openclaw`, persistent |

:::caution[Device verification]
On first startup, the bot asks for its session to be verified (`openclaw
matrix verify status` on the host). Until it is verified, Element flags its
messages as unverified.
:::

## Voice conversation

The microphone button in the web interface opens a voice conversation,
interruptible, on desktop and phone alike. OpenAI's real-time voice
(GPT-Live) answers&nbsp;; the space's assistant does the work (tools, files,
MCP), whatever its model.

```nix
# usr/machines/ia-pro/configuration.nix
{ darkone.service.openclaw.talk.enable = true; }
```

| Option | Default | Role |
|---|---|---|
| `talk.model` | `gpt-live-1-codex` | ChatGPT subscription, otherwise `OPENAI_API_KEY` |
| `talk.voice` | `cove` | Also `arbor`, `breeze`, `ember`, `juniper`, `maple`, `sol`, `spruce`, `vale` |
| `talk.instructions` | none | Added instructions (language, tone) |

The owner's ChatGPT sign-in is required
(`openclaw models auth login --provider openai`), even with an assistant on
Claude, or an `OPENAI_API_KEY` key (see
[Models and subscriptions](#models-and-subscriptions)). At most eight
conversations at a time, 30 minutes each.

:::caution[To be validated]
Not yet tried in a browser or on a phone.
:::

## Agent tools

MCP servers, skills and tools are declared once per space, in
`usr/machines/<hôte>/configuration.nix`. The assistant and each member (Claude
Code, Codex, OpenCode) receive the same ones.

```nix
{ pkgs, ... }:
{
  darkone.host.ai-space = {
    mcp.fetch = {
      command = "uvx";
      args = [ "mcp-server-fetch" ];
    };
    mcp.github = {
      command = "github-mcp-server";
      args = [ "stdio" ];
      secretEnv = [ "GITHUB_PERSONAL_ACCESS_TOKEN" ];
    };
    mcp.docs.url = "https://mcp.example.com/mcp";
    skills.rapport = ./skills/rapport;   # dossier avec SKILL.md
    packages = [ pkgs.uv pkgs.pandoc pkgs.github-mcp-server ];
  };

  darkone.service.openclaw = {
    workspace."AGENTS.md" = ./AGENTS.md;
    projects.notes = "https://forge.example.com/alice/notes.git";
  };
}
```

| Option | Role |
|---|---|
| `darkone.host.ai-space.mcp` | MCP servers, local (`command`, `args`, `env`, `secretEnv`) or remote (`url`, `headers`) |
| `darkone.host.ai-space.skills` | Skills by name&nbsp;: `SKILL.md` content, file or directory |
| `darkone.host.ai-space.packages` | Tools in the assistant's and members' PATH |
| `darkone.host.ai-space.enableClaude`, `enableCodex`, `enableOpenCode` | Claude Code, Codex and OpenCode, enabled by default |
| `darkone.host.ai-space.projectsDir` | Shared projects directory (default `/var/lib/projects`) |
| `darkone.service.openclaw.exec` | Command policy (see [Security](#security)) |
| `darkone.service.openclaw.identity` | Assistant name, emoji and avatar (`name`, `emoji`, `avatar`) |
| `darkone.service.openclaw.workspace` | Assistant workspace files (`AGENTS.md`, `SOUL.md`…) |
| `darkone.service.openclaw.projects` | Git repositories cloned once into the projects directory |
| `darkone.service.openclaw.transcription` | Voice note transcription (see [Transcription](#transcription)) |

:::danger[MCP secrets&nbsp;: `secretEnv` only]
`env` and `headers` are written to the Nix store, readable by everyone. An API
key goes through `secretEnv`, for a local server&nbsp;: each variable is read
from the space's secrets file, under the `mcp/<serveur>/<VARIABLE>` key
(`just space-sops <hôte>`, before deployment). A remote server receives no
secret.
:::

:::note[Workspace]
Declared files are rewritten each time the assistant starts. The others
(memory, files created by the agent) belong to it. Projects are never updated
automatically&nbsp;; a failed clone is reported in
`journalctl -u openclaw-projects` without blocking deployment. An SSH
repository uses the `openclaw` user's key, to be created once
(`sudo -u openclaw -H ssh-keygen -t ed25519`) then declared on the forge
(`/var/lib/openclaw/.ssh/id_ed25519.pub`)&nbsp;; the server key is accepted on
the first clone.
:::

### Transcription

Voice notes, from Matrix or the web, are transcribed by whisper.cpp, with no
external service&nbsp;:

| Space | Transcription |
|---|---|
| MicroVM guest | Hypervisor server, `large-v3-turbo` model |
| Physical machine | On the space, `small` model (466&nbsp;Mo, CPU) |

Hypervisor server unreachable or too slow&nbsp;: the space transcribes by
itself with `small`. `transcription.backend = "local"` always keeps
transcription in the guest. The language is detected for each note&nbsp;;
`transcription.language = "fr"` fixes it.

## Projects and coding agents

The projects directory (`/var/lib/projects`, linked as `~/projects` for each
member) is shared&nbsp;: any file created by a member or by the assistant
remains editable by the others. It is the assistant's working directory&nbsp;;
its instructions and memory stay in its workspace.

From the conversation (web or Matrix), the assistant hands code to Claude Code,
Codex or OpenCode&nbsp;:

| Mode | Use |
|---|---|
| `/acp spawn claude` (or `codex`, `opencode`) | Coding session tied to the conversation, can be resumed |
| Background task (`coding-agent` skill) | Long work, completion reported by message |

Each tool signs in once, on the host&nbsp;:

| Tool | Sign-in |
|---|---|
| Claude Code | The owner's (see [Create a space](#create-a-space)) |
| Codex (session) | `sudo -u openclaw -H codex login --device-auth` |
| Codex (background task) | `sudo -u openclaw -H env CODEX_HOME=/var/lib/openclaw/.codex-coding-agent codex login --device-auth` |
| OpenCode | `sudo -u openclaw -H opencode auth login` |

:::caution[Update]
`projects` used to be cloned into `/var/lib/openclaw/workspace/projects/`.
They are now cloned into the projects directory&nbsp;: move existing clones
there, or let them re-clone at the next start.
:::

## Workflows

| Tool | Use |
|---|---|
| Automations | Assistant scheduled tasks (morning briefing, monitoring) |
| [Lobster](https://docs.openclaw.ai/tools/lobster) | Chaining steps with approvals, resume without redoing everything |

The assistant and the interface create their own automations&nbsp;; Nix can
also declare some&nbsp;:

```nix
# usr/machines/ia-pro/configuration.nix
{
  darkone.service.openclaw.automations.briefing = {
    schedule = "0 7 * * 1-5"; # cron, ou "every 2h"
    message = "Résume mon agenda et mes mails non lus.";
  };
}
```

| Option | Role |
|---|---|
| `schedule`, `message` | When, and the request made to the assistant |
| `announce` | Sends the answer into the conversation (default) |
| `model` | Model specific to this task |
| `enable` | `false`&nbsp;: disabled, then re-enableable from the interface only |

Declared automations are resynchronized on each start&nbsp;: a change made in
the interface is overwritten, a removed declaration deletes its task. The
others are never touched.

Lobster is enabled with `lobster = true`&nbsp;; its files go through the
workspace (`workspace."workflows/tri.lobster" = ./tri.lobster;`), and the
assistant runs them on demand.

:::caution[To be validated]
Lobster has not been tried on a space yet.
:::

## Member accounts

Each member has a Linux account on the space, kept minimal&nbsp;:

| Item | On the space |
|---|---|
| Home Manager profile | `space-member` (zsh, git, vim, tmux), instead of their own |
| Space tools | Claude Code, Codex and OpenCode, with the space's MCP servers and skills (`darkone.home.aiSpace`) |
| Customizations | `usr/users/<login>/space.nix` (all their spaces), then `usr/users/<login>/spaces/<hôte>.nix` (this space), if they exist |
| `usr/users/<login>/default.nix` | Ignored&nbsp;: reserved for their workstations |
| Rights | `projects` group only (no `sudo`), whatever their profile |

Administering the space goes through the `nix` account
(`just enter <hôte>`).

:::tip[Customizing a space]
These files are ordinary Home Manager modules&nbsp;: packages, aliases, git
configuration, other imported modules. A personal MCP server is added there
with `programs.mcp.servers.<nom>`.
:::

Each member signs in to their own subscriptions, once&nbsp;: `claude` (then
`/login`), `codex login --device-auth` and `opencode auth login`. OpenCode
accepts a ChatGPT subscription or an API key, not the Claude subscription.

| Item | Rule |

| Address | `https://openclaw.<zone>.<domaine>` |

## Modifiable configuration

By default, Nix freezes the assistant's configuration&nbsp;: the web interface
displays it read-only. `darkone.service.openclaw.mutableConfig = true` makes it
modifiable, in the interface or via `openclaw config set` on the host, and
gives the owner administrative rights.

| Settings | Who decides |
|---|---|
| Access, Matrix channel, plugins, MCP, transcription | Nix&nbsp;: restored at startup and on every change |
| Model, commands, identity | Nix on first startup, then the interface |
| Others | The interface |

:::caution[Setting seeded by Nix]
Once written, a model, command or identity setting no longer follows Nix.
`openclaw config unset <clé>` removes it&nbsp;: Nix immediately rewrites it
with its value.
:::

## Security

By default, the assistant runs its commands without validation, like
OpenClaw&nbsp;: the barrier is the space itself (microVM cut off from the LAN,
secrets specific to the space). Its service is also confined&nbsp;: it only
writes to `/var/lib/openclaw` and the projects folder, and sees neither the
members' personal folders nor their processes.

`darkone.service.openclaw.exec` selects the policy&nbsp;:

| Value | Commands |
|---|---|
| `full` (default) | All, without validation |
| `ask` | Allowlisted ones pass, the others are submitted to the owner |
| `auto` | A model examines those outside the allowlist and submits doubtful cases to the owner |
| `allowlist` | Allowlisted ones only |
| `deny` | None |

The allowlist is filled on the host&nbsp;:
`openclaw approvals allowlist add --agent main <chemin>`.

:::caution[Validation and Claude Code]
With an `anthropic/*` model (`claude` CLI), outside `full`, pipes, redirections
and substitutions are refused without a prompt&nbsp;: the assistant becomes
noticeably less capable. Validation prevents mistakes; it does not stop a
hijacked assistant, which runs under the same user as the service.
:::

:::note[Validation reserved for the owner]
Only the owner validates, by DM or in the web interface. A device paired before
this setting keeps its right&nbsp;: remove it with `openclaw devices list` then
`openclaw devices remove <id>`, it re-pairs on the next visit.
:::

:::caution[What the assistant can read]
It runs under the `openclaw` user&nbsp;: everything the service holds is within
its reach, including the owner's connection to the AI provider and the Matrix
bot token. Trapped content (web page, document, message) can make it disclose
this information&nbsp;: do not entrust anything to a space that must not be
able to leak it.
:::

:::note[Trusted members]
A space is a single circle of trust&nbsp;: each member's web interface displays
all sessions, including the others' DMs. People who do not trust each other
each take their own space.
:::
