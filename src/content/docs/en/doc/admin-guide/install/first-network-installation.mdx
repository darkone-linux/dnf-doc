A DNF network is set up **step by step**, and you can stop at any stage: a single workstation is enough to get started.

{/* t:p 7168edbb289fe3fc37cb470e6a00a3d543db88eeaef4c1d9f04068d3c6581a84 */}
## The path

1. **A workstation** : the administrator's machine (this page).
2. **A gateway** : create a [zone](/en/doc/admin-guide/install/gateway/) and connect other machines to it.
3. **Coordination** : connect zones via [VPN](/en/doc/admin-guide/install/hcs/) (tailnet).

:::note[A single configuration]
All nodes are described in **one** NixOS configuration, on the administrator's
machine. From there, the entire network is deployed and evolved.
:::

## Create the project

The project starts from the `dnf-boilerplate` template: a ready-made structure
and a commented `etc/config.yaml` to fill in.

<Steps>

1. **Create the repository**

   From the [dnf-boilerplate](https://github.com/darkone-linux/dnf-boilerplate)
   template ("Use this template" button), or by cloning.

2. **Bootstrap the framework**

   ```sh
   nix run github:darkone-linux/darkone-nixos-framework#init
   nix develop github:darkone-linux/darkone-nixos-framework
   ```

   :::note[What does `#init` do?]
   It creates the `dnf/` link to the framework tree in the nix store: this is
   what gives `just` its recipes and the generator its profiles. Then
   `just --list` shows all the available commands.

   Once the project has its own `flake.lock`, you refresh this link with
   `nix run .#init`: this form follows the revision pinned by the project, so
   the tooling never diverges from the built system.
   :::

3. **Initialize the secrets**

   ```sh
   just configure-admin-host
   ```

   :::tip[Idempotent]
   Creates the age keys, the `.sops.yaml` file, the reference password and the
   [internal secrets](/en/doc/admin-guide/operate/secrets/#internal-secrets-and-external-secrets)
   of the declared services. Never recreates what already exists: re-run it
   after each new service, host or zone.
   :::

</Steps>

## Describe the configuration

Everything is declared in `etc/config.yaml` (network, zones, users, hosts).
For a first machine, one zone, one user and one host are enough: every host
belongs to a zone (or carries a public `ipv4` address).

```yaml
# etc/config.yaml
zones:
  main:
    description: "Réseau principal"
    ipPrefix: "10.0"          # cette zone utilise 10.0.0.0/16

users:
  alice:
    uid: 1000
    name: "Alice"
    profile: "nix-admin"
    groups: ["global"]

hosts:
  - hostname: "poste"
    name: "Poste de l'administrateur"
    zone: "main:1.10"         # IP fixe 10.0.1.10 ("main" seul = DHCP)
    profile: "desktop"
    users: ["alice"]
    disko:
      profile: "btrfs-1-disk"
      devices:
        main: "/dev/nvme0n1"
```

Then regenerate, verify and commit:

```sh
just generate      # produit var/generated/*.nix depuis etc/config.yaml
just check-flake   # nix flake check
git add . && git commit -m "Premier hôte"
```

:::caution[Generated files]
`var/generated/` is produced by the tool: never edit it by hand. You edit
`etc/config.yaml`, then regenerate. `just generate` also seeds the files the
framework expects: `usr/users/<login>/` for each account and
`usr/machines/<host>/` for each host with a `disko` block.
:::

:::danger[Commit before building]
nix flakes only see files tracked by git. An uncommitted
`var/generated/hosts.nix` or `usr/machines/<host>/` makes all builds fail.
:::

## Install a machine

Installation burns an image, boots the machine from it, then applies the full
system.

<Steps>

1. **Generate the image**

   ```sh
   just build-iso
   ```

2. **Boot the machine**

   Burn the image to a USB stick, connect the computer to the network **via
   Ethernet**, then boot from the stick. Before the command prompt, the screen
   shows a DNF welcome message, then the IP address and the MAC address of the
   interface connected to the Internet (served by the local gateway or your
   router)&nbsp;: write them down.

   ```text
   - IP: 10.0.0.50
   - MAC: aa:bb:cc:dd:ee:ff
   ```

   The `dnf-netinfo` command displays them again.

3. **Set fixed addresses** (once a zone exists)

   Installation ends with a reboot, and the following steps must find the
   machine again. Two cases&nbsp;:

   - **MAC address already declared**: nothing to do, the gateway serves the
     same fixed address to the USB stick and the installed system;
   - **unknown MAC address**: write it down, then declare it.

   ```sh
   # just host-info <hôte> <ip-actuelle>
   just host-info poste 10.0.0.50
   ```

   Report the value in `etc/config.yaml`, with a **fixed address**, then
   redeploy the gateway of every affected zone&nbsp;:

   ```yaml
   # etc/config.yaml
   - hostname: "poste"
     zone: "maison:2.1"
     mac: "aa:bb:cc:dd:ee:ff"
   ```

   :::caution[Outside the dynamic DHCP range]
   The fixed address must be **outside** the zone's `dhcp-range` (by default
   `<préfixe>.3.200` to `<préfixe>.3.249`). Within the range, the reservation is
   only honored as long as the address has not already been leased to someone
   else&nbsp;: the machine then silently changes address at its first boot. The
   generator refuses this case.
   :::

   ```sh
   # Redéployer la passerelle locale
   just clean
   git add . && git commit -m "host(poste): installation"
   just apply gw
   ```

4. **Install the system**

   :::caution[Before starting the installation]
   Make sure the machine boots by default to the disk that will host the
   system and not to the installation USB stick.
   :::

   ```sh
   # just full-install <hôte> <utilisateur> <ip>
   just full-install poste nixos 10.0.0.50
   ```

   :::tip[Within a few minutes]
   `full-install` installs the system, the programs, the configurations and the
   users. When it reboots automatically, it probes **all** the machine's known
   addresses (the installation one, its zone's, the transient one, its name)
   and continues on whichever one answers. On an encrypted host, it also
   answers the LUKS prompt on its own. In case of failure, the detailed steps
   are in the `Justfile`.
   :::

   :::note[Install over an existing system]
   A machine that already runs may hold a dynamic lease older than its
   reservation. `nixos-anywhere` freezes its target address for the whole
   run&nbsp;: as soon as its installer does DHCP again, the machine switches to
   its reserved address and the run talks into the void.

   The recipe now refuses to start on an address that the host does not keep.
   The simplest is to reboot the machine before installing, so that it takes
   its reserved address.

   If the case still happens, **nothing is lost**&nbsp;: the installer is
   already loaded in memory on the machine, at the right address this time.
   Just run it again, the loading phase is skipped automatically&nbsp;:

   ```sh
   just full-install poste root 10.0.2.1
   ```
   :::

5. The system is installed and up to date.

</Steps>

:::note[You can stop here]
A standalone machine is already fully usable. The
[gateway](/en/doc/admin-guide/install/gateway/) is only needed to create a
zone (shared local network).
:::
