A DNF network is set up **step by step**, and you can stop at any stage: a single workstation is enough to get started.

{/* t:p 9069333d30874b4ad79d8f3d515baa990d526250ef0e55648bb95dab62bdc68d */}
## The journey

1. **A workstation**: the administrator's machine (this page).
2. **A gateway**: create a [zone](/en/doc/admin-guide/install/gateway/) and connect other workstations to it.
3. **Coordination**: link the zones together with a [VPN](/en/doc/admin-guide/install/hcs/) (tailnet).

:::note[A single configuration]
All nodes are described in **one** NixOS configuration, on the administrator's machine. From there, the whole network is deployed and evolved. This machine is itself a DNF host: the administration recipes run under its `nix` deployment account.
:::

### Scripted installation

A answers file stands in for questions&nbsp;; a missing answer is asked for,
or refused with `--non-interactive`.

```yaml
# reponses.yaml
version: 1
admin:
  login: "alice"
  name: "Alice Martin"
  passwordHash: '$y$j9T$...'    # mkpasswd -m yescrypt
network:
  domain: "example.org"
host:
  hostname: "poste"
disk:
  encrypt: true
locale:
  language: "fr_FR.UTF-8"
backup:
  device: "/dev/disk/by-label/SECOURS"   # clé USB de la sauvegarde
cache:                                   # facultatif
  url: "http://cache.lan:5000"
  publicKey: "cache.lan-1:..."           # inutile si signé par cache.nixos.org
```

```sh
darkone new --answers reponses.yaml --non-interactive --yes \
  --luks-passphrase-file /run/user/1000/luks
```

The disk passphrase never enters the answers file, which circulates&nbsp;:
`--luks-passphrase-file` reads it from a file, otherwise it is asked for. It
also encrypts the backup&nbsp;; on an unencrypted disk, that is
`--backup-passphrase-file`. In scripted mode, the USB key is read back without
being unplugged.

### Key backup

`dnf-backup-<domain>.tar.age`, encrypted with age, contains:

- `nix/`: the (SSH) deployment key and the admin age key derived from it;
- `infra.key`: the infra age key;
- `project.bundle`: the project, `/etc/nixos`, as a `git bundle`.

To open it, on any Linux with age:

```sh
age -d dnf-backup-example.org.tar.age | tar -x
git clone dnf-backup/project.bundle mon-reseau
```

On a new administration workstation, the keys go back in place, under the `nix` account, in mode 600: `/home/nix/.ssh/id_ed25519`, `/home/nix/.config/sops/age/keys.txt` and `/etc/sops/age/infra.key`. As the project evolves: `just backup-admin <device>` redoes the backup ([recipes](/en/doc/admin-guide/operate/justfile/)).

`--dry-run` prints the plan without touching anything, on any machine.

## Creating the project

Manual path, from an administration machine that is already a DNF host.
The project starts from the template provided by the framework: a ready-made structure and a commented `etc/config.yaml` to fill in.

<Steps>

1. **Create the repository**

   ```sh
   nix flake new -t github:darkone-linux/darkone-nixos-framework mon-reseau
   cd mon-reseau && git init && git add -A
   ```

   The project pins the latest framework release. Another path: the GitHub template [dnf-boilerplate](https://github.com/darkone-linux/dnf-boilerplate) (the "Use this template" button), a published copy of the same template.

2. **Bootstrap the framework**

   ```sh
   nix run github:darkone-linux/darkone-nixos-framework#init
   nix develop github:darkone-linux/darkone-nixos-framework
   ```

   :::note[What does `#init` do?]
   It creates the `dnf/` symlink to the framework tree in the nix store: that is what gives `just` its recipes and the generator its profiles. Then `just --list` lists all available commands.

   Once the project has its own `flake.lock`, refresh this symlink with `nix run .#init`: this form follows the revision pinned by the project, so the tooling never diverges from the built system.
   :::

3. **Initialize the secrets**

   ```sh
   just configure-admin-host
   ```

   :::tip[Idempotent]
   Creates the age keys, the `.sops.yaml` file, the reference password and the [internal secrets](/en/doc/admin-guide/operate/secrets/#internal-secrets-and-external-secrets) of the declared services. It never recreates what already exists: rerun it after every new service, host or zone.
   :::

</Steps>

## Describing the configuration

Everything is declared in `etc/config.yaml` (network, zones, users, hosts).
For a first workstation, one zone, one user and one host suffice: every host belongs to a zone (or carries a public `ipv4` address).

An editor with yaml-language-server (Zed, VS Code with the YAML extension…) completes and validates every key, thanks to this first line of the file (already present in a project created from the template):

```yaml
# yaml-language-server: $schema=../dnf/config/config.schema.json
```

```yaml
# etc/config.yaml
zones:
  main:
    description: "Réseau principal"
    ipPrefix: "10.0"          # cette zone utilise 10.0.0.0/16

users:
  alice:
    uid: 1000
    name: "Alice"
    profile: "nix-admin"
    groups: ["global"]

hosts:
  - hostname: "poste"
    name: "Poste de l'administrateur"
    zone: "main:1.10"         # IP fixe 10.0.1.10 ("main" seul = DHCP)
    profile: "desktop"
    users: ["alice"]
    disko:
      profile: "btrfs-1-disk"
      devices:
        main: "/dev/nvme0n1"
```

Then regenerate, check and commit:

```sh
just generate      # produit var/generated/*.nix depuis etc/config.yaml
just check-flake   # nix flake check
git add . && git commit -m "Premier hôte"
```

:::caution[Generated files]
`var/generated/` is produced by the tool: never edit it by hand.
Edit `etc/config.yaml`, then regenerate. `just generate` also seeds the files the framework expects: `usr/users/<login>/` for each account and `usr/machines/<host>/` (`configuration.nix`, `install/disko.nix`) for each host with a `disko` block.
:::

:::danger[Commit before building]
Nix flakes only see files tracked by git. An uncommitted `var/generated/hosts.nix` or `usr/machines/<host>/` makes every build fail.
:::

## Installing a workstation

The installation writes an image, boots the machine from it, then applies the full system.

<Steps>

1. **Get the image**

   ```sh
   just build-iso
   ```

   This image carries your deployment key. Another path, without building: the generic ISO attached to each
   [framework release](https://github.com/darkone-linux/darkone-nixos-framework/releases)
   (`dnf-installer-vX.Y.Z-x86_64-linux.iso`); the key then authorizes itself at boot.

2. **Boot the machine**

   Write the image to a USB stick, plug the computer into the network **wired**, then boot from the stick. Before the command prompt, the screen shows a DNF welcome message, then the IP address and MAC address of the interface connected to the Internet (served by the local gateway or your router): note them down.

   ```text
   - IP: 10.0.0.50
   - MAC: aa:bb:cc:dd:ee:ff
   ```

   The `dnf-netinfo` command displays them again.

   With the generic ISO, the screen reminds you: set a password (`passwd`), then authorize the key from the admin workstation.

   ```sh
   sudo -i -u nix ssh-copy-id nixos@10.0.0.50
   ```

3. **Set the addresses** (as soon as a zone exists)

   The installation ends with a reboot, and the next steps must find the machine again. Two cases:

   - **MAC address already declared**: nothing to do, the gateway serves the same static address to the USB stick and the installed system;
   - **MAC address unknown**: read it, then declare it.

   ```sh
   # just host-info <hôte> <ip-actuelle>
   just host-info poste 10.0.0.50
   ```

   Enter the value in `etc/config.yaml`, with a **static address**, then redeploy the gateway of each affected zone:

   ```yaml
   # etc/config.yaml
   - hostname: "poste"
     zone: "maison:2.1"
     mac: "aa:bb:cc:dd:ee:ff"
   ```

   :::caution[Outside the dynamic DHCP range]
   The static address must be **outside** the zone's `dhcp-range` (by default `<prefix>.3.200` to `<prefix>.3.249`). Inside the range, the reservation is only honored as long as the address has not already been lent to someone else: the machine then changes address at its first boot, silently. The generator refuses this case.
   :::

   ```sh
   # Redéployer la passerelle locale
   just clean
   git add . && git commit -m "host(poste): installation"
   just apply gw
   ```

4. **Install the system**

   :::caution[Before starting the installation]
   Make sure the machine reboots by default onto the disk that will hold the system, not the installation USB stick.
   :::

   ```sh
   # just full-install <hôte> <utilisateur> <ip>
   just full-install poste nixos 10.0.0.50
   ```

   :::tip[In a few minutes]
   `full-install` installs the system, the programs, the configurations and the users. When it reboots automatically, it probes **all** known addresses of the machine (the installation one, its zone one, the transient one, its name) and continues on whichever answers. On an encrypted host, it also answers the LUKS prompt by itself. In case of failure, the detailed steps are in the `Justfile`.
   :::

   :::note[Installing over an existing system]
   A machine already running may hold a dynamic lease older than its reservation. `nixos-anywhere` freezes its target address for the whole run: as soon as its installer does a new DHCP, the machine switches to its reserved address and the run talks into the void.

   The recipe now refuses to boot on an address the host does not keep. The simplest fix is to reboot the machine before installing, so it takes its reserved address.

   If the case still occurs, **nothing is lost**: the installer is already loaded in memory on the machine, at the right address this time. Just rerun it there; the loading phase is skipped automatically:

   ```sh
   just full-install poste root 10.0.2.1
   ```
   :::

5. The system is installed and up to date.

</Steps>

:::note[You can stop here]
A standalone workstation is already fully usable. The [gateway](/en/doc/admin-guide/install/gateway/) is only needed to create a zone (shared local network).
:::
