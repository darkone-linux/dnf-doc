A DNF network is set up **step by step**, and you can stop at any stage: a single workstation is enough to get started.

{/* t:p 111b4977ba6921c33b1667a6d080e739005addc68ca5b84b74997ce64a582c2c */}
## The path

1. **A workstation** : the administrator's machine (this page).
2. **A gateway** : create a [zone](/en/doc/admin-guide/install/gateway/) and connect other machines there.
3. **Servers and services** : files, photos, messaging… see the [service catalogue](/en/doc/admin-guide/operate/services/).
4. **Internet** : link zones through [VPN](/en/doc/admin-guide/install/hcs/) (tailnet).

:::note[A single configuration]
All nodes are described in **one** NixOS configuration, on the administrator's
machine. From there, we deploy and evolve the whole network. This machine is
itself a DNF host&nbsp;: the administration recipes run under its deployment
account `nix`.
:::

## Prerequisites

| Item | Required |
|---|---|
| Machine | x86_64, UEFI recommended |
| Secure Boot | disabled |
| Disk | 20 GB minimum |
| Memory | 4 GB (threshold: 3500 MiB) |
| USB keys | two: installer and backup |
| Network | Internet, ≈ 5 GB downloaded |

Disk encryption requires UEFI. The memory check reads `MemTotal`&nbsp;:
a 4 GB machine passes.

## Prepare the key

<Steps>

1. **Download**

   The ISO and its checksum, attached to each
   [framework release](https://github.com/darkone-linux/darkone-nixos-framework/releases)&nbsp;:
   `dnf-installer-vX.Y.Z-x86_64-linux.iso` and its `.sha256`.

2. **Verify the checksum**

   In the folder containing both files&nbsp;:

   ```sh
   sha256sum -c dnf-installer-vX.Y.Z-x86_64-linux.iso.sha256
   ```

   Expected&nbsp;: `dnf-installer-vX.Y.Z-x86_64-linux.iso: OK`.

3. **Burn the key**

   Locate the key with `lsblk`, then write the image to it&nbsp;:

   ```sh
   sudo dd if=dnf-installer-vX.Y.Z-x86_64-linux.iso of=/dev/sdX bs=4M status=progress conv=fsync
   ```

   :::caution[The device is erased]
   A wrong `/dev/sdX` erases another disk&nbsp;: check size and
   model in `lsblk`.
   :::

</Steps>

## Assisted installation

The first workstation installs itself, from the generic ISO, without another
machine&nbsp;: it is the simplest path. The `darkone new` wizard is displayed
in English.

<Steps>

1. **Boot the machine** on the key, preferably wired.

   Without a cable, the console waits for the network, and `Enter` opens `nmtui` to
   choose a Wi-Fi. Once the network is up, a menu offers three choices (type
   the number, then `Enter`)&nbsp;:

   | Choice | Effect |
   |---|---|
   | *1) New network* | starts `darkone new` (this page) |
   | *2) Add this machine to an existing network* | see [Add a machine](/en/doc/admin-guide/install/add-host/) |
   | *3) Shell* | command prompt |

2. **Answer the wizard**

   Choose *1*. Before the first question, the wizard checks the memory,
   the network and the clock&nbsp;; on failure, *Check again*, *Connect to
   Wi-Fi* or *Abort*. From the command prompt (`Ctrl-C` or choice *3*), it
   restarts&nbsp;:

   ```sh
   darkone new
   ```

   It asks for the language and keyboard, the administrator's identity and
   password, the network domain (`home.arpa` if you have no domain of your
   own), the machine name, the disk if there are several (nothing below
   20&nbsp;GB&nbsp;: the backup key is never offered), disk
   encryption, then the disk passphrase. The rest is
   detected&nbsp;: laptop or desktop, UEFI or BIOS, country time zone.
   Unencrypted disk&nbsp;: a passphrase for the key backup.

   The disk passphrase becomes the fleet passphrase (`luks-passphrase`)&nbsp;:
   any encrypted host installed afterwards is formatted with it. See
   [Disk encryption (LUKS)](/en/doc/admin-guide/operate/luks/).

3. **Confirm**

   The summary points out the final choices (domain, login, zone). The
   disk is then erased and the system installed, project included in
   `/etc/nixos`.

4. **Back up the keys**, on a second USB key

   Plug in a USB key (FAT, exFAT, ext4…), choose it&nbsp;: nothing is
   erased on it. The wizard writes `dnf-backup-<domain>.tar.age` there, then asks you to
   unplug and replug it to read it back. No key possible (a
   VM)&nbsp;: *Skip for now*, at your own risk, then
   `just backup-admin <device>` from the installed system.

5. **Reboot**, with the USB keys removed.

   The wizard asks *Remove the installation USB key. Reboot now?* (no by
   default). Encrypted disk&nbsp;: the passphrase is requested at every
   boot, with the chosen keyboard. The first session opens a home
   page in the browser&nbsp;: step 1 of 4 completed, the gateway
   next. It stays within reach in the **Local network** folder of the
   applications (*First steps*), along with the documentation (*DNF Doc*) and a
   terminal in the `/etc/nixos` project (*Network sources*), whose
   `README.md` summarizes everyday use.

</Steps>

:::danger[Without a backup, a lost disk takes all secrets with it]
The `nix` deployment key, the infra age key and the project exist only on
this workstation. The backup, encrypted by the disk passphrase (or the
backup passphrase, for an unencrypted disk), contains them all&nbsp;: store it far from
the machine.
:::

## FAQ

{/* t:p 58a038f48a307758f152a5edc840429a0ca0dec59efa622cf346f10ecdc98c52 */}
### What if the installation fails?

- `nixos-install` is restarted on its own, 3 attempts (*attempt N/3*)&nbsp;; the store already copied is kept.
- Beyond that, *Retry? [y/N]* at a terminal, otherwise the failure is reported.
- `Ctrl-C` stops without a new attempt, and returns control.
- Restart `darkone new` in the same ISO session&nbsp;: *Previous install*.
- *Resume* : same answers, project and disk kept, nothing erased.
- *Start from scratch* : project deleted, disk erased after the summary.
- *Abort* : nothing changes.

The answers live in RAM (`$XDG_RUNTIME_DIR/dnf-answers.yaml`), the
passphrases never&nbsp;: *Resume* asks for them again. If resuming is impossible,
the wizard says why (*It cannot be resumed*) and offers only the rest.
If the ISO is rebooted, the project is lost&nbsp;: start from scratch.

{/* t:p 5499f2987704f4743a5d935cfcec39c2ab175338c6e717e5ab9f778d6d7e4209 */}
### No cable, Wi-Fi?

At boot, `Enter` opens `nmtui`&nbsp;; from the command prompt,
`nmtui` does the same. A check that fails also offers *Connect to Wi-Fi*.
A captive portal blocks the installation&nbsp;: sign in there first.

{/* t:p 2aa93b0baea0d3579b93fe7b8511eba94f1a4dfdd6dd879d12936d4b93aa6bb6 */}
### Installing in a VM?

On a Linux with Nix and KVM, a single command boots the ISO in a
QEMU window, virtual disk included&nbsp;:

```sh
nix run github:darkone-linux/darkone-nixos-framework#try
```

The disk is kept from one run to the next (`~/.local/share/dnf-try`)&nbsp;;
`nix run …#try -- --reset` starts from scratch. A VM has no USB key for the
backup&nbsp;: *Skip for now*, then `just backup-admin` once installed.

{/* t:p ed839c7e7054a2befaa80b572492eb35bab5d0ffc5d1cd7983974f1f434be1fb */}
### Installing by script?

An answers file takes the place of the questions&nbsp;; a missing answer is
requested, or refused with `--non-interactive`.

```yaml
# reponses.yaml
version: 1
admin:
  login: "alice"
  name: "Alice Martin"
  passwordHash: '$y$j9T$...'    # mkpasswd -m yescrypt
network:
  domain: "example.org"
host:
  hostname: "poste"
disk:
  encrypt: true
locale:
  language: "fr_FR.UTF-8"
backup:
  device: "/dev/disk/by-label/SECOURS"   # clé USB de la sauvegarde
```

```sh
darkone new --answers reponses.yaml --non-interactive --yes \
  --luks-passphrase-file /run/user/1000/luks
```

The disk passphrase never goes into the answers file, which
gets passed around&nbsp;: `--luks-passphrase-file` reads it from a file, otherwise it is
requested. It also encrypts the backup&nbsp;; for an unencrypted disk, it is
`--backup-passphrase-file`. In scripted mode, the USB key is read back without being
unplugged.

- `--resume` : resumes the interrupted installation of the session (with `--non-interactive`).
- `--dry-run` : displays the plan without touching anything, on any machine.
- Serial console&nbsp;: no menu, run `darkone new` manually.
- Package cache, in addition to cache.nixos.org&nbsp;: `--cache <url>`, `DNF_CACHE` or `cache.url`.

### What does the backup contain?

`dnf-backup-<domain>.tar.age`, encrypted with age, on the key's file
system, with its `dnf-backup-<domain>.README.txt` in plain text&nbsp;:

- `nix/`&nbsp;: the deployment key (SSH) and the admin age key derived from
  it&nbsp;;
- `infra.key`&nbsp;: the infra age key&nbsp;;
- `project.bundle`&nbsp;: the project, `/etc/nixos`, as a `git bundle`.

To open it, on any Linux with age&nbsp;:

```sh
age -d dnf-backup-example.org.tar.age | tar -x
git clone dnf-backup/project.bundle mon-reseau
```

On a new administration workstation, the keys take their place again, under
the `nix` account, in mode 600&nbsp;: `/home/nix/.ssh/id_ed25519`,
`/home/nix/.config/sops/age/keys.txt` and `/etc/sops/age/infra.key`. The project
evolves&nbsp;: `just backup-admin <device>` redoes the backup, keeping
the old one renamed with its date
([recipes](/en/doc/admin-guide/operate/justfile/)).

{/* t:p 8e21ef1678e1863bc98831caca1288e05f4f83fd65c7ece303d6164b13ea38b3 */}
### Why a backup reminder?

As long as `/var/lib/dnf/backup-admin` is missing, the home page of the first
session shows a banner&nbsp;: the keys are not backed up. This
marker (date and commit) is written by `just backup-admin` once the key is
complete&nbsp;; backup skipped or failed, it stays absent.

{/* t:p b7d497ce728de5eaa711387c18f46cf26b6f3606433f48f007321eb8dab6d070 */}
### Which zone, which prefix?

The network is born with a `main` zone, with prefix `10.0` (`10.0.0.0/16`) if it is
free, otherwise the first free one (`10.x`, `172.16` to `172.31`, `192.168`). The
summary indicates it, and the choice is final.
