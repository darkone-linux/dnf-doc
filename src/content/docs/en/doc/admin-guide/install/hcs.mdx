The coordination server (HCS) connects zones via a
[mesh VPN](/en/doc/admin-guide/understand/network/) and hosts shared services.
It is a small **public** server (a VPS is sufficient).

{/* t:p f7bf40af86c8e342f8fef83298a7e53d71227b618605769ab698d613130695a9 */}
## Declaring the HCS

Coordination is enabled and the host is declared with `profile: hcs`:

```yaml
# etc/config.yaml
network:
  coordination:
    enable: true
    hostname: "hcs"
    domain: "headscale"          # → headscale.domain.tld

hosts:
  - hostname: "hcs"
    name: "Serveur de coordination"
    profile: "hcs"
    ipv4:
      external: "203.0.113.10"   # IP publique du VPS
      internal: "100.64.0.2"     # IP tailnet (après enrôlement)
    services:
      headscale:                 # coordination du VPN
      idm:                       # identités (Kanidm)
      vaultwarden:               # coffre-fort
```

Installation follows the same procedure as a
[gateway](/en/doc/admin-guide/install/gateway/#installing-the-gateway)
(`just install` / `configure` / `apply`). `just configure` also enrolls the HCS on
its own [tailnet](/en/doc/admin-guide/operate/vpn/#enrolling-a-machine)&nbsp;:
then report its tailnet address in the declaration above.

## Global services

A service marked `global: true` is exposed on the HCS with a **public DNS**
(`<name>.domain.tld`): it is reachable from anywhere, including the Internet.

```yaml
    services:
      forgejo:
        domain: "git"
        global: true             # → https://git.domain.tld
```

## Create a user account

:::tip[Each user will have…]
- An identifier and a **master password** (vault).
- An **authentication key** for all services (SSO).
- A **recovery password** in case the key is lost.
:::

<Steps>

1. **Create the system account**

   Add the user in `etc/config.yaml`, then generate, commit, and apply:

   ```yaml
   # etc/config.yaml
   users:
     bob:
       uid: 1001
       name: "Bob"
       profile: "normal"
       groups: ["global"]
   ```

   :::caution[POSIX account (optional)]
   This declaration creates an account on designated Linux machines. Users can
   also be created only in Vaultwarden and Kanidm.
   :::

2. **Vaultwarden account**

   1. Admin: send an invitation.
   2. User: receives an email to set their master password.
   3. Admin: confirm the user.

3. **Kanidm account** (on the HCS)

   ```sh
   just enter hcs
   kanidm person credential create-reset-token <login> --name idm_admin
   ```

   Forward the link or QR code to the user, who creates their key and recovery
   password.

4. **Bitwarden**

   Installing Bitwarden on browsers and smartphones simplifies access.

   :::caution[Be sure to choose "self-hosted"]
   Enter the Vaultwarden URL **before** the master password, otherwise it goes
   to bitwarden.com!
   :::

5. **Service access**

   SSO opens all services with a single authentication. Rights are defined by
   Kanidm groups.

</Steps>

## Connecting from outside

Outside a zone, access to services goes through the Tailscale client. Nothing to
distribute&nbsp;: everyone connects with their Kanidm identity.

<Steps>

1. **Administrator side**

   Give the user an administrator profile or a `zone-<zone>` group, regenerate,
   then deploy the HCS&nbsp;:

   ```yaml
   # etc/config.yaml
   users:
     bob:
       groups: ["global", "zone-maison"]
   ```

   ```sh
   just generate
   just apply hcs
   ```

2. **User side**

   Follow [Connect a device](/en/doc/how-to/user/connect-device/#from-outside).

</Steps>

Details, expiration and troubleshooting&nbsp;:
[VPN](/en/doc/admin-guide/operate/vpn/#administration).
