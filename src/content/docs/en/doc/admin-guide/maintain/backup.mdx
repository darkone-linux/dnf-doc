Backups rely on [restic](https://restic.net/): each host **pushes** its data to an encrypted repository, either local or remote via a zone REST server. The goal is a **3-2-1** strategy (multiple copies, multiple media, one off-site location).

{/* t:p 60dc1832f21e2477c514f34bd29ffb2ab547b0006887f74cb5e17c4c56bf9f1b */}
## Two roles, one module

```d2
style.fill: transparent
direction: down

c1: Client host\nrestic backup { shape: person }
c2: Client host\nrestic backup { shape: person }
srv: REST server\nzone repositories { shape: cylinder }

c1 -> srv
c2 -> srv
```

| Role | Who | What |
|---|---|---|
| REST server | Host with the `restic` service | Stores zone repositories |
| Client | Host with `enable = true` | Pushes its `targets` (backups) |

## Saved categories

A target saves one or more **categories** in sub-repositories:

| Category | Content |
|---|---|
| `system` | Root `/`, excluding volatile data and `/nix`, `/srv`… |
| `nfs` | Shares `/srv/nfs/...` |
| `medias` | Media `/srv/medias/...` |

:::note[Cloud sync folders are never backed up]
A `~/Nextcloud` folder (including numbered variants) replicates an original
already backed up on the server side, and restic does not deduplicate across
repositories: each replica would cost a full copy. Exclusion is done by path
and journal marker, across all categories.
:::

:::note[Two secrets, not to be confused]
- **Repository passphrase** (`restic-password-<zone>`): encrypts the content.
- **REST credential** (`restic/<host>/rest-password`): authenticates the host.

Both are generated by `just configure-admin-host`. See
[Secrets](/en/doc/admin-guide/operate/secrets/).
:::

## Implementation

The complete operational configuration (REST server, targets, retention
policy, restoration) is detailed in the practical guide:

- [Network backups (restic)](/en/doc/how-to/admin/network-backup/)

:::caution[An absent off-site backup doesn't raise an alarm right away]
A `rest:` target whose server is unreachable is **skipped**, not marked as
failed&nbsp;: no immediate alert. It is `ResticBackupStale` (36&nbsp;h) then
`ResticBackupCritical` (7&nbsp;days) that report the missing backup. A remote
site that is down is therefore noticed after a day, not after the first
missed night.
:::

:::tip[Retention policy]
Defaults to: 24 latest + 24 hourly + 7 daily + 8 weekly + 24 monthly.
Integrity is verified on every backup.
:::
