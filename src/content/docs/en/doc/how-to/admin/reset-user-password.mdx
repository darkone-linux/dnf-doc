A user has lost access to their account. Before acting, identify **which** of the
three passwords is involved (they are independent), and the
[alternative](/en/doc/admin-guide/operate/onboarding/#choosing-an-alternative)
chosen when the account was created.

{/* t:p e9d29d28d09d0154d2f09fdb89790145ebe8746c22160267cb2ef6e596e2f5b7 */}
## Three distinct passwords

| Password | Used for | Where to reset it |
|---|---|---|
| **Identity** (Kanidm) | Signing in to services (SSO) | [Kanidm link](#identity-kanidm) |
| **Vault** (Vaultwarden) | Unlocking the password manager | [Emergency access](#vault) |
| **Session** (NixOS) | Logging in on a workstation | [`just passwd`](#session-password) |

{/* t:p 5cfbb00f4f2ddaf88c26cd8e3484b094e4ca5b536a921d8e7af5fb56c5ff4e9d */}
## Identity (Kanidm)

<Steps>

1. Create a reset link&nbsp;:

   ```bash
   just invite <login>            # non-technician: link valid for 1 hour
   just invite <login> advanced   # technician: link valid for 24 hours
   ```

2. Depending on the user&nbsp;:
   - **Non-technician**: open the link yourself, redefine the password and TOTP, update the item in their collection.
   - **Technician**: send them the welcome sheet (link and QR code).

</Steps>

## Vault

The master password encrypts the vault: no server knows it.

| Situation | Remedy |
|---|---|
| **Forgotten password**, emergency access enabled | *Takeover* by the trusted contact |
| **Forgotten password**, otherwise | *Delete User* in `/admin`, then a new invitation |
| **Lost 2FA** | *Remove all 2FA* in `/admin` |

The `/admin` panel only responds from the LAN and the tailnet.

:::note[After a takeover]
The trusted contact sets a new master password and passes it on.
Vaultwarden does not require changing it: leave that to the user.
:::

:::danger[Deleting an account destroys its personal vault]
Only items in shared collections survive. A new invitation is not a
reset: *Resend invite* only works as long as the invitation has not been
accepted.
:::

## Session password

The login password on a machine is managed in the
[secrets](/en/doc/admin-guide/operate/secrets/), not in Kanidm.
`just invite <login>` offers to redefine it, or directly
[`just passwd <login>`](/en/doc/admin-guide/operate/users/#set-the-password).

The user's [GNOME keyring](/en/doc/admin-guide/operate/users/#the-gnome-keyring-after-just-passwd)
then starts empty at their next session.

:::note[Default password]
`just passwd-default` records the fleet's reference password, without
configuring any account: a new account cannot log in until
`just passwd <login>` is run. See [Users](/en/doc/admin-guide/operate/users/).
:::

:::tip[YubiKey]
An enrolled YubiKey (`just yubikey <login>`) allows logging in without
a password, handy while waiting for the reset. See
[Strong authentication](/en/doc/admin-guide/operate/yubikey/).
:::
