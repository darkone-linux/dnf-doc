A user has lost access to their account. Before acting, identify **which** of the
three passwords is at fault (they are independent), and the
[pathway](/en/doc/admin-guide/operate/onboarding/#choosing-a-path) followed when
the account was created.

{/* t:p 31235c448675695a4efd8402dc6b62e6324d0f5eabb015781d394470086e42a6 */}
## Three distinct passwords

| Password | Used for | Where to reset it |
|---|---|---|
| **Identity** (Kanidm) | Signing in to services (SSO) | [Kanidm link](#identity-kanidm) |
| **Vault** (Vaultwarden) | Unlocking the password manager | [Account recovery](#vault) |
| **Session** (NixOS) | Logging in on a workstation | [`just passwd`](#session-password) |

{/* t:p b2155a771abcbe15ffe3d55213e878dba40346c3246d807f4e068d31ee677f85 */}
## Identity (Kanidm)

<Steps>

1. Create a reset link on the coordination server&nbsp;:

   ```bash
   just enter hcs
   kanidm person credential create-reset-token <login> --name idm_admin
   ```

2. Depending on the pathway&nbsp;:
   - **Non-technical**: open the link yourself, redefine the password and TOTP, update the item in their collection.
   - **Technical**: send the link or the QR code to the user.

</Steps>

{/* t:p 5065f3b2c04cd41d721d608330d2116f69e0f9403a10903968dc6cbca47f412c */}
## Vault

The master password encrypts the vault&nbsp;: no server knows it.

| Situation | Remedy |
|---|---|
| **Forgotten password**, non-technical pathway | Organization → *Members* → *Recover account* |
| **Forgotten password**, otherwise | *Delete User* in `/admin`, then a new invitation |
| **Lost 2FA** | *Remove all 2FA* in `/admin` |

:::note[After an account recovery]
The administrator sets a new master password and passes it on.
Vaultwarden does not require changing it&nbsp;: advise the user to do so.
:::

:::danger[Deleting an account destroys its personal vault]
Only items in shared collections survive. A new invitation is not a
reset&nbsp;: *Resend invite* only works as long as the invitation has not been
accepted.
:::

## Session password

The login password on a workstation is managed in the
[secrets](/en/doc/admin-guide/operate/secrets/), not in Kanidm:

<Steps>

1. **Set the fingerprint**

   ```bash
   just passwd <login>
   ```

   Technical pathway&nbsp;: the user types the password themselves, or sends their fingerprint (see [the pathway](/en/doc/admin-guide/operate/onboarding/#technical-path)).

2. **Commit and deploy**

   ```bash
   just commit "user(passwd): <login>"
   just apply @user-<login>
   ```

</Steps>

:::note[Default password]
`just passwd-default` records the fleet reference password, without configuring any account: a new account only logs in after
`just passwd <login>`. See [Users](/en/doc/admin-guide/operate/users/).
:::

:::tip[YubiKey]
An enrolled YubiKey (`just yubikey <login>`) allows logging in without a
password, useful while waiting for the reset. See
[Strong authentication](/en/doc/admin-guide/operate/yubikey/).
:::
