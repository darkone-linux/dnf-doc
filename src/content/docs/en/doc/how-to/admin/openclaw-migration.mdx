A new version of OpenClaw may require migrating its databases before it can serve an [AI space](/en/doc/admin-guide/operate/ai-spaces/). The gateway then refuses to start&nbsp;: the `openclaw-gateway` unit stays in a failed state, with no restart loop, and the `ServiceDown` alert is triggered.

{/* t:p 23e4a49bb5e458409ec3e03cda8452ee1e1b3900b52597d4d36c600dde09bb5f */}
## Recognize the case

On the space host&nbsp;:

```bash
systemctl status openclaw-gateway   # status=78/CONFIG
journalctl -u openclaw-gateway -n 30
```

The journal indicates the command to run, usually `openclaw doctor --fix`.

{/* t:p c24dd7d29782326b6c968bb31814c45c25063a59ed709f0d6a281d7a3f4ced41 */}
## Migrate

<Steps>

1. **Stop the gateway**

   ```bash
   sudo systemctl stop openclaw-gateway
   ```

2. **Repair**

   ```bash
   openclaw doctor --fix --non-interactive
   ```

   `doctor` backs up each database (`*.pre-startup-migration-*.bak`) before migrating it.

3. **Restart**

   ```bash
   sudo systemctl reset-failed openclaw-gateway
   sudo systemctl start openclaw-gateway
   ```

</Steps>

:::note[Slow startup]
The gateway responds one to two minutes after starting on a microVM with 2&nbsp;vCPU.
:::
