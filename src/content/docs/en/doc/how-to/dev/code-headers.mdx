Every code file carries a short header explaining its role. It helps humans and
AI agents alike find their way without reading the whole file.

{/* t:p 9c3cb4170e266eaa6f0b54757573c357cd543fd947201ed4ee604ab2f89fb8b2 */}
## Rules

- **1st line**: concise description of the file's role.
- Describe **the role**, not the line-by-line implementation; explain the *why*.
- Target usage: **using, maintaining, configuring, debugging**.
- Flag any constraints: generated file, do not edit, dependencies.
- English, concise; never restate what the code already expresses.

:::caution[Blank line before each comment]
A blank line **always precedes** a comment (Nix code, shell heredoc,
1st comment inside `{` or `(`). **Only the header** at the very top of the file
is exempt.
:::

## Admonitions in the header (Nix)

The header of a Nix module can contain Starlight admonitions (`note`,
`tip`, `caution`, `danger`): they **feed the [module reference](/en/ref/modules/)** generated by `just codegen`.

```nix
# Module de service : reverse-proxy Caddy pour les services de zone.
#
# :::tip[Activation]
# Activé d'office par les profils d'hôtes exposant des services.
# :::
{ config, lib, ... }:
```

Each module has its own page, whose header is the body&nbsp;:

| In the header | In the reference |
|---|---|
| 1st line | Summary, on the category page |
| `####` headings | Page sections |
| Link to a module | `/ref/modules/<catégorie>/<module>/` |

A sub-module (`<nom>/<sujet>.nix`) has no page&nbsp;: the parent module's header documents it, and its options join the parent's page. `just codegen` rejects a link to a missing reference page.

## Generated file

A file produced by a tool **says so in its header**, so nobody edits it:

```nix
# This file is generated by 'just generate' or 'just clean'
# from the configuration file etc/config.yaml
# --> DO NOT EDIT <--
```

:::danger[Do not edit the output]
To change a generated file, modify **the generator or the source**
(`etc/config.yaml`, the module), then regenerate. See
[The generator](/en/doc/dev-guide/generator/).
:::

## Comments in the code

The reader **scans** the code: a comment read twice has failed.

- **Why**, not what: intent, constraint, non-obvious choice.
- **3 lines** per block, 6 at most; beyond that, the doc page and a one-line pointer.
- **One idea** per comment.
- **Telegraphic style**: short clauses, no incident story.
- **Name the mechanism** (`mkDefault`, `br_netfilter`) rather than describing it.

```nix
# `allowedTCPPorts` carries no `iifname`: on a host that also holds a WAN
# address it publishes sshd on the Internet.
```

The structure of modules is described in [Modules](/en/doc/dev-guide/modules/),
writing the docs in [Documentation](/en/doc/dev-guide/documentation/).
