A framework refactor changes **no** deployed system: the derivation (`drvPath`) of each host stays identical. `just drv-diff` checks this, from the root of a co-development project.

```sh
just drv-diff                   # tout le parc
just drv-diff gw-main,nas       # deux hôtes, pendant le travail
just drv-diff "" HEAD~3         # contre une révision antérieure de dnf/
```

The command evaluates each host twice: against the last commit of `dnf/`, then against the working tree. It lists the hosts whose derivation differs and exits with an error if there are any.

:::tip[During the refactor]
Target two or three hosts with different profiles (gateway, server, workstation), then run the whole fleet before committing.
:::

## Files taken into account

The working tree is read as `just commit` would commit it: tracked files and new files, except those git ignores. The consuming project is the same on both sides; only `dnf/` varies.

{/* t:p b599328025e2e45048cc93c3eac1ae45768c0abf295316daaca29c35c9cdf71c */}
## Pending input updates

A `flake.lock` of `dnf/` that is modified but not yet committed (`nix flake update`) changes all hosts and would mask the effect of the code. The command reports it, then reads the working tree using the lock of the base revision.

```sh
LOCK=tree just drv-diff         # compter aussi la mise à jour des inputs
```

## A derivation differs

The output gives the two `drvPath` of each affected host. Comparing them shows what changed:

```sh
nix run nixpkgs#nix-diff -- <avant.drv> <après.drv>
```

A wanted difference is no longer a refactor: the commit then carries the type `feat` or `fix`.

## Resources

Two evaluations run one after the other, each on two processes. `WORKERS` changes their number, and `WORKER_MEM` (MB) caps the memory of each.

```sh
WORKERS=1 just drv-diff
```
